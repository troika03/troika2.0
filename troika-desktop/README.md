# Тройка для Windows

Самостоятельный клиент WPF для Windows 10/11 x64 с .NET Framework 4.8.
Он не собирает и не встраивает мобильный Flutter-клиент. Интерфейс и локальная
работа написаны отдельно; облачный аккаунт и протокол Troika остаются общими.

Одно окно с янтарным анимированным голосовым контуром, историей и встроенными панелями.
Палитра и локальный шрифт Golos Text соответствуют макетам; боковая навигация
адаптирована для ПК. Панели и поле ввода используют спокойные непрозрачные поверхности.
В профиле доступны светлая тема и шесть сохраняемых акцентов. Смена оформления
сохраняет текущий разговор и несохранённый текст задачи. Обычный размер —
960 × 680, минимальный — 780 × 540. Кнопка в заголовке переключает то же окно
в компактный режим 480 × 600. Повторный запуск открывает существующее окно.
Ctrl+Alt+T вызывает голосовой ввод; Escape останавливает действие; Ctrl+N
создаёт разговор. Enter отправляет текст, Shift+Enter вставляет новую строку.

## Возможности

- Вход и регистрация, защищённое хранение сессии Windows DPAPI, обновление токена.
- Облачные ответы, история, поиск с источниками и одноразовые подтверждения действий.
- Запрос создания DOCX, PDF, PPTX и ZIP с кодом. Новые файлы сохраняются на ПК
  с проверкой размера и SHA-256 до подтверждения серверу. Старые облачные файлы
  можно отдельно сохранить, без автоматического удаления серверной копии.
- Проекты, дела, напоминания, заметки, просмотр и изменение памяти.
- Тариф и дневной остаток, устройства и отзыв доступа, экспорт и удаление аккаунта.
- Запись микрофона по нажатию, серверное распознавание и озвучивание ответа.
- Фоновое пробуждение включается в настройках. Скажите «Тройка», дождитесь
  звукового сигнала и произнесите команду. До сигнала микрофон обрабатывается
  на ПК. При закрытии окна Тройка остаётся в области уведомлений, откуда можно
  выключить микрофон или выйти. При блокировке Windows микрофон на паузе.
- «Файлы» → «Рабочая папка на ПК» позволяет выбрать локальную папку. Голосом
  или текстом можно посмотреть содержимое, найти и открыть файл, прочитать
  текст или создать подпапку. Содержимое файла отображается на ПК.
  «Что я скачал последним?» показывает самый свежий готовый файл из папки
  «Загрузки» Windows без настройки рабочей папки.
- Необязательный локальный фильтр «Мой голос»: три образца, отдельное включение,
  проверка говорящего до отправки записи на распознавание.
- Разрешённые локальные команды Windows. Произвольного терминала нет.
- Распаковка выбранного ZIP в новую папку и выбранные проверки Python/JavaScript
  после локального подтверждения. Остановка завершает группу процессов.
  Раздел «Разработка» спрашивает, где проверять код: здесь, на выбранном ПК
  аккаунта или только сохранить ZIP. Тройка создаёт проект и выполняет до трёх
  исправлений по реальному отчёту. Каждая новая версия сохраняется отдельно.
  Нулевое число тестов не считается успехом; синтаксис не доказывает поведение.
  Python использует unittest и стандартную библиотеку, JavaScript — переносимый
  CommonJS с node:test. Для локальной проверки установите Python или Node.js.
- «Принимать проверки с телефона» делает этот ПК доступным в выборе устройства.
  Оставьте раздел открытым. Первый проект требует подтверждения на ПК;
  разрешение ограничено четырьмя версиями за 10 минут. Закрытие раздела,
  Escape или отзыв доступа останавливают приём. Для связи требуется сервер
  с `/v1/development`; исходники и отчёты передаются временно без записи на диск.
- В Тройке Pro скажите «Сделай сайт-портфолио» в обычном разговоре. Подтвердите
  новую папку или выберите существующие исходники. Тройка запускает
  установленный Codex CLI скрытым процессом через личный вход в ChatGPT.
  Этапы и результат появляются в разговоре, а «Открыть чат в Codex» открывает
  сохранённую сессию в оригинальном приложении. Следующая задача вроде
  «Добавь форму связи» продолжает тот же чат проекта. Тройка проверяет свой
  тариф при запуске новых и последующих задач. Доступ и лимиты Codex определяет
  аккаунт ChatGPT. Для выполнения нужен Codex с поддержкой Windows MXC.
  Настройка подключения находится в разделе «Разработка» → «Codex · аккаунт ChatGPT».

## Сборка и установка

Рядом с исполняемым файлом должна оставаться папка `assets`: логотипы,
голосовые символы, шрифт и его лицензия. Сборка и установщик копируют её
автоматически. При ручном переносе копируйте всю папку сборки.

Запустить из PowerShell в этой папке:

```powershell
.\build.ps1 -Test
.\install.ps1
```

Сборка использует системный компилятор .NET Framework и не требует NuGet.
Python 3.11+ подготавливает закреплённые по SHA-256 Vosk runtime и модели:
`scripts/provision_windows_voice_id.py`, `voice-id.lock.json`. При первой сборке
нужен доступ к официальным источникам; далее проверяется локальная копия.
Установленное приложение ничего не скачивает. Для сборки без сети заранее
подготовьте assets и проверьте их скриптом с `--offline`.

Чтобы открыть локальную пробу управления Windows, запустите из папки сборки:

```powershell
.\TroikaDesktop.exe --computer-use-prototype
```

Кнопка «Разрешить и запустить» даёт доступ к тестовому редактору на две минуты.
После записи образца окно показывает путь к проверенному временному файлу.
«Остановить», Esc и закрытие окна отзывают доступ на этом ПК.

В тестовом запуске с моделью используется тот же редактор. Из папки репозитория
запустите тестовый сервер в окружении с `OPENROUTER_API_KEY` и случайным
`TROIKA_COMPUTER_LAB_TOKEN`. Укажите тестовую модель OpenRouter с поддержкой
JSON-ответов.

```powershell
.venv\Scripts\python.exe -m scripts.troika_computer_lab --model <model-id> --port 8765
```

В процессе клиента установите тот же `TROIKA_COMPUTER_LAB_TOKEN` и запустите из
папки сборки:

```powershell
.\TroikaDesktop.exe --computer-use-agent http://127.0.0.1:8765
```

В окне введите пробную задачу, например «Запиши „Тройка проверяет результат“ и
сохрани». Запрос отправится после локального разрешения. Тестовый ключ OpenRouter
нужен только серверу. В клиенте обычный режим запускается без этого параметра.

Для согласия на серверную симуляцию запустите локальный продуктовый API с
`product_computer_dry_run_enabled: true`. Запишите токен зарегистрированного
тестового устройства Windows в переменную `TROIKA_COMPUTER_TEST_DEVICE_TOKEN`
в окружении запуска и откройте отдельное окно.

```powershell
.\TroikaDesktop.exe --computer-use-consent http://127.0.0.1:8642
```

Окно показывает ожидающие запросы этого устройства. После выбора нажмите
«Разрешить» или «Отклонить». Stop, Esc и закрытие окна отправляют отзыв для
текущего разрешения. Протокол сервера описан в [аудите симуляции](../docs/audit/TROIKA_COMPUTER_DRY_RUN_2026_11_11.md).

Для пробного управления редактором из Run предусмотрен отдельный запуск
`--computer-use-windows-lab` с локальным API и разрешением на выбранное
устройство. [Настройка и проверка редактора](../docs/audit/TROIKA_WINDOWS_RUN_EDITOR_2026_11_12.md).

`build.ps1 -Test` также собирает отдельный тестовый редактор
`TroikaComputerUseEditor.exe`. Его можно открыть с тем же локальным API
и разрешением через `--run <адрес> <run-id> <grant-id>`.

Из папки тестовой сборки можно запустить локальную пробу классического Блокнота.

```powershell
.\TroikaComputerUseEditor.exe --notepad-preview
```

Выберите режим разрешений. Тройка откроет новый пустой документ в отдельном
процессе Блокнота. В режиме «Всегда спрашивать» отдельно подтвердите ввод и
сохранение. После успешной пробы окно покажет путь к проверенному файлу.
Проба использует фиксированный образец. Для её автоматической проверки
запустите `build.ps1 -TestNotepad` на интерактивном рабочем столе Windows.

В сборке с `-TestWindowCapture` команда `--run-notepad-assisted <адрес> <run-id> <grant-id>`
использует это окно Блокнота в тестовом Run. В соседнем окне можно проверить
один кадр и разрешить его отправку в OpenRouter. Три режима доступа к вводу
и сохранению доступны в окне разрешений.

Для общей пробы управления ПК используйте `--computer-use <папка-репозитория> <адрес>`.
Окно позволяет запустить одну задачу для Блокнота и браузера и выбрать
режим разрешений. [Настройка тестового API и запуск](../docs/audit/TROIKA_WINDOWS_RUN_EDITOR_2026_11_12.md#единый-инструмент-управления-пк).

При обновлении работающей версии указать новую папку:

```powershell
.\build.ps1 -Test -OutputDirectory .\build\candidate
.\install.ps1 -SourceDirectory .\build\candidate
```

Установка не требует администратора: отдельная папка с версией в
`%LOCALAPPDATA%\Programs\TroikaDesktop\releases` и ярлык «Тройка ПК» на рабочем
столе. Предыдущие версии и каталог старого Flutter-приложения сохраняются.
После обновления закрыть текущее окно и открыть ярлык.

Настройки и локальные файлы находятся в `%LOCALAPPDATA%\TroikaDesktop`.
Файлы разделены по аккаунтам. Новый клиент не импортирует сессию старого
Flutter-клиента; войти можно с теми же почтой и паролем.

## Мой голос

Откройте «Настройки», затем «Мой голос». Запишите три показанные фразы обычным
голосом, по 5–8 секунд, в тихом месте. Каждый образец должен содержать не менее
четырёх секунд речи; паузы не засчитываются. Регистрация сохраняет образец,
но не включает фильтр автоматически. После регистрации отдельно включите
«Отзываться только на мой голос».

При включённом фильтре каждый голосовой запрос проверяется локально до STT.
Короткая фраза, несовпавший голос, повреждённая модель или образец блокируют
отправку записи. Текстовый ввод и обычные подтверждения действий доступны.
Windows по-прежнему использует кнопку или Ctrl+Alt+T; фонового wake word нет.

Хранятся только три нормализованных вектора Vosk spk-0.4, отдельно для аккаунта
в `%LOCALAPPDATA%\TroikaDesktop\voice-identity`, под защитой Windows DPAPI.
Записи регистрации остаются в RAM и очищаются после проверки; образец не
синхронизируется и не отправляется на сервер. Выход сохраняет локальный образец;
удаление аккаунта через этот клиент удаляет его. Кнопка «Удалить образец голоса»
также выключает фильтр. Повторная регистрация заменяет образец только после
трёх согласованных записей и оставляет новый фильтр выключенным.

Это фильтр чужой речи, не средство входа и не защита от записи или клона голоса.
Порог cosine similarity 0,75 и минимум 400 голосовых кадров являются начальными
настройками, без обещания измеренной точности на голосах пользователей. Шум,
микрофон и изменение голоса могут вызвать отказ. Нужна отдельная физическая
приёмка владельцем и другим говорящим; синтетические тесты её не заменяют.

## Проверки и ограничения

`build.ps1 -Test` проверяет поток ответа и ошибки, обновление токена,
изоляцию аккаунтов, доставку файлов, ZIP, реальные Python failure/fix/pass,
остановку проверки и фильтрацию секретов. Проверки интерфейса дополнительно
проверяют доступность профиля в минимальном окне, сохранение разговора и
черновика при смене темы и запрет обхода подтверждения через навигацию.
`DesktopTests.exe --live` отдельно
создаёт временный серверный аккаунт, проверяет облачный путь и удаляет аккаунт.
Это не проверка микрофона и воспроизведения на физическом устройстве.

`VoiceIdentityTests.exe` проверяет границы векторов, DPAPI, согласованность
регистрации, изоляцию аккаунтов, блокировку STT, Stop и поздние ответы.
`VoiceIdentityTests.exe --native <публичный PCM WAV 16 кГц моно>` отдельно
проверяет реальное извлечение 128-мерного вектора и сообщает холодную и повторную
задержку. WAV должен содержать минимум четыре секунды речи и не более 60 секунд.

Напоминания опрашиваются раз в 30 секунд при открытом или свёрнутом приложении;
после полного закрытия не доставляются. Тихие часы локально поддерживают
Europe/Moscow, UTC и известные Windows timezone IDs; неизвестная зона отключает
озвучивание. Камера, live screen, wake word, системная фоновая служба и
phone-to-PC Companion пока отсутствуют. Проверки кода выполняются с правами
пользователя, без отдельной песочницы; запускать только доверенный проект.

Это предварительная сборка без подписи и автоматического обновления. Доступность
сервера и лимиты аккаунта влияют на облачные функции. Ошибка или частичный ответ
не считаются успешным выполнением задачи. Изменение существующих Office-файлов,
полный цикл сборки произвольного репозитория и установка зависимостей не реализованы.
