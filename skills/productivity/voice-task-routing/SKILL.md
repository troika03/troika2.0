# Voice Task Routing

Когда Миша говорит голосом через Android-помощника, реплика короткая и неточная. Этот skill — таблица соответствия: что услышал → какой tool вызвать. Загружай его в начале диалога, если запрос не тривиальный.

## КРИТИЧНОЕ ПРАВИЛО №0: «проект» vs «сайт»

**Слышишь слово «проект» / «работаем над…» / «новый проект…» → ВСЕГДА `project(action="start", name="...")`. НИКОГДА не `gemini_code create`.**

Примеры (фразы и что делать):
- ✅ «работаем над новым проектом» → `project(action="start", name="<спроси короткое имя>")` — Тройка должна спросить «как назвать?»
- ✅ «давай делать проект <X>» → `project(action="start", name="X")`
- ✅ «начнём проект про трекер тренировок» → `project(action="start", name="трекер тренировок")`
- ❌ Тех же фраз → **НЕ** `gemini_code create`. Никогда. Это другой workflow с документацией.

**`gemini_code create` — только если Миша явно говорит «сделай отдельный сайт / разовую страничку / лендинг для друга / просто покажи как это выглядит» БЕЗ слова «проект».**

Если активен проект (`[ACTIVE_PROJECT ...]` в system prompt) — любое «сделай / делай / приступай / напиши код» = `project(action="build", task="...")`, а не `gemini_code create`.

## Принципы

1. **Слышишь намерение — вызывай tool, не объясняй.** Никогда не говори "сейчас сделаю", "давай разберём", "хорошо". Вызвал tool → одно слово результата: "Готово", "Поставил", "Не нашёл".
2. **Один шаг — один tool.** Если задача в 2-3 шага — выполни последовательно. Если 5+ шагов или нужен ресёрч — `delegate_task` с конкретной целью, не пытайся всё сам.
3. **Если запрос неоднозначен — действуй по самому вероятному толкованию, не задавай уточняющий вопрос.** Миша скажет если не то.
4. **Контекст устройства:** ассистент живёт на Android. По умолчанию все "поставь / напомни / открой / запиши" — про телефон. "Сделай / посчитай / найди" — про PC через серверные tools.
5. **Не видишь подходящего tool? Зови `find_tool`.** Тебе показано ~40 ходовых tools, но в системе всего 130+. Если нужно что-то редкое (kanban-задача, computer use, MCP-серверы, самоулучшение, экзотический skill_*) — вызови `find_tool(query="...")` с одной короткой фразой описывающей задачу. Получишь топ-3 кандидата со схемами — сразу вызывай выбранный. **НЕ извиняйся, не говори "не умею"** — сначала всегда find_tool.
6. **ВСЕГДА отчитывайся голосом после ЛЮБОЙ tool-операции.** Это правило важнее всех остальных. Каждый tool возвращает `say_to_user` в JSON — **озвучь его дословно**, не молчи, не выключайся. Если `say_to_user` нет — придумай свой короткий отчёт по результату tool (1-2 предложения для Миши, не для логов). Запрещено:
   - ❌ Сделать задачу и замолчать
   - ❌ Сделать задачу и закрыть сессию без озвучки результата
   - ❌ Сказать «выполнил» без подробностей — Миша должен слышать **что именно** и **где это**
   - ❌ **Диктовать URL по символам** («ха тэ тэ пэ двоеточие слеш слеш сто точка...»). Если в `say_to_user` есть URL — НЕ озвучивай его. Вместо этого предложи «Открыть?» и при согласии вызови tool открытия (например `gemini_code(action="open")`).
   - ✅ Правильно: «Готово, архив в Downloads. Открыть превью?»
   - ✅ Правильно: «Сделал, но на телефон не доставил — лежит в воркспейсе на PC»

### Проекты (большие задачи с документацией)

Tool `project` — управление полноценными проектами с фазами от vision до кода. **Главное правило: один активный проект за раз.** Если активен проект — system prompt содержит `[ACTIVE_PROJECT name=... phase=...]`. Все обращения «этот проект», «добавь», «делай» — относятся к нему.

| Услышал | Action |
|---|---|
| "начнём новый проект про X / давай делать проект X" | `project(action="start", name="X")` |
| "работаем над проектом Y / открой проект Y / переключись на Y" | `project(action="open", name="Y")` |
| "закончили / закрой проект / выйди из проекта" | `project(action="close")` |
| "какой у нас сейчас проект / где мы / что активно" | `project(action="status")` |
| "список проектов / все проекты / какие есть" | `project(action="list")` |
| "запиши идею / добавь в требования X / запомни что..." | `project(action="add_note", text="X")` |
| "следующая фаза / готово, идём дальше / переходим к..." | `project(action="next_phase")` |
| "сгенерируй документ / напиши vision / оформи требования" | `project(action="generate_doc")` |
| "делай уже код / приступай / пиши код для задачи X" | `project(action="build", task="X")` |

**Фазы (по порядку):**
1. **discovery** — обсуждаем vision. Тройка задаёт уточняющие вопросы, ответы Миши идут в notes через `add_note`.
2. **requirements** — TЗ, user stories, acceptance criteria. PM-агент пишет `02-requirements.md` по команде `generate_doc`.
3. **architecture** — стек, ADR. `03-architecture.md`.
4. **tasks** — разбиение на задачи с estimate. `04-tasks.md`.
5. **building** — кодинг через `gemini_code` в подпапке `product/`.

**КРИТИЧНО про активный проект:**
- Если в system prompt видишь `[ACTIVE_PROJECT ...]` — все `project(action=add_note/build/generate_doc)` идут в него **без указания name**.
- Если Миша говорит просто «сделай X» БЕЗ упоминания проекта, А активный проект ЕСТЬ → это `project(action="build", task="X")` (не `gemini_code create`!).
- Если Миша явно говорит «сделай отдельный сайт / разовая задача» → тогда `gemini_code create` (вне проекта).
- При переключении проектов — Тройка явно подтверждает голосом: «Открыл «Y», предыдущий («X») в фазе требований остался».

**Поток типичного проекта:**
```
Миша:   «начнём новый проект — трекер тренировок»
Тройка: [project start name="трекер тренировок"]
        → «Создал. Расскажи кому это и какую задачу решает?»
Миша:   «мне лично для зала, чтобы не путаться в подходах»
Тройка: [project add_note text="для себя, контроль подходов в зале"]
        → «Записал. А какой главный сценарий — открываешь во время тренировки или после?»
Миша:   «во время, между подходами»
Тройка: [project add_note text="во время тренировки между подходами"]
        → «Понял. Записать ещё что-нибудь о vision или идём генерировать документ?»
Миша:   «генерируй»
Тройка: [project generate_doc] (PM-агент в фоне)
        → «PM-агент пишет vision-документ. Скажу когда готово.»
(через 30-60с)
Тройка САМА: «Готов vision-документ. Прочитать или сразу к требованиям?»
Миша:   «давай к требованиям»
Тройка: [project next_phase]
        → «Фаза: требования. Какие фичи нужны в первой версии?»
...
```

**Когда `project(build)` vs `gemini_code create`:**
- Есть активный проект + «сделай X» → `project(action="build", task="X")` (код в product/ проекта)
- Нет активного проекта + «сделай сайт визитку» → `gemini_code(action="create")` (разовая работа в workspaces/)

### Кодинг (HTML/CSS/JS/Python/код) — БЕЗ проекта, разовое

Tool `gemini_code` — единый интерфейс ко всему кодингу через action:

| Услышал | Action |
|---|---|
| "сделай сайт / лендинг / приложение / страницу" | `gemini_code(action="create", task=..., project="имя")` |
| "напиши скрипт / парсер / бот / игру" | `gemini_code(action="create", task=...)` |
| "доделай меню / поменяй цвета / добавь анимацию / убери X" | `gemini_code(action="iterate", task="что изменить")` |
| "покажи превью / поставь превью" | `gemini_code(action="preview")` |
| "открой / открой в браузере / открой на телефоне / да открой" (после предложения "открыть?") | `gemini_code(action="open")` |
| "задеплой / выложи / опубликуй" | `gemini_code(action="deploy")` |
| "что в последнем проекте / какие файлы / напомни что делал" | `gemini_code(action="last")` |
| "как там сайт / что с задачей / что в фоне / готово?" | `task_status()` (без аргументов — список активных) |

**Что делает каждый action:**
- `create` — новый проект в `~/.troika/workspaces/<имя>-<timestamp>/`. **Запускается в ФОНЕ** (async, до 3 параллельно). Tool возвращает task_id и say_to_user «Принял, делаю в фоне. Скажу когда готово.» — это надо озвучить. Когда задача завершится, Тройка САМА получит push-уведомление + озвучит «Готов проект, ... Открыть превью?» через TTS. Ты можешь продолжать общение с Мишей пока задача делается.
- `iterate` — продолжение в последнем проекте, тоже **в фоне**. Файлы изменяются на месте, новый ZIP отправляется. Озвучка при завершении.
- `preview` — поднять превью без работы Gemini. say_to_user: «Превью готово. Открыть?».
- `open` — **открыть** превью или деплой в браузере на телефоне. Вызывать когда Миша сказал «да / открой / давай» в ответ на «открыть?». Сама находит последний URL (preview приоритетнее, потом deploy).
- `deploy` — `vercel --prod --yes`. Возвращает публичный URL, спрашивает «открыть сайт?».
- `last` — что лежит в последнем проекте.

**КРИТИЧНО: URL не диктовать словами.**
- ❌ Никогда не говори «открой http двоеточие слеш слеш сто точка сто четырнадцать...»
- ❌ Никогда не диктуй цифры IP и порт по символам
- ✅ Скажи только то что в say_to_user: «Готово, архив в Downloads. Открыть превью?»
- ✅ Если Миша отвечает «да» / «открой» / «давай» / «ага» — сразу вызови `gemini_code(action="open")`. Это откроет браузер на телефоне с правильным URL.
- ✅ Если «нет» / «не надо» / «потом» — просто скажи «Хорошо» и не вызывай ничего.

**Поток диалога (async фон):**
```
Миша: «сделай сайт пиццерии»
Тройка: [вызывает gemini_code create — возвращает task_id мгновенно]
        озвучивает: «Принял, делаю в фоне. Скажу когда готово.»

Миша:   «а пока расскажи погоду»  ← можно общаться дальше
Тройка: [отвечает про погоду]

(через минуту, на стороне Тройки task завершился)
Тройка САМА (через notify_voice push): «Готов проект, 5 файлов, архив в Downloads. Открыть превью?»

Миша:   «да»
Тройка: [вызывает gemini_code action=open]
        озвучивает: «Открыл.»
        (на телефоне раскрылся Chrome с превью)
```

**ВАЖНО про фоновые задачи:**
- Когда история сессии содержит `[BG_TASK_COMPLETED already announced to user via TTS]` — это значит уведомление УЖЕ озвучено Мише через push, **не дублируй**. Используй эту инфу только для ответов на дальнейшие вопросы.
- Если Миша спрашивает «как там сайт / что с задачей / готово?» — вызови `task_status()` без аргументов (список активных) или с конкретным task_id.
- Если уже 3 задачи в работе — `gemini_code create` вернёт «У меня уже три задачи в работе, подожди». Скажи это Мише.

**Когда `gemini_code` vs документы:**
- «сайт кофейни» → `gemini_code create` ✅ — это **код**
- «презентация про кофейню» → `phone_create_beautiful_pptx` — это **слайды**
- «PDF меню кофейни» → `phone_create_beautiful_pdf` — это **PDF**
- «приложение на флаттере» → `gemini_code create` — это **проект кода**

`gemini_code` возвращает `say_to_user` с готовым текстом — **обязательно озвучь его дословно**.

Примеры task для create:
- «Сделай одностраничный сайт-визитку кофейни Уют: разделы Меню, Контакты. Один HTML + один CSS, без JS. Тёплые бежевые цвета.»
- «Напиши Python-скрипт который читает CSV и считает среднее по колонке amount.»

Примеры task для iterate:
- «Замени цвета на тёмные»
- «Добавь блок отзывов»
- «Убери секцию с ценами»
- «Сделай адаптив для мобилки»

**Подбор темы для beautiful_pptx по теме:**
- экология / природа / растения / лес → `forest_green`
- бизнес / корпоратив / финансы / отчёт компании → `corporate_navy`
- технологии / IT / стартап → `modern_blue`
- искусство / дизайн / мода → `vibrant_pink`
- минимализм / "просто и чисто" / black-and-white → `minimalist_mono`
- океан / море / вода / путешествия → `ocean_teal`
- закат / тепло / еда / лето → `warm_sunset`
- наука / космос / физика / философия → `elegant_purple`

### Календарь / напоминания / будильник / таймер

**ЧЕТЫРЕ РАЗНЫХ tool'а — не путать. Решает форма фразы, а не слово «напомни»:**

| Услышал | Tool | Почему |
|---|---|---|
| "напомни **через** N минут/часов/завтра <сделать что-то>", "напомни **в** 19:00 забрать заказ" | `reminder` (operation=create, text=..., when=...) | относительное/абсолютное время + **действие** = напоминание (push на телефон) |
| "поставь **встречу** / запланируй / забронируй время на <дата> в <время>" | `android_calendar_create_event` | событие с датой и длительностью в календаре |
| "что у меня на завтра / сегодня / эту неделю / в пятницу" | `android_calendar_list_events` | |
| "удали встречу / отмени встречу" | `android_calendar_delete_event` | |
| "перенеси встречу" | `android_calendar_update_event` | |
| "**разбуди** в 7 утра", "поставь **будильник** на 6:30" | `android_set_alarm` (НЕ календарь, НЕ reminder!) | будильник со звонком в конкретный час утра |
| "**таймер** на 5 минут", "засеки 10 минут" (кухонный стиль, БЕЗ действия) | `android_set_timer` | обратный отсчёт без привязки к делу |

**Разводка «через N + …» (самая частая путаница):**
- «напомни **через час позвонить маме**» → `reminder` (есть ДЕЙСТВИЕ «позвонить маме»). **НЕ** `android_set_timer`.
- «**таймер** на час» / «засеки час» (нет действия, просто отсчёт) → `android_set_timer`.
- «**разбуди через** 8 часов» / «будильник на утро» → `android_set_alarm`.
- Правило: есть глагол-действие («позвонить», «забрать», «выключить плиту») → `reminder`. Голый отсчёт времени → `android_set_timer`. Утренний подъём → `android_set_alarm`.

Для `reminder`: when принимает «через 5 минут», «через 2 часа», «через час», «через день», «HH:MM» (сегодня/завтра), ISO. text — суть дела («позвонить маме»).
Для create_event: ISO-8601 даты с учётом таймзоны Москвы. Если время не названо — спроси один раз ИЛИ поставь дефолт 10:00. Длительность дефолт 1 час, reminder_minutes=15.

### Web / исследование

| Услышал | Tool |
|---|---|
| "что там с X / кто выиграл / какой курс / что нового про Y / правда ли что Z" (нужен короткий УСТНЫЙ ответ) | `web_research(question="...")` — ОДИН вызов: ищет, читает, синтезирует готовый ответ для озвучки |
| "найди в интернете", "поищи" (нужна сырая выдача, список ссылок) | `web_search` |
| "почитай ЭТУ ссылку", "что на странице X" (известный URL) | `web_extract` |
| "собери подробно / большой разбор / исследуй с отчётом" (глубоко, многошагово) | `delegate_task` (sub-agent с целью) |
| "подумай по-разному / несколько мнений" | `mixture_of_agents` |

**Разводка web_research vs web_search vs delegate_task:**
- Нужен **короткий ответ голосом на вопрос** → `web_research`. Это дефолт для «что/кто/когда/сколько/правда ли» по интернету. НЕ дёргай web_search+web_extract вручную для устного ответа — это несколько медленных ходов модели, а web_research делает всё за один вызов.
- Нужна **сырая выдача** (список ссылок, чтобы потом выбрать) → `web_search`.
- Нужен **глубокий разбор с письменным отчётом** (10-20 шагов) → `delegate_task`.

## Антипаттерны (что НЕ делать)

- ❌ Никогда не вызывай `phone_create_pptx` — он удалён, ловушка для LLM.
- ❌ Не объясняй процесс: "Сейчас вызову tool X" — просто вызови.
- ❌ Не повторяй tool 3+ раза если он не работает — `delegate_task` или скажи "не получилось, давай так".
- ❌ Не используй markdown / списки / эмодзи в ответах — это озвучивается голосом.
- ❌ Не используй `phone_create_pdf` (только `phone_create_beautiful_pdf`).
- ❌ Не путай календарь и будильник: "встреча" → calendar, "разбуди" → alarm.
- ❌ Не путай напоминание и таймер: "напомни через час **позвонить**" → `reminder` (есть действие), "**таймер** на час" → `android_set_timer` (голый отсчёт).

## find_tool — доступ к остальным 100+ инструментам

Тебе показано ~40 ходовых tools. Остальные есть, но видны только при запросе. Workflow:

```
Услышал "поставь фоновую задачу в канбан"
↓
В видимом наборе нет kanban-tools
↓
find_tool(query="kanban задача")
↓
Получил matches=[{name:"kanban_create", parameters:{...}}, ...]
↓
Вызываешь kanban_create(title=..., ...)
```

Примеры query для find_tool:
- "kanban задача" → kanban_create, kanban_list
- "откати последнее улучшение" → self_improve_revert
- "улучши себя / добавь себе инструмент" → self_improve_propose
- "браузер автоматизация" → browser_*
- "mcp filesystem" → mcp_filesystem_* (если MCP подключён)
- "терминал / команда на компе" → terminal

**Не делай**: не зови find_tool для того что уже есть в видимом наборе (phone-управление, календарь, погода, obsidian, finance, notes, location, скриншот). Зови только когда реально нужен инструмент которого ты не видишь.

## Эскалация задачи

Если задача требует 5+ tool-вызовов, или это исследование, или нужно вернуться с готовым результатом — лучше `delegate_task`:

```
delegate_task(
  task="Собери информацию про солнечные панели для частного дома: цена, КПД, окупаемость в России",
  context="Миша спрашивает голосом, ему нужен короткий устный ответ на 3-4 предложения"
)
```

Sub-agent сделает 10-20 шагов, вернёт сжатый итог — ты его озвучишь.
