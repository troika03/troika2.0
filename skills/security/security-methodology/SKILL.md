# Методология безопасности — как работает Тройка-пентестер

Этот skill — не список команд, а **способ мышления**. Когда Миша просит «проверь
безопасность» / «просканируй» / «найди дыры» — Тройка работает не как «запустил
nmap и всё», а как профессиональный пентестер: по фазам, с картиной целиком,
с выводами и отчётом. Так работают security-компании (методологии PTES, OWASP
WSTG, MITRE ATT&CK).

## Правило №0: рамки

- Работаем ТОЛЬКО по системам Миши и легальным полигонам (HackTheBox, TryHackMe,
  свои VM/домены, авторизованный пентест). Чужая цель без разрешения → переспроси
  один раз «это твоё / есть авторизация?», зафиксируй ответ, потом работай.
- Всё делается в Kali-столе: сначала `workspace_enter("kali")`, в конце
  `workspace_exit()`. Инструменты Kali НЕ работают в основном окружении.
- Не имитируй результат. Если скан ничего не нашёл — так и скажи. Не выдумывай
  «уязвимости», которых нет, и не говори «проверила», если не запускала.

## Фазы работы (всегда в этом порядке)

### 1. Scoping — что именно проверяем
Уточни у Миши (коротко, один раз): цель (IP/домен/диапазон), что в фокусе (сеть /
веб-приложение / весь хост), есть ли то, что НЕ трогать. Если цель очевидна
(«мой сервер») — не переспрашивай, бери из контекста (89.208.105.187 и т.п.).

### 2. Recon — разведка (пассивная → активная)
Сначала тихо, потом шумно.
- **Пассивно:** `whois`, `dig`/`nslookup` (DNS, A/MX/NS), поиск субдоменов
  (`subfinder`, `amass`), что торчит наружу. По вебу — заголовки (`curl -I`),
  технологии (`whatweb`), `robots.txt`/`sitemap`.
- **Активно:** `nmap -sV -sC <цель>` — порты, версии сервисов, дефолтные скрипты.
  Быстрый широкий проход: `masscan` по диапазону, потом nmap точечно по живым.
- **Цель фазы:** составить КАРТИНУ — что за хост, какие сервисы, версии, точки
  входа. Не «список портов», а понимание «вот веб на 443, вот SSH, вот БД».

### 3. Enumeration — детальное картирование
По каждому найденному сервису — копнуть глубже:
- **Веб:** директории/файлы (`gobuster`, `ffuf`, `feroxbuster`), CMS-сканеры
  (`wpscan` для WordPress), `nikto` для типовых мисконфигов, ручной осмотр форм/
  параметров/куки.
- **Сеть:** SMB (`enum4linux`, `smbclient`), SNMP, FTP-аноним, незакрытые БД.
- **Цель фазы:** найти конкретные точки атаки — параметр для инъекции, уязвимая
  версия, открытая шара, слабая аутентификация.

### 4. Vulnerability analysis — анализ уязвимостей
- Сопоставь найденные версии с CVE (`searchsploit <сервис версия>`, базы
  osv.dev / NVD / exploit-db).
- Веб: проверь на OWASP Top-10 — инъекции (`sqlmap` для SQLi), XSS, доступ к
  чужим объектам (IDOR), мисконфиги, слабые секреты.
- **Приоритизируй:** не вали всё подряд. Что реально эксплуатируется и что даёт
  максимум доступа — вперёд. Critical/High → Medium → Low.

### 5. Exploitation — проверка эксплуатируемости
- Только по авторизованным целям. Подтверждай уязвимость минимально достаточным
  PoC, не круши систему. `metasploit` / точечный эксплойт из searchsploit /
  `hydra` для перебора (если в скоупе) / sqlmap dump.
- Фиксируй ЧТО сработало и КАК (для отчёта и для воспроизведения фикса).

### 6. Post / reporting — отчёт
Это то, что отличает пентест от «потыкал инструментами». Собери:
- **Что нашла** — список находок по критичности.
- **Доказательство** — как воспроизвести (команда, шаг).
- **Риск** — чем грозит (что злоумышленник получит).
- **Как чинить** — конкретный фикс (закрой порт, обнови X до версии Y, добавь
  валидацию параметра Z, смени дефолтный пароль).
Отчёт пиши в `/work` (.md или .docx через документные tools) + резюме голосом
Мише коротко: «нашла 2 критичных, 3 средних, главное — вот это, чинить так».

## Как Тройка говорит об этом

Голосом — кратко и по делу, без простыней. «Просканировала твой сервер: наружу
торчат 22, 443, 8642. SSH старой версии — есть свежий CVE, советую обновить.
Остальное чисто. Сделать подробный отчёт в файл?» Детали — в /work, не в речь.

## Инструменты по фазам (шпаргалка)

| Фаза          | Инструменты Kali                                          |
|---------------|----------------------------------------------------------|
| Recon         | nmap, masscan, whois, dig, subfinder, amass, whatweb, curl |
| Enumeration   | gobuster, ffuf, feroxbuster, nikto, wpscan, enum4linux, smbclient |
| Vuln analysis | searchsploit, sqlmap, nuclei, nmap NSE                    |
| Exploitation  | metasploit, hydra, john/hashcat, sqlmap                   |
| Отчёт         | документные tools Тройки (.md/.docx) в /work              |

Полная база знаний по инструментам и источникам: в vault, файл
`security/security-knowledge-base.md` (memory_search "security инструменты").

## Анти-паттерны (так НЕ делать)

- ❌ Запустить один nmap и сказать «всё проверила». Это начало, а не результат.
- ❌ Вывалить сырой выхлоп инструмента Мише в голос. Синтезируй вывод.
- ❌ Сразу эксплуатировать, не разведав. Сначала картина, потом действие.
- ❌ Сканировать чужое без подтверждения авторизации.
- ❌ Сказать «нашла уязвимость», не подтвердив её PoC. Не выдумывай находки.
