# Troika 1.0: план реализации

Обновлено 2026-10-05. Это вспомогательный документ, а не второй roadmap.
Scope, цены и Definition of Done задаёт [главный Word-план](docs/Troika_1.0_Launch_Plan_Final_Updated.docx).
Прогресс хранится только в [трекере](docs/TROIKA_1_0_EXECUTION_TRACKER.md),
дефекты и проверки — в [аудите функций](docs/TROIKA_FUNCTIONAL_AUDIT.md).

## Правила исполнения

1. Работать только в `D:\troika-product`. `D:\troikahermes` — источник для чтения.
2. Выполнять Word-план целыми разделами сверху вниз; раздел 20 — итоговая проверка, не альтернативная очередь.
3. Исправлять воспроизводимые дефекты уже реализованных сценариев по запросу владельца. Ремонт не означает закрытие будущих разделов.
4. Не считать код, сборку или unit-тест доказательством работы всей функции у пользователя.
5. В одном изменении фиксировать конкретный сценарий, наблюдаемый результат, проверку и ограничения установленной версии.
6. Данные, совместимые идентификаторы, LICENSE и рабочие runtime-зависимости сохранять при очистке.
7. Обновлять память текущими фактами, затем коммитить и отправлять готовое изменение в `origin main`.

## Архитектурные границы

Клиент Android/Windows выполняет локальные allowlist-команды и отправляет
облачные запросы по HTTPS. API определяет владельца по device token;
session/run/task/memory/workspace/artifact принадлежат аккаунту.
Нормальный hosted agent использует только `troika-product`. Скриншот требует
отдельного согласия и beta flags. Облачный агент не получает host shell
или произвольное управление ПК.

Сервер хранит основную копию данных. Реализованы SQLite/filesystem stores,
общий account context и polling клиента. PostgreSQL/object storage/queue,
полноценная офлайн-очередь и проверенный backup restore ещё не готовы.
Целевая account architecture описана отдельно в [синхронизации](docs/ACCOUNT_SYNC_ARCHITECTURE.md).

## Выпуск

Troika пока не готова к публичной продаже. Отдельные исторические проверки
не закрывают billing, recovery, production storage, backup deletion,
observability, installer/update и финальный E2E. Локальные команды не тратят
AI credits; выключенная сейчас quota enforcement не является обещанием безлимита.

Старые фазы A–E и стартовые задачи из сентября сохранены только в
[архиве](docs/archive/PRODUCTIZATION_PLAN_BEFORE_2026_10_05.md).
