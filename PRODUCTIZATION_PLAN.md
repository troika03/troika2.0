# Тройка: основной поэтапный план ремонта и развития

Обновлено 7 октября 2026 года по прямому запросу владельца. Этот файл задаёт порядок ремонта текущей Тройки и добавления согласованных функций. Требования к запуску, UX и тарифам остаются в [Word-плане](docs/Troika_1.0_Launch_Plan_Final_Updated.docx). Прогресс разделов запуска хранится в [трекере](docs/TROIKA_1_0_EXECUTION_TRACKER.md), факты о поломках и проверках — в [аудите](docs/TROIKA_FUNCTIONAL_AUDIT.md). Записанный пункт не считается выполненным.

## Согласованный результат

Тройка должна стабильно работать на Android и Windows: отвечать голосом, помнить контекст, выполнять задачи, доставлять напоминания, искать информацию, создавать качественные документы и помогать разрабатывать программы.

Решение владельца от 6 октября дополняет прежний Word-план:

- ИИ может оставаться облачным. Регистрация, аккаунт, история и память пока используют сервер.
- Готовые новые документы, презентации и проекты с кодом сохраняются на телефоне или ПК. Постоянную серверную копию этих файлов не создаём.
- Допустима временная сборка файла в оперативной памяти сервера для передачи устройству. После подтверждения получения копия удаляется; без подтверждения действует ограниченный срок хранения.
- Существующие облачные файлы сохраняем до отдельной миграции. Автоматически удалять пользовательские данные нельзя.
- Возвращаем разработку: создание кода, работа с проектом, проверки, разбор ошибок и исправления. Запуск кода выполняется на разрешённом устройстве пользователя, а не на сервере Тройки.
- `hermes_cli` и необходимые runtime-зависимости сохраняем. `D:\troikahermes` остаётся источником только для чтения. Изменения делаем в `D:\troika-product`.

## Что известно сейчас

Аудит 5 октября зафиксировал недоступный web provider, отсутствие Android background token refresh, устаревшую APK на проверенном Samsung, ошибки dashboard/TUI lint и несовместимость dashboard PTY с native Windows. Windows generators унаследованного сайта также работают неполностью. Для текущего состояния учитывать последующие обновления аудита и сверять установленную версию заново.

Python baseline содержит 407 неуспешных тестов и одну ошибку подготовки теста; неуспешны 125 запусков test files. Это очередь для разбора, а не доказательство 407 отдельных поломок пользовательского приложения.

Повтор 6–7 октября охватил 1236 файлов тестов; неуспешны 146 file runs.
[Новый список](docs/audit/PYTHON_FAILURES_2026_10_07.md) сохраняется отдельно от
исторического baseline: лимиты времени и среда отличаются. Целевые проверки
локальных файлов и разработки проходят; общий набор требует разбора.

По обновлению аудита от 6 октября поиск восстановлен через SearXNG; полное
чтение страниц ещё требует подключения. Напоминания и связанные native правки
параллельно исправляются в другой сессии владельца. Этот план сохраняет их
критерии, но не объявляет незавершённую работу принятой.

Ещё отсутствуют recovery/email verification, billing, Windows background notifications/push, полноценная offline sync, production backup restore/deletion, импорт и редактирование Office/XLSX, подписанные установщики и обновления. Для голоса, напоминаний и сохранения файлов нужен свежий E2E актуального установленного клиента.

## Этап 1. Зафиксировать реальные ошибки и версии

1. Сверить commit сервера, версию приложения, сборку на ПК и APK на телефоне.
2. Для каждого отказа записать действие пользователя, ожидаемый и фактический результат, версию, повторение и проверку после ремонта.
3. Разделить подтверждённые дефекты, отсутствующие функции и непроверенные сценарии.
4. Разобрать неуспешные Python file runs из актуального и исторического аудитов: продуктовая ошибка, Windows/POSIX несовместимость, upstream тест, fixture или отсутствующий сервис. Исправить продуктовые ошибки; ограничения отметить явно.
5. Убрать устаревшие утверждения из активной документации и памяти.

**Готово, когда:** аудит содержит воспроизводимую очередь без дублей; для каждого отказа определён следующий шаг и проверяемая версия.

## Этап 2. Починить основные ежедневные сценарии

1. Восстановить web search/extract/research: рабочий provider, credentials, тайм-ауты, ограничение расходов и понятный отказ.
2. Добавить refresh токена в Android background voice service. Проверить expiry, logout, revoke, потерю сети и повторный вход.
3. Проверить голос целиком: пробуждение, запись, распознавание, ответ, прерывание, Bluetooth, заблокированный экран, фон и reboot.
4. Проверить дела и напоминания на актуальной APK: часовой пояс, notifications/exact alarms, quiet hours, отмена и отсутствие дублей.
5. Проверить историю, память и аккаунт на двух устройствах; исключить смешение аккаунтов.
6. Устранить ложное «сделано» при ошибке инструмента или доставки.

**Готово, когда:** сценарии проходят на установленном Android и Windows; версии и результаты сохранены в аудите. Отказ не маскируется успешным ответом.

## Этап 3. Документы и презентации сохраняются на устройстве

1. Передавать DOCX/PDF/PPTX и ZIP без постоянного серверного файла. Проверять владельца, устройство, размер, целостность и срок передачи.
2. Сохранять файл локально до подтверждения серверу. Восстанавливать незавершённую передачу после обрыва без повторного создания документа.
3. Добавить локальный список, открытие, экспорт в выбранную папку, отправку и удаление. Сохранённые файлы открываются без интернета.
4. Применить режим к текстовым и фоновым голосовым запросам. Старые клиентские пути не должны незаметно сохранять новые файлы на сервере.
5. Проверить качество: профессиональный стиль, читаемые заголовки, таблицы и диаграммы по необходимости, корректные страницы и слайды без обрезки.
6. Добавить импорт и правки существующих Office-файлов, новую версию, затем XLSX. Оригинал не перезаписывать без явного действия пользователя.
7. Предложить перенос старых облачных файлов. Удалять серверную копию только после подтверждённой доставки и согласованной миграции.

**Готово, когда:** запрос создаёт открываемый файл на телефоне/ПК; после подтверждения серверной файловой копии нет. Обрыв, переполненный диск, повреждённый файл и другой аккаунт не приводят к потере данных или ложному успеху.

## Этап 4. Вернуть разработку и проверку кода

Первый рабочий объём — режим «Разработка»: описание задачи, проект с исходниками, README и тестами, сохранение на устройство, проверки на ПК и передача ошибок Тройке для новой версии проекта.

1. Создавать код, структуру папок и инструкцию запуска. Отделять проверку синтаксиса от реально выполненных тестов.
2. Защитить распаковку: относительные пути, ограничения размера, отсутствие подмены папок, ссылок, секретов и перезаписи чужих файлов.
3. Добавить локальные проверки Python/JavaScript, видимый вывод, код завершения, тайм-аут и остановку. Нулевое число тестов не считать подтверждением качества.
4. Добавить цикл исправления: действующие исходники и выбранный отчёт проверки, исправление ИИ, новая версия, повторная проверка.
5. Расширить на существующие проекты: выбор папки, предпросмотр изменений, применение правок, Git diff, откат и исключение secrets из контекста.
6. Добавить зависимости и сборки по проекту: pytest, npm, Flutter и другие реально поддержанные инструменты. Запуск согласуется локально; shell облачного сервера не открывается.
7. Добавить code review, тесты поведения, поиск ошибок, предпросмотр интерфейса и отчёт «проверено / не проверено».
8. Для разработки с телефона подключать отдельный ПК: выбор устройства и разрешённой папки, отзыв доступа, остановка и подтверждение запуска.

**Готово, когда:** реальная проверка созданного проекта обнаруживает ошибку, Тройка исправляет её, повторная проверка проходит. Исходники лежат на устройстве; изменения ограничены выбранной папкой. Наличие старой CLI-интеграции версии 1 не считается восстановлением функции.

## Этап 5. Стабильный клиент и чистая сборка

1. Исправить dashboard/TUI lint и разобранные продуктовые Python failures.
2. Исправить Windows generators developer website; проверить содержимое Skills Hub.
3. Реализовать рабочий dashboard chat на native Windows либо явно ограничить поддержку POSIX/WSL. Сломанный путь не показывать как доступный.
4. Проверить Android/Windows сборки, запуск, обновление с сохранением данных, локальные команды, hotkey и файловые ассоциации.
5. Закрыть утечки состояния, бесконечные загрузки, повторные запросы и непонятные ошибки.

**Готово, когда:** обязательные проверки затронутых частей проходят; исключения объяснены и не маскируют ошибки продукта.

## Этап 6. Аккаунт, синхронизация и восстановление

1. Добавить восстановление пароля, подтверждение почты и управление устройствами.
2. Завершить offline очередь, повторы, конфликты и защиту от дублей.
3. Проверить восстановление истории, памяти, задач и настроек после входа. Локальные документы не обещать восстановить из облака без отдельного opt-in backup.
4. Добавить Android push и Windows background notifications без открытого приложения.
5. Проверить logout/revoke/delete/export и изоляцию аккаунтов.

**Готово, когда:** потеря сети и переустановка не ломают согласованные данные аккаунта; пользователь понимает правила резервирования локальных файлов.

## Этап 7. Завершить сайт и подписку

1. Закрыть раздел 7 Word-плана: вход, аккаунт, download, activation, поддержка, статус и legal.
2. Закрыть раздел 8: Free/Plus/Pro, credits/cost ledger, checkout, webhooks, отмена и возвраты. Проверить повторные события и лимиты расходов.
3. Обещать в тарифах только доступные и проверенные функции.

**Готово, когда:** новый пользователь проходит весь путь без ручной помощи; оплата и отмена корректно меняют доступ; повтор webhook не списывает деньги дважды.

## Этап 8. Production и выпуск

1. Завершить production хранилища, очередь, шифрование at rest, backup deletion ledger, restore scrubber и репетицию восстановления.
2. Завершить единый runtime задач, повторы, отмену и ограничения времени/стоимости.
3. Добавить метрики, alerts, диагностику и поддержку без личных данных в логах.
4. Выпустить подписанные установщики, проверенные обновления и процедуру отката.
5. Пройти закрытую beta Android/Windows, затем критерии разделов 9–20 Word-плана.

**Готово, когда:** свежий E2E включает вход, голос, поиск, память, задачу, напоминание, локальный документ, разработку с тестами, оплату, revoke, export/delete и восстановление. Критических ошибок нет; ограничения опубликованы.

## Выполнение и ближайшее действие

Для завершённой работы сохранять ссылку на изменение, проверку, версию клиента/сервера и ограничения в аудите. Затем обновлять память и трекер. «Код добавлен», «тест прошёл», «сборка готова» и «проверено на установленном устройстве» — разные статусы.

В исходниках реализованы локальная передача файлов этапа 3 и первый объём разработки этапа 4: создание проекта, локальная проверка на Windows и передача текущего кода с отчётом ИИ для новой версии. Целевые проверки прошли; Android и Windows собираются. Это пока не доказывает работу установленного приложения или production. Ближайшее действие — согласованно обновить API и клиент, проверить на устройстве сохранение/открытие документов и полный цикл проекта, затем закрыть P0 этапа 2. Работа с существующими репозиториями, произвольные сборки и Companion остаются незавершёнными. Сроки не назначены до проверки объёма воспроизводимых ошибок.
