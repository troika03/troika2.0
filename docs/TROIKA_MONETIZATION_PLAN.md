**Реализация тарифов:**

## 2bis. Кодеры (Тариф 2) — РЕШЕНО: BYOK через OpenRouter

> Решение от 2026-06-30. Кодеры НЕ на подписке/ключе Миши. Каждый юзер — свой ключ.

**Почему не на твоём ключе/подписке:**
- Личная подписка Claude под нескольких платящих юзеров не работает: лимит делится на всех +
  нарушение ToS Anthropic (перепродажа персональной подписки). Подписка остаётся только Мише лично.
- Общий лимит на твоём ключе = мало (выжгут за час) + риск разорения (claude_code жжёт десятки $/день).

**Что выбрано: кодер = один ключ OpenRouter юзера, с двумя режимами.**
- Дефолт «бесплатно» = **Qwen3-Coder `:free`** (SWE-bench 70.6%, 1M контекст; сильнее Gemini Flash,
  который реально туповат — его НЕ берём дефолтом).
- «Нужен топ» = тем же ключом переключение на платную модель (Claude / Kimi K2.7) — платит юзер по токенам.
- Лимит OpenRouter free: 20 RPM, 50–1000 запросов/день (разовые $10 → 1000/день навсегда).
  **На ключе юзера**, не на твоём → у каждого свои 1000/день (≈25 agentic-задач/день — потолок личного юзера).
- Безлимит совсем = Ollama локально (GLM-5/Qwen3-Coder на машине юзера), для тех у кого есть железо.

**За что юзер платит ТЕБЕ в Тарифе 2 (раз кодинг на его ключе):**
НЕ за токены кодинга (их платит он сам Anthropic/OpenRouter). Платит за:
1. разблокировку функций (голос→кодер, проекты `project`, автопилот, async jobs, PM-агент, design-система);
2. твой расход на **мозг ДИАЛОГА** (OpenRouter/Groq Миши — он растёт от числа функций);
3. хостинг + поддержку.
То есть продаём обвязку («машину»), а не токены («бензин»). Честно, юзер это принимает.

**Что поправить в коде:**
- `qwen`-бэкенд в `tools/coder_tool.py` настроен на ЗАКРЫТЫЙ Qwen OAuth free tier (Alibaba закрыла 15.04.2026) →
  перенастроить на OpenRouter (Qwen3-Coder `:free`) через `qwen /auth`, либо заменить бэкенд.
- Аутентификация кодеров сейчас глобальная (`os.environ.copy()` в `coder_tool.py:122`) → сделать
  **per-user**: ключ/модель из профиля юзера (`_SESSION_USER_ID` уже есть в `session_context.py`).

## 3. Мозг и контроль расходов (защита от разорения)

**Проблема:** общий мозг (твой OpenRouter/Groq) на N юзерах = финансовая дыра, если один юзер
сожжёт ключ за ночь.

**Решение — кредитная модель:**
- Подписка даёт **пакет кредитов/сообщений в месяц** (Tier1 = N сообщений, Tier2 = + X часов кодера, и т.д.).
- Каждый юзер — счётчик в БД (`user_id → used_credits`, `reset_at`).
- Кончились → «лимит исчерпан, докупи / жди сброса». Не падаем в минус.
- Дорогие операции (claude_code) списывают больше / отдельный лимит часов.

**Развилка (на потом, ты пока не решил):** кто платит за токены —
1. Ты платишь, заложено в цену (макс. «один тап», нужен жёсткий лимит) — **дефолт для Tier1**.
2. BYOK — юзер вводит свой ключ (тебе токены бесплатны, но лишний шаг) — **опция для Tier2/3 «безлимит»**.
3. Гибрид — N бесплатных, дальше платный тариф выше или свой ключ.

Рекомендация: Tier1 = вариант 1 с лимитом; Tier3 «безлимит» = разрешить BYOK как опцию.

## 5. Подключение пользователя — РЕШЕНО частично (30.06.2026)

> Решено: раздача = **прямой APK по ссылке/боту** (не Play пока). Требование Миши: **юзер НЕ должен видеть ключи.**

### ⚠️ Текущая схема НЕБЕЗОПАСНА для продаж (факт из кода)
`hermes-android/lib/config/hermes_config.dart:17-18`:
- `defaultApiKey = 'hermes-2024'` — **ОДИН ключ вшит в APK** для всех.
- хранится в обычных SharedPreferences (`hermes_api_key`), шлётся `Authorization: Bearer hermes-2024`
  (`PhoneBridgeClient.kt:57`).
- связь по **HTTP**, не HTTPS → ключ летит открытым текстом.

**Три дыры:** (1) распаковал APK (`apktool`) → достал `hermes-2024` → подключился бесплатно/раздал друзьям;
(2) один ключ = нельзя отличить/отозвать юзера; (3) HTTP = перехват ключа в публичном Wi-Fi.
Для Миши-одного ОК. Для продаж — первый покупатель раздаёт доступ бесплатно.

### Правильная схема (юзер ключей не видит)
Различать ДВА типа секретов:
1. **Токен доступа к серверу** — НЕ вшивать в APK. Выдаётся после оплаты, привязан к `user_id`,
   отзываемый, с истечением. Лежит в **Android Keystore** (шифрованное хранилище), не в prefs. Юзер видит
   только одноразовый QR/код, который мёртв после первого обмена.
2. **Ключи кодеров/мозга** (OpenRouter/Claude/Groq) — **вообще не покидают сервер.** Приложение шлёт
   «сделай X» → сервер сам дёргает провайдера → отдаёт результат. BYOK-ключ юзера тоже хранится на
   сервере в его профиле (шифрованным), не в приложении.

### Путь юзера (цель)
```
1. Оплатил (бот/сайт) → сервер создаёт user_id + plan, генерит persistent-токен
2. Получил ОДНОРАЗОВЫЙ QR/ссылку troika://connect?code=... (НЕ ключ, а временный код)
3. Скачал APK по ссылке/из бота, поставил (Android спросит «неизвестный источник» — ОК для MVP)
4. Навёл камеру/тапнул ссылку → приложение обменяло code → на токен по защищённому каналу
5. Токен в Keystore. Дал разрешения (onboarding-экран уже есть)
6. Говорит «Тройка» — сервер по токену знает user_id+plan → нужный toolset+лимиты
```

### Что достроить в коде
- Убрать боевой `defaultApiKey` из APK (оставить максимум гостевой/демо-режим).
- Эндпоинт обмена `one-time code → user token` на сервере (+генерация кода при оплате).
- Хранение токена в **Android Keystore** вместо SharedPreferences.
- **HTTPS** на сервере (сейчас HTTP — обязателен TLS до продаж).
- deep-link `troika://connect` + сканер QR в приложении.
- Сервер: по токену резолвить `user_id`+`plan` (связано с мультитенантностью §4 и биллингом §3).
