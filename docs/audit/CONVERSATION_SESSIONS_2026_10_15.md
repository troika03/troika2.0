# Автоматические рабочие сессии — 15 октября 2026 года

## Причина и изменение

Владелец сообщил, что простое приветствие возобновляет давнюю разработку.
Прежний путь загружал общую историю аккаунта, включая старые запросы и
tool chains, в тот же рабочий разговор. Сокращение длинной истории само по
себе не отделяло старое поручение от текущего намерения пользователя.

По отдельной просьбе владельца текущая серверная работа принудительно
прервана перезапуском только API. Сохранённые пользовательские данные не
очищались. Это остановка runtime, а не удаление истории или файлов.

В стандартном месячном runtime с включённым compact context сервер теперь
создаёт независимые рабочие сессии:

- при коротком самостоятельном приветствии и других распознанных социальных репликах;
- при переходе от такой реплики к содержательному запросу;
- после 30 минут без новых запросов;
- после 24 ходов или достижения 12 000 оценочных токенов прежней истории.

Длинный текущий ход не обрезается. Пауза определяется между запросами;
смена рабочей сессии сама по себе не отменяет явно запущенный фоновый проект.
Распознаватель требует полного совпадения социальной реплики. Приветствие с
просьбой создать файл остаётся запросом действия.

Стабильный `home_session_id` и прежние ID служат адресами общей беседы.
Сервер направляет новый запрос в актуальный сегмент и возвращает объединённую
историю через прежний messages endpoint. Повторная отправка старой истории
клиентом не возвращает её в активный контекст после смены сессии. Введены
owner-scoped связи сегментов; они переживают перезапуск и удаляются каскадно
при удалении аккаунта. Оригинальные сообщения остаются в SessionDB и входят
в существующий экспорт аккаунта.

Прежняя история доступна модели по запросу через `troika_context`:
`history_recent`, `history_search`, `history_read` с постраничным чтением.
Архив не подмешивается целиком в новый prompt. Память, проекты, задачи,
файлы, устройства и согласия не сбрасываются. Память аккаунта остаётся
отдельным owner-scoped хранилищем.

Для распознанной социальной реплики набор инструментов пуст; принудительный
вызов capability router также отклоняется с `no_action_requested`.
Проекты не подмешиваются в приветствие. Общая инструкция требует отвечать
на последнее сообщение и продолжать прежнее поручение только по явной просьбе.

Проверка реальной модели выявила дополнительный случай: cached prompt
приветствия без инструментов мешал читать архив в следующем запросе.
Поэтому переход от приветствия к содержательному запросу создаёт свежую
рабочую сессию со штатным router. Архив обеих сессий сохраняется.

Legacy profiles без месячного compact runtime сохраняют прежний replay;
социальная реплика всё равно получает пустую историю и пустой набор
инструментов. Поведение отключённых возможностей не обходится.

## Проверки

Изолированный кандидат собран на `a5a7758` с наложением исходников реально
развёрнутого API. Незавершённые native/reminder/site правки не включены.

- 703 passed, 0 failed, 1 skipped в 36 целевых Python-файлах.
- После исправления перехода между приветствием и действием: 84 passed,
  0 failed в четырёх затронутых файлах.
- Финальная проверка контекста и сессий: 33 passed, 0 failed.
- Проверены сохранность оригиналов, replay старого клиента, два устройства,
  перезапуск, idle/лимит, точное чтение архива, индексы и cache isolation,
  отзыв устройства, чужой аккаунт, account deletion и запрет forced router.
- Отдельный canary использует собственные SQLite и временные аккаунты.
  Реальная модель проверена через `/v1/runs` и `/v1/chat/completions`:
  приветствие без tool calls; точный факт из прежней сессии; сохранённая
  память и общая история; чужой доступ запрещён; смена после паузы с
  повторным извлечением прежнего факта. Временные аккаунты удалены.

Полный доступный Windows-набор запущен штатным runner с шестью процессами.
Два запуска охватили все 1 254 обнаруженных файла без повторения завершённых
file runs. Первый длительный запуск завершился без aggregate после 937 файлов
(последние счётчики: 18 402 passed, 288 failed). Оставшиеся 317 файлов
завершили runner: 7 096 passed, 124 failed; в них финальные context/session
проверки прошли. Родительский процесс второго запуска получил KeyboardInterrupt
после вывода aggregate, поэтому единый успешный exit code не заявляется.
Суммарные наблюдённые счётчики — 25 498 passed и 412 failed; кроме них есть
collection/import failures и skips. Это красный Windows baseline, а не
подтверждение полной релизной готовности. Реальная модель не гарантирует идеального припоминания
каждой детали: оригиналы сохранены, точность зависит от их чтения.
