# Проверка основы месячного AI-ресурса Troika

Дата: 12 октября 2026 года. Checkout: D:\troika-product,
ветка codex/product-foundation. Решение владельца и тарифы находятся в
[политике подписки](../TROIKA_SUBSCRIPTION_ECONOMICS.md), порядок внедрения —
в [основном плане](../../PRODUCTIZATION_PLAN.md). Это первый этап разработки,
без изменения работающего production счётчика и без запуска оплаты.

## Реализовано

- Политика Free/Plus/Pro: 500 000/5 000 000/10 000 000 расчётных AI-токенов
  за 0/790/1 490 ₽ в месяц; шкала 30 ₽ за миллион единиц ресурса.
- Канонические disjoint input/cache/output counts и reasoning как часть output;
  точная Decimal стоимость и однократное округление всей операции вверх.
- Версионированные all-in цены, отказ при неизвестной используемой цене.
  Цены и FX подаются доверенным адаптером; сеть и смена модели здесь отсутствуют.
- Общий SQLite ledger в access DB с атомарным резервированием на аккаунт,
  единым балансом устройств и любых вызовов parent/worker/voice/tools.
- Идемпотентные операции и выдачи, единственный захват права отправки вызова,
  фактическое списание расчётного ресурса и возврат неиспользованного резерва.
- Диспетчерский timeout/restart сохраняет резерв до сверки. До отправки резерв
  освобождается; превышение верхней оценки не дебетует следующий месяц.
- Free calendar month; платный период выдаётся явно доверенным billing/operator
  адаптером. Запрос или правка entitlement не запускает автоматическое продление.
- Welcome один раз на 14 дней после серверного подтверждения eligibility;
  докупка на 90 дней после подтверждённого платежа; ближайший expiry расходуется
  первым, остатки докупки переживают обновление месячного ресурса.
- Предметные квоты Free и запрет development/deep_research/premium. Покупка
  дополнительных токенов сама по себе не открывает функции другого тарифа.
- Проверка активного owner/device/token, export числовых данных и каскадное
  удаление ledger при настоящем account deletion. Экспорт не содержит prompts,
  clear-text ключей идемпотентности, bearer credentials или raw media.

Публичных HTTP методов выдачи денег/бонусов нет. Флаги подтверждения в серверных
методах являются контрактом доверенного адаптера, а не проверкой подписи оплаты;
нельзя принимать их из JSON пользователя. Автоматические grants не включены.
Ledger проверяет одну помеченную предметную операцию: будущий Run адаптер
помечает один успешный результат, а не каждый внутренний LLM-вызов.

## Проверки

1. Первичный запуск resource ledger + access: 46 passed, exit 0.
2. Все tests/troika_product и tests/gateway/test_product_auth.py:
   21 test files, 313 passed, 0 failed, exit 0. Это объединённый checkout,
   включающий незавершённые изменения памяти/напоминаний других задач.
3. После исправления гонки dispatch: 31 проверка нового ledger passed,
   0 failed, exit 0. Проверена гонка 16 обработчиков: отправку получает один.
4. Ruff check и format нового кода: passed. Python compileall: passed.
5. Отдельный набор предложенного commit без чужого WIP: 31 passed, exit 0.
   Первый повтор получил 30 passed и одну ошибку SQLite «database or disk is
   full» на заполненном C; после переноса TEMP/TMP проверок на D прошли все 31.
6. Для 1 244 default test files объединены завершённые результаты предыдущих
   запусков и целевых проверок (960 файлов), затем проверены оставшиеся 284.
   Остаток: 6 505 passed, 114 failed, 2 файла без выполненных тестов; полный
   aggregate записан, 100% этого остатка завершены за 436 секунд, -j 6,
   file timeout 90 секунд. Обёртка была прервана новым сообщением после записи
   полного summary, поэтому отдельного exit-файла нет; успешный exit не заявляется.
   Общий baseline красный. Это покрытие по файлам нескольких запусков,
   не единый чистый прогон 1 244 файлов и не общий суммарный счётчик тестов.

Финансовые проверки покрывают конкурентный расход последних токенов с двух
устройств, повтор receipt, conflicting key, неизвестный provider bill после
restart, возврат до dispatch, rollover с поздним settlement, paid period,
expiry и порядок grants, предметные квоты pending/success/failure, revoke,
подмену owner и payment receipt, export/delete и некорректные числа/цены.

Сообщённый владельцем baseline приветствия 2–7 тыс. input проверен как полный
provider input, а не длина двух видимых слов. При примерных all-in ценах
20,7/64,86 ₽ за миллион input/output и ответе 500 токенов получены 2 461/5 911
расчётных AI-токенов. Cache input оплачивается меньше. Это проверка формулы,
не production замер конкретного разговора и не обещание числа сообщений.

## Открытые работы

Cost adapters всех LLM/auxiliary/compression/worker/STT/TTS/vision/paid tools;
проверенные цены/FX и actual provider bill reconciliation; единственная
предметная квота на целый Run; concurrency 1/1/3 и Stop всех workers;
оценка/approval бюджета; subscription API и Android/WPF monthly UI;
проверка подписанных платежей, email verification/anti-abuse, global Free cap,
upgrade/downgrade/prorating/cancel/refund; удержание receipts и reconciliation
неизвестных расходов; production migration и installed-client E2E.

Новые таблицы создаются при явной инициализации ResourceLedger. Backend пока
не создаёт его для обычного provider run: действующий дневной guard сохранён.
Тарифные ограничения не объявляются активными, пока все платные маршруты
не проходят через новый учёт. Старые entitlements и реальные аккаунты
на сервере этим этапом не изменены. Android/WPF не редактировались и
не пересобирались этой задачей. Изменения другой работы не включать в commit.
