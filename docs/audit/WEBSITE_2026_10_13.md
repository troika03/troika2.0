## Реализованные сценарии

- Регистрация и вход используют действующий Troika API и создают веб-устройство.
- Токены продукта находятся в зашифрованной HttpOnly-cookie с Secure и
  SameSite=Lax. Пароль и токены не возвращаются клиентскому JavaScript.
- Обновление сессии сериализуется между вкладками. Выход отзывает текущее
  веб-устройство; отдельно доступны отзыв других устройств и завершение всех сеансов.
- Кабинет показывает фактический тариф и ресурс сервера, поддерживая дневной
  и месячный формат. Согласованные цены не подменяют фактически включённый учёт.
- Просмотр, создание, изменение и удаление памяти, настройка автоматической
  памяти, экспорт и удаление аккаунта обращаются к настоящим серверным API.
- Обращения поддержки сохраняются в D1 и проверяют действующий аккаунт.
  Доступ привязан к аккаунту, а не к конкретному веб-устройству. Ответ оператора
  требует проверенной серверной идентичности Sites. Обращения можно выгрузить
  и удалить; удаление аккаунта через сайт удаляет и его обращения сайта.
- Страница статуса выполняет свежую проверку API и показывает время проверки;
  это не полная проверка STT/TTS и всех внешних провайдеров.
- APK и Windows ZIP передаются из R2 потоком; файловые ссылки содержат SHA-256.
  Загрузка больших файлов оператором выполняется частями.

## Оформление

Использованы логотип, favicon, Golos Text с лицензией, иконки и материалы
социального предпросмотра из `brand/troika`. Палитра соответствует комплекту.
По уточнению владельца главная содержит короткий оффер, три сценария,
устройства и компактные тарифы. Инструкции и дополнительные условия открываются
отдельно. Главная, регистрация и навигация просмотрены в браузере. Опубликованная
главная проверена при 390 × 844 и 1280 × 900: горизонтального переполнения
нет, логотипы загружены. Снимок сохранён локально; это не полная матрица
размеров всех страниц.

## Проверки

- Сборка сайта прошла, страницы содержат полноценный HTML без обязательного JS
  для основного контента. JavaScript нужен кабинету и загрузкам.
- 12 проверок поведения прошли: маршруты, metadata, 404, шрифт, CSRF,
  шифрование/подмена cookie, rate limit, allowlist прокси, изоляция обращений,
  серверная роль поддержки, реальный отзыв устройства, подтверждение удаления,
  удаление обращений и передача файлов.
- Локальный Worker с действующим production API прошёл 16 функциональных
  проверок на двух временных аккаунтах, без AI-вызовов и оплаты. Первый cleanup
  прервался из-за временного сетевого отказа. Один аккаунт уже был удалён,
  второй удалён через тот же API с точной проверкой временного ID оператором.
  Отсутствие этого аккаунта подтверждено в серверном registry.
- Опубликованный сайт прошёл 32 функциональные проверки: HTML страниц,
  наличие обеих загрузок, auth, кабинет, D1, изоляция, запрет чужого удаления,
  запрет административной роли для одного service bypass, refresh, настоящий ZIP
  экспорта и выключенная оплата. Два временных аккаунта удалены через сайт.
- Оба опубликованных файла скачаны потоком полностью; размеры и SHA-256 совпали.

## Оставшиеся условия полного запуска

Владелец сообщил, что данные платёжной системы пришлёт позже. Оплата
выключена через `PAYMENTS_ENABLED=false`; сайт не принимает деньги.
Автоматическое восстановление пароля, почтовая верификация, реквизиты оператора,
юридическая проверка платных условий, подписанные установщики и решение об
открытой аудитории остаются незавершёнными. Общая готовность Troika 1.0 и
весь раздел 7 Word-плана не объявляются принятыми.

Worker не изменяет product runtime, данные существующих пользователей или
производственный Compose. Полный унаследованный Python/Flutter baseline в
этой задаче не запускался: изменения ограничены сайтом; его реальные
продуктовые API отдельно проверены указанными smoke-сценариями.
