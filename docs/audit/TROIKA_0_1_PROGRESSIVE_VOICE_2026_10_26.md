# Troika 0.1: раннее воспроизведение естественного голоса

25–26 октября 2026 года подготовлено изменение Android foreground-пути: клиент запрашивает потоковый MP3 и передаёт поступающие байты проигрывателю до полного завершения синтеза. Существующий естественный голос и выбор бесплатных моделей сохраняются. Production и основная установленная APK не обновлялись. Стабильный ответ за 1–2 секунды ещё не подтверждён.

## Установленная причина дополнительного ожидания

В проверенном исходном Flutter-клиенте запрос `/v1/audio/speech` не содержал `stream:true`, а перед воспроизведением клиент собирал весь MP3. Проверенный backend уже поддерживает раннюю передачу, но включает её только по этому явному параметру. Изменение включает существующий потоковый режим для Android; Python-протокол не меняется. Буферизующий fallback провайдера не превращается в потоковый от одного параметра.

При проверке нового проигрывателя отдельно обнаружена ошибка HTTP framing в localhost proxy `just_audio 0.10.6`: неизвестная длина, удалённый chunked framing и persistent connection оставляют чтение без конечного EOF. Это дефект нового диагностического прототипа, а не установленная причина исходных задержек Тройки. Независимый HTTP control воспроизводит отказ. Отдельная копия библиотеки с chunked framing меняет результат с 4 passed / 5 failed на 8 passed / 1 failed; оставшийся отказ относится к тихому disconnect. Package cache не изменялся.

Клиент использует собственный loopback `HttpServer` с корректным chunked EOF, случайным портом и 192-битным путём. Native player не получает токен или URL провайдера. MP3 остаётся в RAM: до 10 MiB на фразу, два активных reader, полный replay с начала без Range. В product-кандидате reader ограничен общим бюджетом воспроизведения 90 секунд; в диагностике использовалось 12 секунд. Тихий disconnect без следующей записи не всегда обнаруживается сразу. Stop и смена identity явно закрывают источник и сервер. Очистка ссылок RAM не означает доказанного обнуления памяти сборщика мусора.

## Ограниченный тест на телефоне

Заранее синтезированный естественный Fish MP3 передавался из RAM; EOF удерживался восемь секунд. Метрика — от первых PC-байтов до получения компьютером положительного события позиции Android. Она не измеряет физический первый звук. Во время запусков новых provider requests не было.

В первом запуске APK8 было две short-инстанции. Playback первой не зафиксирован; причина неизвестна. Число 3109 мс относится только к последней завершённой инстанции. Повтор и release запускали с контролируемым fresh launch, но последовательность и OS caches не рандомизировали. Разницу нельзя полностью приписать режиму сборки.

Пользователь подтвердил слышимость обеих фраз, отсутствие повторённого начала и успешную остановку в завершённом APK8 run. Это отдельное качественное подтверждение, не автоматическое доказательство остальных запусков. Release9 сохранил 325 безопасных событий; короткий case занял 2167 мс до первой позиции. Release APK: 17730223 байта, SHA-256 `71d35c05d582ee229e4aba1045c6c5ed368c708f460c21ab538420391ffc3b34`.

Все APK прежних probe-запусков и принадлежащие задаче reverse удалены. Primary package, его metadata и данные сохранены. Оба RAM fixture server завершились с exit 0; bytearrays очищены в `finally`. Исходники, отчёты и семь APK сохранены. Для освобождения диска очищены только восстанавливаемые outputs отдельного probe-проекта; пользовательские caches и WIP не удалялись.

## Область изменения и ограничения

Каждый ответ получает отдельный `SpeechReply`, каждое воспроизведение — принадлежащие ему RAM source, HTTP adapter и native player. Поздний callback, старый Stop или завершение предыдущего ответа не могут перенаправить звук в новый ответ. Смена владельца, origin, session, отзыв устройства и выход из аккаунта инвалидируют речь до первого ожидания. Same-owner refresh не обрывает действующий ответ. Проверяются native errors, пустой EOF, зависшая загрузка, превышение RAM и отмена до/после получения HTTP headers.

Отдельный player на каждую фразу выбран для изоляции ошибок и cleanup. В phone9 использовался один player на три cases; его тёплые показатели не измеряют производительность product-кандидата. Android native background/reminder WIP не включён в commit. Остальные платформы сохраняют прежний буферизующий backend.

Ревью выявило существовавшее окно в подготовке API-запроса: после ожидания контекста устройства захваченные headers могли сочетаться с новым текущим endpoint. Для chat/stream/speech preflight и продолжений Run добавлена привязка к владельцу, origin, session и revision. Проверка повторяется после ожиданий, внутри повторного TLS-запроса, после callbacks и перед отправкой approval/fallback. Same-owner refresh разрешён. Отмена внутри approval catch не превращается в отправку старого решения новому аккаунту. Непрерывное молчащее SSE не получает нового универсального механизма отмены; проверка срабатывает при следующем продолжении. Другие API и атомарность многошаговой записи аккаунта вне этого ограниченного исправления.

Только два новых audio-плагина используют classpath действующего проекта: AGP 8.11.1 и Kotlin 2.2.20. Wrapper, settings, app build, package cache и версии runtime не обновлялись. Pin находится в исходном root Gradle-файле и регистрируется до оценки app; внешний diagnostic override версий не нужен. Отдельные receipts сохраняют первоначальные ошибки доставки зависимостей и окончательный результат сборки.

Полная сборка обнаружила ещё одно несоответствие неизменённого HEAD: фоновый отчёт вызывал отсутствующую трёхпараметрическую функцию player. Добавлен отдельный `speakWithResult`, сохранивший прежний API. Он возвращает успех только после `MediaPlayer.onCompletion` для того же поколения; ошибка, Stop, пустой текст и замена воспроизведения не считаются успешной доставкой отчёта. Вызов отчёта использует этот результат. Существующие незавершённые native callbacks напоминаний не переносились в собственный commit.

Ранние прямые Fish HTTP пробы дали первый аудиобайт за 0,833–2,287 секунды. Они не включали проигрывание и не складываются с таблицей в измеренный E2E. Не измерены полный путь STT/model/gateway/TTS/acoustic onset, повторные cold starts product-клиента и живой разговор после обновления. Бесплатный router сохраняет нестабильные хвосты задержки. Ориентир 1–2 секунды остаётся незакрытым.


## Проверки исходников и сборка

Замороженный HEAD-кандидат: 210 passed / 2 skipped; оба config cases отдельно прошли с синтетическим URL, всего 212 различных cases. Анализ lib/test: 58 прежних info, без ошибок и предупреждений. Новые 23 identity cases входят в общий счётчик. Для слияния Account/Config отдельно прошли пять поведенческих проверок; Android native bridge проверен статически.

Текущая рабочая копия после сохранения WIP: 217 passed / 2 skipped; оба config cases отдельно 2 passed. Analyze: 58 info, 0 warning, 0 error. Числа отдельных запусков не складываются в один набор.

Изолированная release APK полного клиента собрана из HEAD и собственного изменения; native WIP в неё не копировался. Размер 81424183 байт, SHA-256 `e043e1f492514ac07479e59ead88f3b09a6219ebf167f29bc1c61e43d94b79c3`, `debuggable=false`, отдельный applicationId `com.troika.hermes_assistant.voicediagnostics` и заведомо тестовый endpoint. На этапе проверки сборки она не устанавливалась. Сборка использовала действующие AGP/Kotlin, canonical source pin и точные зависимости из task cache/официальных Maven источников. Внешней подмены classpath не было. Первоначальные отказы сохранены: generated Properties representation, отсутствующий AGP9 в offline cache и отсутствующая Guava 33.0.0-android и несовместимый вызов native player в неизменённом HEAD.

Python на этом этапе не менялся. Последний общий Python discovery остаётся красным: 24761 passed, 501 failed, 158 skipped, 2 errors и ещё 24 nonzero файла без summary при cap 60 секунд. Целевой повтор 37 файлов дал 668 passed. Эти результаты не объявляются новым зелёным Python regression.

Исходные staged/unstaged слои сохранены отдельно. Из 61 исходного WIP 55 файлов вне пересечений остались байтово идентичны; пять пересекающихся файлов объединены с собственными изменениями, память объединена в HEAD/index/working вариантах. Остальные 21 staged path не входят в commit. Никакого deploy или замены основного приложения не выполнялось. ## Установка по запросу владельца — 26 октября

Полная диагностическая APK установлена отдельным пакетом `com.troika.hermes_assistant.voicediagnostics`. SHA-256 установленного base.apk совпал с проверенной сборкой. Основной пакет не заменён; его версия, дата обновления и путь остались прежними. Разрешения автоматически не выдавались, приложение не запускалось. Имя и значок совпадают с основной «Тройкой»; пакеты различаются в сведениях о приложении.

Сборка содержит `https://voice-diagnostics.invalid`; developer diagnostics выключены, поэтому обычный UI не позволяет войти или изменить адрес. Установка не является живым голосовым тестом. Для него нужна отдельно подготовленная сборка с доступным тестовым подключением. Production и все исходные staged/unstaged слои сохранены.
