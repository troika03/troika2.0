# Разработка на телефоне и выбранном ПК

Решение владельца от 8 октября 2026: восстановить цикл автономной разработки,
доступный с телефона и ПК; перед проверкой спрашивать, где выполнять её.
Исторический `tools/project_tool.py` использован как источник последовательности
«план, код, проверка, ошибки, исправление». Общий доступ к shell и выполнение
кода на облачном сервере не восстанавливались.

## Реализованное поведение

Раздел «Разработка» обращается к облачному агенту напрямую. Создание проекта
с `index.js` больше не проходит через локальные команды запуска приложений.
Дополнительно Android-матчер открывает приложение только по отдельной явной
команде и полному совпадению имени; буква `x` внутри имени файла не запускает X.

Пользователь описывает задачу, выбирает Python/JavaScript и место проверки.
Можно проверить на текущем телефоне, текущем ПК, выбранном доступном ПК аккаунта
или только сохранить код. ZIP должен быть действительно передан и сохранён;
текстовое заявление ИИ о готовности без файла считается ошибкой.

После локального разрешения цикл распаковывает новую версию в отдельную папку,
запускает выбранную проверку, передаёт текущие исходники и настоящий отчёт ИИ
при ошибке и проверяет следующую версию. Лимит — три исправления. Совпавшие
исходники, Stop, тайм-аут и отсутствие тестов не дают ложного успеха. Старые
версии сохраняются. Каждый вызов ИИ учитывается действующим тарифом.

На Android в APK включена Pyodide 0.28.3/Python 3.13.2. Архив core закреплён
SHA-256 `46fd28bfacd5b78333d73f171412cc992a2cab2332b067e4d2181fd255cca730`;
метаданные, хеши файлов и лицензии находятся рядом с активами. Python и
переносимый CommonJS работают в отдельном WebWorker с виртуальными исходниками,
без монтирования файлов телефона, JavaScript/Java-моста и внешней сети.
Поддерживаются Python unittest и JavaScript `test(name, callback)` с основными
проверками `node:assert/strict`; внешние пакеты и другие возможности Node.js
нужно проверять на ПК. Проверка синтаксиса не означает выполнение тестов.

Новый самостоятельный WPF-клиент и исторический Flutter Windows поддерживают
приём проверок с телефона. Приём включается локально, работает при открытом
разделе и требует подтверждения первого проекта. Разрешение ограничено четырьмя
версиями за десять минут. ПК запускает фиксированные команды Python/Node.js
с правами пользователя; отдельной ОС-песочницы нет. Сессия, аккаунт, выбранное
устройство и краткоживущее разрешение связывают задания и отчёты. Отмена, отзыв
доступа и закрытие раздела прекращают приём. Windows Job Object завершает
дочерние процессы нового ПК-клиента.

API `/v1/development` только передаёт задания, исходники и отчёты. Они находятся
в RAM с TTL 10 минут; сервер код не запускает, не записывает исходники на диск
или в журнал. Проверены ownership, одноразовая выдача задания, отмена, отзыв
доступа, replay, лимиты размера/числа заданий и общий бюджет RAM. Этот механизм
не является универсальным phone-to-PC Companion.

## Проверки

- Полный Flutter: 98 passed, 2 skipped. Analyze: 0 errors/warnings, 31 info.
- Новый ПК-клиент: сборка и 30 passed; в том числе настоящий Python/JavaScript
  failure/fix/pass, импорт исходников тестами, Stop, новые версии, повторный код,
  выбранный ПК и выполнение полученного проекта после подтверждения.
- Точный APK WebWorker с включённым Python WASM: 5 passed в Node harness.
- Android-матчер: JUnit 4.13.2, 3 passed; новый bridge компилируется против SDK.
- Серверная передача: 9 passed через штатный runner, включая HTTP с настоящим
  AccessRegistry и отдельными устройствами одного/другого аккаунта.
- Интерфейс выбора устройства: телефон 375 × 812, крупный шрифт и восемь ПК
  без переполнения. Панель WPF просмотрена при минимальном размере 780 × 540.

Два запуска Android integration собрали debug APK, но запуск сорвался из-за
системного AppOps crash и незавершённой загрузки пользователя эмулятора Android
36.1. Физическая попытка Samsung собрала debug APK; повтор с `--no-uninstall`
остановился при CMake: на диске C не осталось места. Тесты на телефоне не
выполнены; успешный harness не объявляется установленным Android E2E.

Полный default Python запущен штатным runner `-j 6` и завершил попытку с exit 1;
итоговый aggregate отсутствует. Последний счётчик в журнале: 17 385 passed,
295 failed. Есть Windows/POSIX и прежние несовместимости; TEMP первой попытки
лежал внутри checkout, поэтому часть тестов определения Git-корня зависит от
окружения. Чужие изменения возможностей и напоминаний также оставались в рабочем
дереве. Полный baseline не объявляется зелёным.
