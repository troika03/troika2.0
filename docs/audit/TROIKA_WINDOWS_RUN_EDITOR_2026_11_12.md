# Управление тестовым редактором Windows из Run

Локальный тестовый API выдаёт команды Hermes выбранному устройству Windows.
Пользователь подтверждает доступ в окне редактора. Модель выбирает осмотр,
ввод текста из задачи и сохранение. Исполнитель UI Automation работает в
отдельном процессе и проверяет идентификатор окна. Редактор подтверждает
сохранение после чтения точных байтов временного файла.

Одному Run соответствует одно разрешение на выбранное устройство. Оно
действует до 120 секунд. Сервер передаёт только одну команду за раз, выдаёт
её один раз и принимает отчёт с тем же идентификатором и токеном устройства.
Команда действует до десяти секунд, осмотр до 15 секунд. Ввод и сохранение
требуют свежего осмотра. Windows проверяет срок ещё раз перед изменением.

Модель получает технические квитанции и признаки доступности ввода и
сохранения. Windows получает текст только в команде ввода. Сервер удаляет его
из очереди при выдаче команды или при отзыве. Содержимое редактора,
идентификатор Windows и путь файла остаются на ПК. Итог Run формируется
по квитанциям. В этом режиме отключены запись диалога и дампы запросов
к модели. Текст команды отсутствует в квитанциях и событиях Run.

Локальный Stop, Esc и закрытие окна сразу отзывают допуск редактора. Stop
на сервере прекращает выдачу команд и приём отчётов. Уже полученная
команда может завершиться до того, как Windows узнает об отзыве. Ошибка
доставки не запускает повтор действия.

## Запуск в тестовом окружении

Запустите API на `127.0.0.1` с продуктовой авторизацией и
`platforms.api_server.extra.product_computer_windows_lab_enabled: true`.
Режим выключен по умолчанию. Используйте отдельный аккаунт и два тестовых
устройства. Инициатор создаёт `POST /v1/runs` с текстом задачи и полем
`"computer_windows_lab": true`. Затем он отправляет
`POST /v1/runs/{run_id}/computer-windows-lab/request` с `version: 1`,
`target_device_id` и `ttl_seconds`. Ответ содержит `grant_id`.

В окружении запуска WPF установите `TROIKA_COMPUTER_TEST_DEVICE_TOKEN`
для выбранного устройства Windows. Передайте идентификаторы Run и
разрешения из ответов API.

```powershell
.\TroikaDesktop.exe --computer-use-windows-lab http://127.0.0.1:8642 <run-id> <grant-id>
```

Задайте строку для ввода в тексте задачи. Нажмите «Разрешить и запустить»
в редакторе. После проверенного сохранения окно показывает локальный путь
к файлу. Команда ввода принимает одну строку длиной до 512 единиц UTF-16.
Сервер и Windows проверяют длину, корректность Unicode и управляющие символы.
Новый клиент подтверждает поддержку текста через `text_input: true`.
Старый клиент сохраняет режим со встроенной пробной строкой.

## Редактор в отдельном приложении

`build.ps1 -Test` собирает `TroikaComputerUseEditor.exe` рядом с
`TroikaDesktop.exe`. Для запуска с тем же тестовым Run передайте
идентификаторы из ответов API и токен выбранного Windows-устройства
через `TROIKA_COMPUTER_TEST_DEVICE_TOKEN`.

```powershell
.\TroikaComputerUseEditor.exe --run http://127.0.0.1:8642 <run-id> <grant-id>
```

Окно редактора работает в собственном процессе и хранит допуск локально.
Исполнитель UI Automation запускается из `TroikaDesktop.exe` отдельным
процессом. Перед чтением он проверяет путь к исполняемому файлу редактора,
процесс-владелец окна и идентификатор окна. Управление ограничено
контролами этого редактора. [Определение процесса-владельца окна](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowthreadprocessid)

Для ввода отдельный редактор принимает стандартный вызов
`ValuePattern.SetValue`. Поле разрешает изменение после проверки свежести
одноразового допуска и точного совпадения текста с разрешённой строкой.
Текст попадает в процесс исполнителя по перенаправленному входному потоку.
Перед чтением и вводом исполнитель проверяет признак парольного поля.
Сохранение выполняет кнопка тестового редактора, после чего проверяются
байты файла. [Стандартная операция ValuePattern.SetValue](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.valuepattern.setvalue)

Нативные тесты подтвердили сохранение с проверкой байтов и отзыв уже
подготовленного сохранения после Stop. Тест с таким же идентификатором
редактора в другом исполняемом файле получил отказ. Редактор входит
в тестовую сборку. Обычный установщик копирует только файлы клиента.

Дополнительные проверки подтвердили отказ до согласия, при подмене текста
и при попытке прочитать парольное поле. Истечение срока команды в момент
`SetValue` оставляет поле пустым и возвращает статус устаревшего осмотра.
После перехода на `SetValue` прошли полная сборка WPF и 32 проверки
Computer Use. Сквозной Run снова сверил байты Unicode-строки в файле
отдельного редактора.

Сквозной Run с подставными ответами модели прошёл через локальный HTTP.
Отдельный редактор сохранил Unicode-строку и сверил байты. Полный набор WPF
прошёл. Первый параллельный прогон серверных тестов прервал файл Computer Use
по лимиту времени. В отдельном прогоне прошли все 27 тестов этого файла.
В повторном прогоне 18 файлов прошли 484 теста, один пропущен.

## Визуальный осмотр и OCR

Соберите клиент с `build.ps1 -Test` и откройте визуальную пробу из папки
сборки:

```powershell
.\TroikaComputerUseEditor.exe --preview
```

Нажмите «Разрешить осмотр», затем «Сделать снимок». Тестовый редактор
отрисовывает только своё пробное поле через WPF в кадр до 640 × 240
пикселей. Распознавание Windows читает русский текст из пикселей кадра.
Если русский языковой пакет OCR отсутствует, интерфейс показывает кадр и
сообщает, что распознавание недоступно. Для пробы достаточно локальной
сборки. Кадр и результат остаются в памяти процесса.
[Отрисовка WPF](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.imaging.rendertargetbitmap.render),
[Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.recognizeasync)

Осмотр доступен до двух минут после согласия. Кадр и распознанный текст
убираются из интерфейса через 15 секунд, при скрытии, сворачивании и
остановке. После Stop ответ уже запущенного OCR отбрасывается. Этот режим
работает отдельно от Run и ограничен визуальным деревом тестового поля.

Полный набор WPF прошёл. Windows OCR распознал «Пробная запись Тройки» в
кадре поля. Тест по пикселям проверил размер кадра, отрисовку текста и
исключение соседнего элемента. Отдельно проверены отказ до согласия,
очистка предпросмотра по сроку и при скрытии, Stop во время OCR и
отсутствие результата после Stop. Все 32 проверки Computer Use прошли,
включая Run с отдельным редактором.

Исполнитель передаёт Windows Graphics Capture дескриптор одного окна

до 1280 × 800 и распознанный текст используются только в локальном
предпросмотре. Режим ограничен пробным окном.
[Захват по дескриптору окна](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createforwindow)

Проверка перекрыла целевое окно другим окном. В полученном кадре были
пиксели целевого окна, а тестовый цвет перекрытия отсутствовал. Проверены
отказ до согласия, очистка при скрытии окна, Stop во время захвата и отказ
при установленном запрете захвата. Полный WPF с `-TestWindowCapture`
и 32 регрессии Computer Use прошли.

## Один кадр в модельной пробе

Соберите `troika-desktop\build.ps1 -TestWindowCapture`. Из корня
репозитория запустите одноразовый локальный сервер и пробное окно:

```powershell
$env:TROIKA_COMPUTER_LAB_TOKEN = [Guid]::NewGuid().ToString("N")
$server = Start-Process -FilePath .\.venv\Scripts\python.exe -WindowStyle Hidden -PassThru `
    -ArgumentList "-m", "scripts.troika_computer_lab", "--vision-test"
try {
    .\troika-desktop\build\TroikaComputerUseEditor.exe --vision-lab http://127.0.0.1:8765
} finally {
    if (!$server.HasExited) { $server.Kill() }
    Remove-Item Env:TROIKA_COMPUTER_LAB_TOKEN
}
```

Разрешите осмотр и сделайте снимок. Проверьте предпросмотр и нажмите
«Передать один кадр». Действие доступно 15 секунд с начала захвата.
Stop отменяет ожидающую отправку и очищает ответ. Сервер принимает
один PNG до 1 МиБ и 1280 × 800 пикселей по токену, действующему две минуты
со старта сервера. Для новой передачи запустите новую пробу.

Сервер проверяет и перекодирует PNG без метаданных. SDK Hermes получает
одну часть изображения и фиксированный вопрос. Подставной ответ
формируется в памяти внутри транспорта SDK. Тест не вызывает внешний
провайдер и не запускает локальную языковую модель. Ответ выводится как
текст. Кадры не попадают в историю и журнал отладочных запросов SDK.
[Формат запроса с изображением](https://openrouter.ai/support/)

Сквозной тест получил кадр от отдельного процесса Windows, проверил его
пиксели в запросе SDK и дождался ответа в интерфейсе. Проверены отказ до
подтверждения, истечение предпросмотра, повторная отправка, лишние поля
ответа и отсутствие кадра в отладочном журнале. Полная сборка WPF,
35 проверок Computer Use и отдельный запуск сервера с `--vision-test`
прошли.

## Кадр в тестовом Run Hermes

На локальном API с продуктовой авторизацией и адресом `127.0.0.1`
включите `platforms.api_server.extra.product_computer_windows_vision_enabled`.
В той же секции `extra` укажите `product_computer_windows_vision_model`
с ID конкретной модели OpenRouter, поддерживающей изображения. Установите
`OPENROUTER_API_KEY` в окружении сервера или в `.env` профиля Hermes.
Флаг по умолчанию выключен. Без ключа или модели Run не открывается.

Для проверки используйте тестовый аккаунт и зарегистрированное
Windows-устройство. Инициатор создаёт `POST /v1/runs`
с текстовым `input` и `"computer_windows_vision": true`. Затем отправляет
`POST /v1/runs/{run_id}/computer-windows-vision/request` с полями
`version: 1`, `target_device_id` и `ttl_seconds` до 120. Ответ содержит
`grant_id`.

Установите токен выбранного Windows-устройства в
`TROIKA_COMPUTER_TEST_DEVICE_TOKEN`. Из сборки `-TestWindowCapture`
запустите пробу:

```powershell
.\TroikaComputerUseEditor.exe --run-vision http://127.0.0.1:8642 <run-id> <grant-id>
```

Разрешите осмотр, сделайте снимок и проверьте предпросмотр. Нажатие
«Передать кадр в OpenRouter» подтверждает внешнюю передачу для этого Run.
Согласие привязано к назначенному Windows-устройству и получателю.
Повторная отправка отклоняется. Срок кадра начинается в момент захвата
и ограничен 15 секундами. Stop и закрытие окна отзывают локальное
разрешение и запрашивают отзыв на сервере. Ответ после отзыва не
публикуется. Уже переданный запрос может завершиться у OpenRouter.

Hermes передаёт в OpenRouter один текст и одно изображение PNG. Запрос
требует `zdr: true` и `data_collection: deny`. При недоступности
подходящего маршрута Run возвращает ошибку. Описание приходит инициатору
в результате Run. Инструменты управления недоступны. Кадр отсутствует
в выводе Run, истории, дампах запросов и событиях плагинов.
[Настройки маршрута OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection)

Подставной режим проверок задаётся отдельным флагом
`product_computer_windows_vision_fixture: true` без модели. Он не
используется при ошибке OpenRouter.

Живой сквозной Run отправил синтетический кадр отдельного окна через
OpenRouter. Модель `google/gemma-4-26b-a4b-it` правильно определила
синий фон. В этой пробе использовался изолированный тестовый аккаунт
Тройки. Автоматические проверки сверили пиксели запроса, отдельное
согласие на внешнюю передачу, ответ Run и отказ при лимите OpenRouter.
Полный WPF и 109 целевых проверок Python прошли.
[Проверенная модель OpenRouter](https://openrouter.ai/google/gemma-4-26b-a4b-it)

## Единый Run. Осмотр, действие и проверка

Включите оба тестовых режима `product_computer_windows_lab_enabled` и
`product_computer_windows_vision_enabled` на локальном API. Укажите ключ
OpenRouter и модель с поддержкой изображений и вызова инструментов.
Создайте Run с `"computer_windows_assisted": true`. Запросите разрешение
для Windows-устройства через `/v1/runs/{run_id}/computer-windows-assisted/request`
с полями `version: 1`, `target_device_id` и `ttl_seconds` до 120.

Запустите тестовый редактор из сборки `-TestWindowCapture`. Токен выбранного
Windows-устройства передайте в `TROIKA_COMPUTER_TEST_DEVICE_TOKEN`.

```powershell
.\TroikaComputerUseEditor.exe --run-assisted http://127.0.0.1:8642 <run-id> <grant-id>
```

В редакторе выберите доступ. «Всегда спрашивать перед изменением» предлагает
подтвердить точный текст и сохранение по отдельности. «Разрешить действия в
этом окне до конца запуска» подтверждает ограниченный доступ за один раз.
«Только просмотр» возвращает описание кадра. По умолчанию редактор
спрашивает перед изменением. Режим действует на один Run.

В соседнем окне подтвердите осмотр, проверьте снимок этого редактора и
разрешите отправку в OpenRouter. В режимах с действиями модель получает
текст задачи, описание одного кадра и квитанции действий. Она заново
осматривает редактор перед изменениями. Windows сверяет введённый текст и
байты сохранённого файла. Оба окна отзывают разрешение по Stop. На чтение
кадра действует срок 15 секунд, на подтверждение изменения до 30 секунд.
Сценарий ограничен отдельным тестовым редактором и его временным файлом.

Цикл опирается на осмотр, действие и проверку, описанные в Claude Code,
и на отдельное подтверждение перед действием по подходу Codex. Граница
доступа проверяется исполнителем, результат сообщает о подтверждённом
действии Windows. [Claude Code](https://code.claude.com/docs/en/how-claude-code-works),
[OpenAI Docs](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals)

Живой Run через OpenRouter и Gemma 4 26B осмотрел тестовый редактор,
запросил два отдельных подтверждения, ввёл строку и сохранил файл.
Проверка сравнила фактические байты с заданной строкой. Отдельные
сквозные проверки покрыли все три режима, отказ и Stop во время
ожидания подтверждения.
