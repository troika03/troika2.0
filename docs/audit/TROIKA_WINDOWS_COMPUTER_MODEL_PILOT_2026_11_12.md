# Модельный пилот управления Windows

Тестовый запуск WPF `--computer-use-agent` принимает текст задачи и просит
модель выбрать следующий шаг в отдельном тестовом редакторе. Тестовый сервер
слушает `127.0.0.1` и использует модельный клиент Hermes для запроса в OpenRouter.
Оператор указывает модель и отдельный тестовый ключ. При ошибке запрос
завершается без перехода к другому провайдеру или ключу. Локальная модель для
этого сценария не используется.

После локального согласия клиент отправляет текст задачи, технический статус
прошлого действия и доступные команды. Осмотр состоит из идентификатора и двух
флагов. Содержимое экрана, имя окна и путь к файлу не входят в запрос модели.
Тестовый сервер отклоняет дополнительные поля и неправильный идентификатор
осмотра. Он не пишет запросы в историю Тройки. Запрос направляется на фиксированный
HTTPS-адрес OpenRouter без перенаправлений, повторов SDK и заголовков кэша ответа.

Модель выбирает `inspect`, `write`, `save` или `finish`. Клиент ограничивает
задачу восемью решениями, двумя минутами согласия и 15 секундами на осмотр.
Ввод принимает одну строку, а сохранение требует нового осмотра. Файл создаётся
в отдельной временной папке и считается сохранённым после чтения его байтов.
Ответ модели `finish` сам по себе даёт статус завершения без создания файла.

Stop отзывает разрешение на ПК и отменяет ожидание HTTP. Клиент проверяет его
ещё раз после ответа модели и перед изменением окна. Если запрос к провайдеру
уже отправлен, он может завершиться, но его результат не выполнит действие.

Обычный Windows-клиент, серверные маршруты продукта и внешний Блокнот этой
работой не подключаются. Пилот ограничен собственным тестовым окном. Запуск
описан в [инструкции WPF](../../troika-desktop/README.md).

## Проверки

Прошли полная сборка WPF с `build.ps1 -Test` и 15 целевых тестов Python, включая
регрессии dry run. Проверены отказ от чужого идентификатора осмотра, запрет
лишних полей, авторизация и поздний ответ после Stop. Ruff и проверка пробелов
в изменениях прошли.

Сквозной сценарий прошёл через реальный локальный HTTP, тестовый сервер и
Windows UI Automation. Подставной SDK Hermes выбрал четыре команды по доступным
действиям. Сохранённый текст совпал с текстом команды. Живого запроса к OpenRouter
в этой проверке не было. Новый сервер запускается отдельно, прежние серверные
модули Python в коммите не изменены. Результаты полного набора для этих модулей
зафиксированы в [аудите dry run](TROIKA_COMPUTER_DRY_RUN_2026_11_11.md).
