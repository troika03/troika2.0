# Развёртывание каталога возможностей

2026-10-08 серверный каталог развёрнут после сообщения владельца о недоступном
разделе Android. До обновления `/v1/account/capabilities` возвращал 404.

Новый образ `troika-production:capabilities-20261008` построен поверх точного
работавшего development image; его исходный образ сохранён под тегом
`troika-production:capabilities-base-20261008` для отката. Код каталога взят из
проверенного коммита `11a3cc8`: 12 runtime файлов, без остальных локальных
незавершённых изменений. При объединении сохранены восемь серверных строк
development relay. Разница остальных исходных файлов с родителем коммита
проверена перед объединением. Перенос Windows CRLF устранён в build context.

В образ добавлены версии из committed lock: jsonschema 4.26.0,
jsonschema-specifications 2025.9.1, referencing 0.37.0, rpds-py 0.30.0;
attrs 25.4.0 уже был установлен. `py_compile` прошёл.

В отдельном одноразовом контейнере без production volumes штатный
`scripts/run_tests.sh` выполнил 25 тестов каталога: все прошли. Тестовые pytest
и tiktoken установлены только в этот контейнер и не включены в runtime image.
Общий ранее проверенный Python baseline остаётся красным; новая полная
проверка при этом развёртывании не выполнялась.

Пересоздан только `api` через `deploy/production/compose.yaml` с `--no-deps`.
Пользовательский storage и настройки не заменялись. API healthy;
STT `bf92c78` и существующий SearXNG не пересоздавались. Старый образ доступен
для отката тем же Compose-путём.

Проверка публичного API на временных аккаунтах подтвердила:

- `/health` — 200; каталог без авторизации — 401.
- Авторизованный каталог — 200, `troika.capabilities`, девять групп,
  `Cache-Control: no-store`.
- Переключение web сохраняется при повторном GET и не меняет другой аккаунт.
- Неизвестная capability отклоняется с 400.
- Flags capability preferences, deferred tools, development relay и device
  file delivery включены.
- Оба временных аккаунта удалены после проверки.

Android подключён, но каталог во время проверки UI не был открыт.
Отображение страницы на телефоне, полный установленный цикл с инструментом
и фактический расход входных токенов провайдера этим развёртыванием не доказаны.
После обновления сервера старую страницу с ошибкой нужно обновить или открыть
заново; повторная установка APK для серверного исправления не требуется.
