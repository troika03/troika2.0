# Основа агентного контура Тройки — 11 ноября 2026

Первый этап реализации после исследования архитектуры. Hermes остаётся движком.
Изменения подготовлены в отдельном рабочем дереве от `ba0f607`. В набор не входят
изменения владельца или других задач, настройки production и новые возможности
управления устройствами.

## Изменения

- Компактный Core версии 9 уточняет, как агент доводит задачу до проверяемого
  результата, учитывает ограничения и сообщает о неизвестном исходе. Полный Core
  остаётся версии 7. Существующая миграция версии обновляет компактный контекст
  без удаления истории. Каталог, схемы инструментов, права и модели сохранены.
- Контроль повторов в продуктовом API различает маршрутизированные инструменты
  и известные операции чтения. Для результата используется поле `ok`, когда оно
  есть. Успешные записи не считаются повторами чтения. Политика не разрешает и не
  выполняет вызов; решения остаются за прежними проверками. Остановка по умолчанию
  включена только для продукта; выключатель `product_tool_loop_guardrails_enabled`
  сохраняет диагностический режим. CLI по умолчанию не меняется.
- Обычный агент с месячным учётом ресурса, включая запуск с ключом пользователя,
  получает `product_agent_timeout_seconds` (по умолчанию 1 800 секунд) при
  привязке агента. После истечения времени новые вызовы блокируются, агенту
  передаётся команда остановки. Уже отправленные платные вызовы остаются на
  сверке. Chat и Runs проверяют лимит до отправки удержанного финального текста
  и сообщают `resource_run_deadline_exceeded`. Ранее переданная безопасная фраза
  о ходе работы остаётся в потоке.
- Поток удерживает короткое начало внутренней инструкции до отличимого
  продолжения. Проверка идёт на границе полной фразы. Обычный ответ в женском
  роде и написание промпта для стороннего агента сохраняются.
- Три Android обработчика пишут в журналы фиксированные события и коды вместо
  URL, данных авторизации, сырых команд, текста экрана и сообщений исключений.
  Формат ответа `ok`/`error`/`info` сохранён. Разрешённый явный запрос чтения
  по прежнему протоколу продолжает возвращать результат запрашивающей стороне.

## Проверки

Через `scripts/run_tests.sh` прошли 545 тестов в 21 файле, один пропущен.
Проверены настоящие HTTP обработчики с подставным агентом, время окончания,
ранняя фраза без ложного подтверждения, гонка потоков, учёт ресурса, ключ
пользователя, доступ к инструментам, генерация документов и личность Тройки. Для
Android компиляция и JVM проверка используют три изменённых Kotlin исходника,
локальный Android SDK и подставной транспорт. Проверки не обращались к моделям
и не требовали устройства. Ruff по изменённым Python файлам и `git diff --check`
прошли.

Общий Windows набор запускался отдельно с изолированным домашним каталогом и
лимитом 60 секунд на файл. До прерывания обработаны 945 из 1 273 файлов:
18 505 тестов прошли, 297 упали; файлов со сбоями или таймаутами — 92. При
повторе этих файлов на чистом `ba0f607` 89 файлов также завершились со сбоем.
Из трёх остальных два прошли на кандидате в целевом прогоне; третий прервался
на сетевой загрузке публичного каталога моделей. С локальной заглушкой этого
каталога все 12 тестов файла прошли. Оставшиеся 328 файлов обработаны при
возобновлении: сохранены длительности всех файлов, код завершения 1. Итоговая
сводка возобновления не сохранилась, поэтому точное число сбоев по всему набору
не подтверждено. После возобновления отдельно прошли 108 проверок учёта ресурса,
подписки, рабочего контекста и контекста инструментов; они включены в 545 выше.
Это не зелёный общий прогон.

В числе сбоев чистого `ba0f607` — два теста Chat/Runs, ожидавшие полного отключения
потока. Тесты теперь передают ложное утверждение в callback и проверяют, что клиент
получает только проверенный финальный ответ. Оба теста прошли.

## Границы и следующий шаг

Время отсчитывается от привязки агента: оно не ограничивает весь STT/TTS тракт,
старый режим без месячного учёта или операции ввода-вывода, которые уже идут и
не поддерживают отмену. У фоновой разработки остаётся свой лимит. Проверка
исходников не доказывает сокращение задержки: в локальном `cl100k_base`
изолированный Core вырос с 1 383 до 1 405 токенов. Задержка и стоимость живого
разговора не измерялись. APK не собиралась и не устанавливалась. Production не
обновлялся.

Для публикации исходников используется `[skip ci]`: workflow на push в `main`
иначе публикует Docker-образ с тегом `latest`. Локальные проверки не заменяют CI.

Далее — контракт локальных действий в режиме dry run: схема намерения, явное
согласие с ограниченным сроком, остановка и отзыв, проверяемый результат. До
проверок этого контракта новый доступ к Windows или Android не включается.
