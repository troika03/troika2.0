# Качество проектов в разделе разработки

## Результат

Проверена жалоба: веб-приложение для подсчёта калорий пришло ZIP-архивом с
двумя файлами, включая Hello World, а в приложении раздел разработки может
открывать обычный чат. Исходный архив пользователя не был приложен, поэтому
его состав здесь не проверялся.

Инструмент `troika_create_project` только принимает файлы и собирает ZIP.
Он не генерирует исходники. Ранее он не проверял полноту проекта. Теперь
создание ZIP отклоняется, если нет реализованного кода, README.md с запуском
или файла тестов поведения. Тривиальная программа Hello World не считается
реализацией. Проверка состава не запускает код и не подтверждает работу
функций. Передача документов и отдельных файлов через `troika_files.write`
сохраняет прежнюю совместимость.

Подсказки разработки в системной инструкции сервера, Android и ПК-клиенте
теперь прямо объясняют, что упаковщик не пишет код, и требуют сохранять
браузерный интерфейс и логику веб-запроса. Это снижает риск подмены веб-сайта
консольной программой, но само по себе не гарантирует соблюдение требований
моделью.

## Проверка модели и приложения

Прямой диагностический запрос к текущей модели `openrouter/free` вызвал поиск
средств разработки и упаковщик. Первый вызов упаковщика завершился ошибкой
аргументов; следующий содержал `index.html`, `style.css` и `calories.js`, но
не включал README и тесты. Сервер вернул понятную ошибку полноты; ZIP не был
создан. Временная учётная запись удалена. Утверждать, что генерация проекта
исправлена, нельзя: модель не завершила эту задачу, а доступная конфигурация
остаётся на бесплатном маршруте.

Сборка Android release APK прошла, однако телефон не был подключён и APK не
установлен. Переход «Файлы → Разработка» в исходном коде ведёт на экран
разработки; сообщение о переходе в обычный чат не было воспроизведено на
устройстве. Поэтому причина этого перехода в установленной версии остаётся
непроверенной.

## Проверки кода

- Целевые тесты Python для упаковщика, передачи, возможностей и системной
  инструкции прошли: 57 passed; отдельный набор правил проекта — 10 passed.
- Клиент Flutter: 98 passed, 2 skipped. Analyze: 0 errors/warnings,
  31 info.
- ПК-клиент: сборка прошла, 30 тестов и 3 проверки каталога возможностей
  прошли.
- Полный штатный Python-набор запущен. На момент записи runner прошёл 16 709
  тестов и сообщил 269 ошибок; общий запуск ещё работал. Уже видны ошибки
  совместимости Windows-тестов, ожидающих POSIX-поведение процессов.
  Предыдущие полные baseline-запуски тоже были красными, поэтому эти числа
  сами по себе не показывают, вызваны ли отдельные ошибки текущими правками.
- Production API обновлён новым образом; health вернул успешный ответ.
  Остальные production-сервисы не пересоздавались.

## Что остаётся

Нужна проверка на телефоне: открыть «Файлы → Разработка», повторить задачу
подсчёта калорий и убедиться, что запрос остаётся в разработке, модель создаёт
полный браузерный проект, локальные тесты действительно проверяют исходный
модуль, а ZIP появляется в файлах. Пока этого нет, сервер гарантирует только
отказ от явно неполного пакета, а не успешный результат модели или работу
приложения.
