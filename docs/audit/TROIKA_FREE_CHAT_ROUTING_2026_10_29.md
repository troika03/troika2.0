# Восстановление обычного ответа — 29 октября 2026

Владелец сообщил, что Тройка стала отвечать медленнее и выдаёт только
«user safety safe». Stop и напоминание на установленной основной APK работают.
После описанного ниже ремонта владелец подтвердил нормальный содержательный
ответ на телефоне. Задержка до физического звука отдельно не измерялась.

## Причина и границы доказательства

В production использовался `openrouter/free`. Этот маршрутизатор случайно выбирает
доступную бесплатную модель; фильтрация зависит от запрошенных возможностей.
В текущем каталоге присутствует `nvidia/nemotron-3.5-content-safety:free` —
классификатор безопасности, возвращающий оценки safe/unsafe, без tool calling.
Это согласуется с сообщённой фразой, но прежние личные запросы и фактический model
той генерации не читались. Историческая причина остаётся обоснованной гипотезой.
[Free Router](https://github.com/OpenRouterTeam/docs/blob/main/guides/routing/routers/free-router.mdx),
[описание классификатора](https://openrouter.ai/nvidia/nemotron-3.5-content-safety:free).

Свежий прямой router-probe выбрал `recursive/flint-v1.0:free` и исчерпал 96
completion tokens без видимого текста. До переключения два синтетических запроса
через production API дали корректные ответы, но первый текст появился через
1778,23 мс в Runs и 7628,40 мс в Chat. Это показывает нестабильность маршрута,
а не воспроизводит прежний classifier-ответ пользователя.

## Минимальный ремонт

Обычный hosted agent закреплён за `nvidia/nemotron-3.5-lightning:free`. На сервере
перед активацией повторно проверены весь нулевой price map, text output и tools.
В основной `config.yaml` и reference-фрагмент добавлена точная price entry:
`debit_mode: model_tokens`, четыре нулевых коэффициента, output bounds
8192/65536. В реальный mounted config эта запись объединена с прежним каталогом;
`resource-beta.yaml` самостоятельно не загружается. Vision capability новой
модели не объявлялась. Сохранены прежние услуги Fish и отдельный development route.
`reasoning_effort: none`, `fallback_providers: []`, `fallback_model: null` исключают
автоматический переход обычного hosted агента на платный резерв.

Перезапущен тот же `production-api-1` с тем же image
`sha256:1f82d6b8f4234cc322bae8fe2a0cb9de56363ae087ef50557466c6b63200421e`.
Окружение, HostConfig и mounts сравнены в RAM до/после; они совпали. Прежний
config сохранён на сервере для отката. Health и hash mounted candidate проверены.
Compose, другие сервисы, ключи и данные владельца не менялись. Новая APK не нужна:
остаётся установленная 29 октября сборка SHA-256
`0cac9025674c33a8d1535301672505f55256c4b136afd8e3414c8835d9293048`.

## Проверки

Основная серия из пяти принятых synthetic provider probes использовала проверенные бесплатные
text routes, нулевой provider max_price, без retries/redirects/платного fallback.
Lightning: первый русский текст 244,17 мс, полный короткий ответ 361,64 мс;
Ultra: 788,43/905,43 мс. Lightning выполнила безопасный диагностический tool call
и ответила на его результат по-русски. Первый tool step занял 31092,55 мс;
ответ после результата — 367,44/505,13 мс. У всех пяти принятых прямых probes
провайдер сообщил `cost: 0`. Это малая серия, не оценка стабильного p95.

Предварительный read-only probe с env-only источником ключа вернул HTTP 400.
Он не входит в успешную серию; его ошибка не устанавливает причину исходного
сбоя. Успешная серия читала explicit HOME/.env первым без interpolation,
затем environment только при отсутствии записи, без общего profile loader.

После переключения через обычные API routes получены четыре корректных русских
ответа без classifier-формы. Первый Runs после restart: 13621,34 мс до текста,
13709,41 мс до завершения; следующий Chat: 858,11/957,98 мс. Повторный Runs:
1037,50/1076,55 мс; Chat: 760,96/802,41 мс. Холодный выброс сохранён в результатах.
Это server loopback text timing; STT, TTS, сеть телефона и акустическое начало
не включены. Стабильные голосовые 1–2 секунды этим не доказаны.

115 tests passed, 0 failed в четырёх файлах через `scripts/run_tests.sh`:
LLM metering, metered runtime, resource ledger и development team. Проверены
admission точного model price, raw-token debit и существующие guards. Python
source не менялся; полный прежний красный baseline не перезапускался. Flutter
и Android source не менялись, поэтому прежний результат 282 passed/2 skipped
не объявляется новым запуском тестов этой серверной поставки.

Первые disposable accounts без verified resource grant остановились до provider
с `monthly_resource_exhausted`; они удалены. Для последующих probes только новым
одноразовым аккаунтам выдан диагностический grant через trusted operator methods.
Все такие аккаунты после запросов удалены, без изменения реальных entitlements.
Один SSH запуск не дал диагностического результата; последующая проверка не нашла
осиротевших аккаунтов этого namespace. Дальнейшие jobs выполнялись независимо
через systemd, чтобы обрыв SSH не отменял finally-cleanup. Личные prompts/chats,
аудио и credentials не читались и не сохранялись в отчёт.

## EGM и оставшиеся ограничения

По прямому запросу владельца установлен и включён `egm@egm` 0.1.0 из
`google/elephant-goldfish-model`, commit
`f0ba151b252c9abf1318d9fe857a43265d06de89`. Прежние настройки Codex сохранены;
модель Codex не переключалась. Применён `egm-drift-report` к production README
и соответствующим исходникам. Найдены пробелы upgrade/image и resource-fragment
merge; инструкция уточнена этой поставкой. Отдельное расхождение Telegram profile
относится к сохранённому параллельному WIP и не включено в этот ремонт.

Для ordinary chat пока нет отдельной runtime-проверки нулевой цены каждого
provider response: здесь используется точный заново проверенный `:free` slug,
пустые fallback-цепочки и существующий metering. Новый classifier denylist или
платный fallback не вводились. Холодные задержки, большие tool runs и полный
voice E2E остаются задачами дальнейшего измерения. Standby/reboot, expiry/revoke,
backup/restore и другие разделы продукта этим ремонтом не закрываются.
