## Native streaming: сборка и установка подтверждены

Подготовлена проекция девяти собственных файлов поверх HEAD `2a580e6`, без чужого
native reminder/account WIP. NativeSpeechQueue получает PreparedAudio handle до
завершения загрузки и передаёт его асинхронному Media3 player. Версия Media3 — 1.4.1,
та же, что уже использует just_audio. Ограничение RAM — 10 MiB на фразу. Приложение
инициирует один synthesis Call на фразу со stream:true; повторное открытие и seek
читают RAM и не создают дополнительных synthesis Calls. Очередь сохраняет порядок и ограниченную предзагрузку.

Очередь владеет active и prepared handles: закрывает их при completion, Stop,
shouldStop и deadline, а поздний результат подготовки закрывает отдельно. Закрытие
будит RAM-reader и отменяет HTTP. Turn generation и закрытый player защищают от
позднего запуска; Call.cancel подавляет chat POST, отменённый до execute. Завершение
старого запроса очищает только собственный Call. Ошибка загрузки передаётся как
ошибка чтения, а не нормальный EOF. Естественный голос и бесплатная модель сохранены.

Нижняя плашка — один overlay: сначала «Слушаю»/«Говори», затем «Думаю»; текст ответа
появляется после завершения chat stream, до ожидания конца очереди речи. Safe delta
раньше направляется в очередь и отдельно на плашке не отображается. Поэтому
субъективные 3–4 секунды после плашки не заменяют измерение от конца речи.
TroikaVoiceTiming пишет только счётчик, фазы request/first_byte/eof/playback_position,
миллисекунды, bytes и EOF; текст, URL, ключи и аудио в эти события не входят.

JVM-проверки очереди и RAM-буфера: 14 passed, Kotlin 2.2.20/JUnit 4.13.2. Последняя
серия включает barrier второго handle в deadline-тесте, передачу в playback до EOF, порядок,
предзагрузку, закрытие active/prefetched/late handles и отмену. Свежий Flutter-набор:
210 passed / 2 skipped. Analyze: exit 0, без ошибок и предупреждений, 59 info.
Это целевые проверки; красный общий Python-набор ими не закрывается.

Первая сборочная попытка остановлена из-за неявного online pub. Повтор прошёл
Flutter checks, но остановлен до APK при проверке контракта audio focus Media3:
automatic focus для USAGE_ASSISTANT несовместим с этой версией. В исходниках теперь
setAudioAttributes(..., false): assistant usage сохранён, automatic focus отключён,
как в прежнем MediaPlayer-пути без явного запроса focus. Изменены только этот
Kotlin-файл и комментарий. Совпадение всех Dart inputs подтверждено отдельным receipt,

Capture 18:53:23 UTC содержит 16 идентификаторов фраз. Это не 16 turns: привязки

## Постоянная операционная команда API

На сервере сохраняются закрепляющие образ override-файлы. Для последующего
обслуживания этого API использовать исходные project directory, env file и compose
вместе с `activation-pinned-image.override.yaml`:

```sh
docker compose \
  --project-name production \
  --project-directory /srv/troika/current/deploy/production \
  --env-file /srv/troika/current/deploy/production/resource-images.env \
  -f /srv/troika/current/deploy/production/compose.yaml \
  -f /srv/troika/releases/voice-latency-20261027/activation-pinned-image.override.yaml \
  up -d --no-deps --no-build --pull never --timeout 60 api
```

Базовый compose без закрепляющего override может вернуть старый tag API.
Для отката сохранены прежний образ и
`/srv/troika/releases/voice-latency-20261027/rollback-pinned-image.override.yaml`:
в той же API-only команде заменить только последний `-f` на этот файл. Не удалять
оба override и прежний образ; после операции проверять образ, hashes исходников,
health и сохранность окружения. Значения секретных env-файлов в отчёт не включены.
