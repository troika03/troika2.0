# Troika 0.1: сокращение ожидания ответа — 24 октября 2026

Цель владельца — начало содержательного голосового ответа примерно через
1–2 секунды после конца реплики. Этот результат пока не достигнут и не измерен
на установленном основном клиенте. Production не изменялся.

## Изменения

1. Для настоящего OpenRouter URL исключён запрос Ollama `/api/show` при
   определении контекста модели. Раньше холодная ветка могла ждать его timeout
   5 секунд; фактический вклад в наблюдаемые пользователем 5–10 секунд неизвестен.
   Конфигурация контекста, положительный кэш, hosted/custom Ollama и дальнейший
   поиск метаданных сохранены. Проверяется URL, а не только название provider.
2. Сервер передаёт известный пробел или перенос после проверенной фразы сразу.
   Раньше `rstrip()` удалял разделитель, и клиент повторно удерживал предложение
   с точкой до следующих данных. Десятичные дроби, проверка заявлений о выполнении
   и удержание непроверенного финала сохранены. Изменение разделителя перед
   финальным уточнением не повторяет уже переданный префикс.
3. В Flutter обычный ответ больше не ждёт синхронизацию напоминаний перед
   обновлением состояния и выпуском хвоста в TTS. Синхронизация продолжается
   существующим сервисом. Ответ о создании напоминания по-прежнему ждёт результат
   и сохраняет предупреждения о доставке. Из чужого WIP выделены только два
   собственных участка; Windows/refresh/native дополнения той работы не публикуются.

## Измерения и границы доказательств

Resolver проверен через HTTPX MockTransport: 20 повторов на каждую ветку и
ревизию, искусственное ожидание 50 мс. OpenRouter: запросов `/api/show` 20 до
исправления и 0 после; p50 51,592 и 0,081 мс. Hosted Ollama: 20 запросов в обеих
ревизиях, p50 51,512 и 51,536 мс; результат контекста не изменился. Это не замер
живого OpenRouter, создания всего агента или голоса.

Свежая отдельная проба резервного Edge TTS использовала синтетическую короткую
русскую фразу, аудио только в RAM. Для закреплённой в проекте версии 7.3.1
получены 3/3 MP3: первые аудиоданные через 2,905 / 1,941 / 1,492 секунды;
весь MP3 через 3,843 / 2,470 / 1,890 секунды. Это последовательные запросы
из текущей сети, без STT, LLM, шлюза продукта и физического воспроизведения.
Выборка слишком мала для надёжных p50/p95. Диагностическая среда с прежней
7.2.7 получила 3/3 ошибки WebSocket handshake; источник различия не установлен.
Глобальное окружение и зависимость проекта не изменялись.

После уточнения владельца «пока на бесплатных моделях» выполнена отдельная
проверка двух маршрутов с подтверждёнными нулевыми ценами и запретом fallback.
`openrouter/free` вернул HTTP 429 без текста; фиксированный
`nvidia/nemotron-3.5-lightning:free` ответил HTTP 200: первый текст 0,438 с,
финал 0,504 с, usage cost $0. Это по одному запросу, не оценка стабильности.
Одновременно работали шесть процессов тестового набора.

Read-only credits по-прежнему показывает отрицательный остаток. Он может мешать
бесплатным моделям по [документации OpenRouter](https://openrouter.ai/docs/api_reference/limits),
но успешный запрос NVIDIA не позволяет считать все бесплатные маршруты
недоступными. Причина HTTP 429 этим не установлена. Предыдущий неизвестный
резерв $0,00074256 не сброшен. Модель продукта и production не переключались;
платные модели и платный fallback не используются.

Фиксированная NVIDIA на старом тестовом ключе: 20/20 greetings,
первый текст p50/p95 1,149/6,201 с, максимум 10,849 с; 16/20 в пределах 2 с.
Planning с low/1536: 5/10 успешны, два length_limit, три timeout; успешные
first text p50/p95 16,120/21,438 с. Все три двухшаговые проверки инструмента
прошли: корректные аргументы и ответ RAM-fixture, без действий продукта.
Всего 36 calls, 33 receipts с cost $0, три timeout без usage receipt.

Временный ключ проверен только в памяти процессов. На нём NVIDIA greeting
10/10, p50/p95 0,726/6,052 с; openrouter/free 3/10, семь ошибок:
три reasoning_required, два 429, один 404 и одна stream_error.
Альтернатива google/gemma-4-26b-a4b-it:free получила 10/10 HTTP 429;
скорость и качество ответов не измерены.

На том же временном ключе planning: low 5/5, первый текст p50/p95
14,118/18,545 с; disabled 5/5, 0,717/0,906 с. Арифметический heuristic прошёл
5/5 и 4/5 соответственно; это не семантическая проверка качества всего плана.
Группы выполнялись последовательно, с ограничением ответа 1536 tokens.
Эти небольшие серии не обосновывают безусловное отключение reasoning во всех
задачах. Фиксированный бесплатный профиль пока используется только локально.

Локальный gateway с настоящими auth/resource guard/AIAgent/SSE: 5/5,
первый текст p50/p95 1,417/3,805 с, конец 1,526/4,261 с; все пять usage cost $0.
Первый запрос: agent init 956 мс и первый текст 3,805 с. Последующие четыре:
init 142–146 мс, первый текст 1,161–1,433 с. Серия проведена после общего набора.
Профиль синтетический, лимит контекста заранее задан 128000, metadata HTTP
исключён, tools=0, max_tokens=384, quotas/voice выключены, resource guard включён,
повторных model calls и fallback нет. Это отдельная конфигурация для измерения,
не обновлённый production и не контролируемый A/B с сериями 22 октября.

Текущий естественный голос Fish S2.1 Pro с прежним русским voice ID тоже
проверен временным ключом: 3/3 HTTP 200 после проверки всех цен каталога.
Первые аудиоданные: 2,287 / 1,175 / 0,833 с; весь MP3: 3,204 / 1,867 / 1,545 с.
Текст синтетический, аудио только в RAM; микрофон и реальное воспроизведение
не проверены. Эти отдельные числа нельзя складывать и выдавать за голосовой E2E.
Ключ не записан в .env/командную строку/результаты; после завершения дочерних
процессов переменные очищены и REPL сброшен. Проверенные файлы перечислены
в числовом receipt; проверка не утверждает сканирование всего диска.

## Проверки

Полная default-discovery: 1270 уникальных файлов, с явным
per-file cap 60 секунд вместо прежнего default 600. По summaries:
24761 passed, 501 failed,
158 skipped, 2 errors; exit 1.
24 nonzero файлов без summary не считаются нулём tests.
Пропусков/дубликатов файлов нет; Python source hashes не менялись. Это красный
набор с ограничением времени; его счётчики нельзя сравнивать с прежним cap 600
как доказательство исправления или появления всех ошибок.

Шесть файлов получили nonzero, хотя раньше проходили. Разбор стеков выявил
лимиты 60/30 с, ожидание TLS в прежней custom probe, короткое временное ожидание
и вероятную collection race при удалении временного каталога другим worker.
Новые изменённые строки в этих стеках не наблюдались. Изолированный повтор
не выполнен; считать все эти отказы доказанно прежними нельзя.

После него unfiltered целевой повтор: 37 файлов,
668 passed, 0 failed, 0 skipped, exit 0.
Новые delimiter/footer cases сначала падали; после исправления Python guard-набор
прошёл 68 tests. Resolver до исправления: 6 failed / 12 passed, новый файл
после исправления: 21 passed.

Flutter HEAD + собственная правка: 15 passed; analyze чистый. Полная рабочая
копия: 139 passed, 2 skipped; эти два config-сценария отдельно прошли с безопасным
synthetic HTTPS define: 2 passed. Полный analyze: exit 0, 58 info, без warnings/errors.
Счётчики повторов не складываются. Новые client cases проверяют раннюю отправку
TTS, обычный ответ при pending reminder GET, ошибки, reminder await, flush и cancel.

Отдельная diagnostics APK собрана, applicationId проверен внутри APK,
166743483 bytes, SHA-256
`b0973a197dbfe6ecc2bf9908cbaa87cf0248db7c77eeca1e04edb077b57675ef`.
Она не устанавливалась. Обёртка получила UnicodeEncodeError при печати галочки
после успешного build; сохранённый exit сборки 0 и APK проверены независимо.
Прежняя APK и её receipts сохранены отдельно.

Полный набор включает исходный пользовательский WIP. Он не является проверкой
чистого HEAD. Новые клиентские тесты отдельно проверяются на HEAD с выделенной
правкой, без prerequisites чужой работы с напоминаниями. Mock TTS 503 доказывает
раннюю отправку запроса и сохранение текста при отказе; слышимый звук не проверяет.

## Что остаётся

Оба Android пути ещё загружают MP3 фразы целиком перед воспроизведением. Фоновый
native reminder sync находится в чужом незавершённом WIP и этим commit не меняется.
Нужен отдельный сквозной замер: конец речи, финальная расшифровка, первая безопасная
фраза модели, первый запрос/байт TTS и начало воспроизведения, отдельно cold/warm.
Сборка и синтетические проверки не подтверждают цель 1–2 секунды.

Основной установленный Android/Windows клиент не заменён. Все исходные staged,
unstaged и untracked изменения сохранены. Изменения предназначены для локальной
проверки; публикация образа и production deployment не запускались.
