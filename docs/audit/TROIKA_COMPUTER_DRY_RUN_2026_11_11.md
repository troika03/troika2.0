# Контракт Computer Use для пробного запуска

Второй шаг плана внедрения проверяет согласие, срок действия и остановку команд
на синтетическом окне. Маршрут доступен в тестовом API при активной авторизации
продукта и явном включении `platforms.api_server.extra.product_computer_dry_run_enabled`.

## Как проходит пробный запуск

Запрос начинается с активного Run, созданного в `/v1/runs`. Владелец указывает
зарегистрированное устройство Android или Windows своего аккаунта и срок до
120 секунд. Сервер проверяет принадлежность Run и устройства. Запрос согласия
показывает выбранное устройство, синтетическое окно `scratchpad`, операции
`inspect` и `click`, оставшееся время и лимит восемь операций. Согласие поступает
с авторизованного целевого устройства и привязывается к его токену. Срок идёт
с момента запроса и при согласии не продлевается.

Все вызовы используют `POST /v1/runs/{run_id}/computer-dry-run/{operation}` и
объект JSON с `version: 1`. Объект запроса ограничен 4 КиБ. Схема отвергает
неизвестную версию, лишние поля и дубли имён полей.

| Операция | Кто может вызвать | Дополнительные поля |
|---|---|---|
| `request` | Устройство, запустившее Run | `target_device_id`, `ttl_seconds` |
| `review` | Целевое устройство | `grant_id` |
| `consent` | Целевое устройство | `grant_id`, `allow` (логическое значение) |
| `action` | Устройство, запустившее Run | `grant_id`, `action_id`, `sequence`, `action`. Для `click` нужны также `observation_id` и `element_id: "preview"`. |
| `stop` | Любое из двух устройств с исходным токеном | `grant_id` |

`grant_id` создаётся сервером и передаётся тестовому клиенту целевого устройства
для `review`. `action_id` задаёт инициатор в виде 32 строчных шестнадцатеричных
символов. `sequence` начинается с 1. Повтор того же ID и полей возвращает прежний
статус. Изменение полей при том же ID отклоняется. `click` требует последний
актуальный осмотр. Осмотр действует до 15 секунд и перестаёт действовать после
нажатия. Команды не исполняются после Stop, завершения Run, отзыва токена или
устройства и истечения срока согласия.

`inspect` возвращает тестовое описание окна отдельно от `receipt`. Результат
операции содержит `status: "simulated"` и `verified: false`. В `receipt` входят
только версия, режим, статус, идентификатор операции, номер и тип действия. Само
описание окна не передаётся в историю или события Run. Состояние согласия и
записи действий хранятся в памяти процесса. Отзыв и остановка удаляют осмотр и
результаты действий, удаление аккаунта очищает все его запросы.

## Приёмка и границы

91 целевой тест прошёл через `scripts/run_tests.sh`, в том числе 10 проверок
dry run. Использованы существующие HTTP обработчики Run, Stop и отзыва устройства
с локальной базой и подставным агентом. Проверены запрет устаревших команд и
отсутствие меток тестового окна в SSE и базе. Ruff и `git diff --check` прошли.
При обычном запуске API на loopback с подставным агентом проверены выключенный
маршрут, обязательная авторизация, согласие, осмотр, Stop и отказ в повторе после
Stop. Временные базы удалены после выхода тестового процесса.

Общий прогон Windows обработал 1 274 файла с лимитом 60 секунд на файл.
Runner сообщил 23 617 пройденных тестов, 404 ошибки и 162 файла с ненулевым
кодом завершения. В 54 из этих файлов итоговых результатов тестов нет, поэтому
404 не включает ошибки сбора и таймауты без итоговой сводки файла. Счётчик
процента в сводке равен нулю из-за отсутствия общего числа собранных тестов.
89 из 162 файлов также завершались сбоем в прежних прогонах. Совпадение имени
файла не подтверждает совпадение причины. Список всех причин не сверялся.

В общем прогоне прошли все 10 тестов dry run, штатные API и авторизация.
Файлы проверки личности и подтверждения действий прерваны по таймауту.
При повторе отдельно прошли 36 тестов личности и 5 тестов подтверждения действий.
Всего целевые прогоны прошли 132 теста. Для отправки кода используется `[skip ci]`,
поскольку workflow на push в `main` публикует Docker-образ с тегом `latest`.

Согласие по API подтверждает принадлежность токена, а присутствие человека
потребует отдельного подтверждения в приложении. Команды моделируют действия
над одним тестовым элементом. Доставка на устройство, локальный Stop и
передача временного осмотра только в текущий запрос модели остаются следующими
проверками перед подключением реального управления. Режим по умолчанию выключен.
