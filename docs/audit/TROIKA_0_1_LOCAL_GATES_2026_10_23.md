# Troika 0.1: локальные проверки перед закрытой альфой

Проверки: 23–24 октября 2026 года. Исходная версия: `b0055257` в
`codex/product-foundation`. Production, настройки рабочего профиля и основной
установленный Android-клиент не обновлялись. Исходный staged/unstaged/untracked
WIP сохраняется отдельно от изменений этой задачи.
Проверялось сохранённое рабочее дерево вместе с исходным WIP, а не отдельная
чистая checkout-копия. Диагностическая Android APK содержит текущий Android WIP;
этот WIP и изменения клиентов не включаются в commit данной задачи.

## Задержка и минимальное исправление

Приоритет владельца от 24 октября — живой голосовой ответ вместо ожидания
5–10 секунд. Рабочий ориентир: начало содержательного ответа через 1–2 секунды
после конца реплики. Это целевой критерий, а не подтверждённое время.
Короткий служебный звук или фраза ожидания не закрывают этот критерий.

Последние живые модельные серии описаны в
[отчёте задержки](TROIKA_0_1_LATENCY_2026_10_22.md). Для двух последовательных
локальных серий приветствий доля завершений оставалась 17/20; после явного
отключения reasoning p50/p95 видимого SSE составляли 2,659/14,418 с.
Это не контролируемый A/B и не измерение production. Цель p50 ≤ 2,5 с ещё
не подтверждена.

23 и 24 октября read-only запросы OpenRouter `/credits` вернули HTTP 200
и отрицательный остаток тестового ключа. Числа баланса и ключ не сохраняются
в отчёте. Новых модельных POST в этой части работы нет. Ранее зарезервированные
$0,00074256 без квитанции не обнулялись; автоматический платный fallback не
включался. Причина прежнего Qwen HTTP 429 по этим данным не установлена.

Найден отдельный локальный источник ожидания: `working_context.token_count`
вызывал конструктор `cl100k_base`, который при пустом кэше загружал словарь
через сеть без собственного тайм-аута. Теперь оценка читает только локальный
словарь, проверяет размер и SHA-256 и переиспользует готовый encoder. Пустой,
повреждённый или недоступный кэш использует прежнюю оценку по UTF-8 bytes/3.
Кэш не загружается, не исправляется и не удаляется из запроса; environment
не меняется. При появлении исправного локального словаря точный подсчёт
восстанавливается без перезапуска. Словарь не добавляется в Git.
Это убирает автоматическую HTTP-загрузку словаря. Если сам cache path расположен
на сетевой файловой системе, ожидание её `stat/open` отдельно не ограничено.

Это локальная оценка контекста, а не фактический расход модели. Резервирование
расходов по байтовой границе и списание по provider usage не менялись.
При fallback численные оценки и границы сжатия могут отличаться от `cl100k_base`;
оригинальная история и сообщения не переписываются.

Изолированный замер функции на синтетическом тексте, без сети: первый вызов
при отсутствующем кэше — 0,192 мс, повреждённом — 2,129 мс, исправном —
121,389 мс. Для каждого состояния затем выполнены 50 повторов; p95 —
0,018/0,026/0,088 мс соответственно. Это время локальной функции с уже
импортированными модулями, не cold start процесса и не задержка ответа ИИ.
В примере приблизительная оценка 220 отличается от точных 141 токена.

## Проверенные границы

Две новые интеграционные проверки проходят через реальный loopback HTTP:

- регистрация, неверный пароль, вход второго устройства того же аккаунта,
  общая история, закрытие и повторное открытие SQLite, rotation refresh token,
  запрет повторного refresh и выход со всех устройств;
- чужой аккаунт не читает историю и не останавливает чужую задачу; Stop блокирует
  последующие tool/model calls оставшегося worker, SSE заканчивается отменой,
  затем новый запрос получает отдельный действующий resource scope.

Worker второго сценария подготовлен тестом; это проверка настоящих auth,
storage, HTTP, resource scope и cancellation boundaries, без обращения к модели.
Запись истории первого сценария выполнена через настоящий SessionDB и затем
прочитана клиентом API. Проверки не являются E2E установленного приложения.

Повтор DOCX harness использует канонический ACK-маршрут
`POST /v1/device-files/{id}/received`: 12 настоящих loopback HTTP-запросов,
реальный AIAgent/tool loop, настоящий DOCX, SHA/size, flush/fsync/reopen,
OpenXML, изоляция owner/device, ACK и удаление RAM-передачи. Три SDK-ответа
подготовлены тестом; реальных provider/search calls нет. Первый частный receipt
с ACK на неканоническом `/v1/device-files/{id}` сохранён как superseded и не
используется как доказательство маршрута клиента. Bodyless ACK сам по себе
не удостоверяет запись на диск. Word и визуальная верстка не проверены.

Существующий C# offline-набор: сборка успешна, 31 проверка прошла. Покрыты
refresh/DPAPI, изоляция локальных папок аккаунта, Stop, сохранение до ACK,
отказ ACK для повреждённого файла и повтор после потерянного ACK без повторной
загрузки и дубликатов. Первый запуск с длинным тестовым TEMP упёрся в MAX_PATH;
тот же бинарный файл прошёл с коротким изолированным TEMP. Ограничение длины
пути клиента этим не исправлено. Обычное окно и production endpoint не запускались.

Дополнительный C# roundtrip использует настоящие `ApiClient` и `LocalStore`
с явным loopback endpoint и временным хранилищем. Сборка успешна; 6 сценариев,
35 проверок и 29 реальных HTTP-запросов прошли. Проверены register/login,
DPAPI roundtrip, общая home session, список и повторная загрузка истории,
изоляция двух владельцев, остановка активного запроса и получение настоящего
DOCX. Файл существует и повторно читается с ожидаемым SHA до отправки ACK;
временный `.part` уже переименован. Выполнены один download и один канонический
ACK; pending RAM очищен. SDK/model usage этого сервера подготовлены тестом,
реальных provider/search requests нет. Временное хранилище клиента удалено;
HOME/USERPROFILE сохранены. Это клиентские классы через настоящий HTTP,
а не проверка установленного UI, микрофона, динамика или Word.

## Python-проверки окончательного исходника

Полный доступный default-набор через `scripts/run_tests.sh -j 6`: 1269 файлов,
без пропусков и повторов. По распознанным summaries — 24 589 passed,
581 failed, 207 skipped, 1 error; exit 1. Для 48 запусков с ненулевым кодом
нет summary: их нельзя учитывать как ноль успешных или неуспешных tests.
У нескольких других файлов имеются passed summaries, но runner всё равно
отметил timeout. Wall-clock всего прогона — 52 147 с; отдельный summary
metered runtime показывает 13 passed за 49 610 с при лимите файла 600 с.
Эти длительности не используются как измерения производительности приложения.
Причины всех общих отказов не установлены; это не список 581 продуктового дефекта.

После этого выполнен целевой повтор 32 файлов через тот же canonical runner,
`-j 2`: **572 passed, 0 failed, 0 skipped, exit 0**. Включены оба новых файла,
working context, billing/ledger/metering, summary reasoning, provider wiring,
история, voice guards, search evidence и доставка документов. Источники Python
сверены SHA-256 до и после обоих прогонов и остались неизменными.
Результаты полного и целевого прогона не складываются.

Tokenizer regression до исправления: 3 failed, 1 passed при блокировке загрузки.
Новый окончательный файл: 20 passed, включая реальный проверенный cl100k cache.
Промежуточный узкий запуск с 92 passed завершился exit 1 из-за timeout импорта
OpenAI в другом файле; его не считаем чистым. Окончательное подтверждение —
указанный повтор 572 tests. Добавления в тесты не маскируют отсутствие живого
провайдера: клиентские и модельные доказательства учитываются отдельно.

## Открытые критерии альфы

| Критерий | Подтверждено | Что остаётся |
|---|---|---|
| Диалог и задержка | reasoning wire guards; локальная оценка без загрузки словаря | новая живая серия 20/20 после восстановления доступности inference, целевой p50/p95 |
| Поиск | snippets отделены от полного чтения; пустая выдача не доказывает чтение | отдельный доступный тестовый SearXNG и живой ответ с источниками |
| DOCX | генератор, HTTP/SHA/ACK/RAM; C# и физический Android save/reopen | открытие в Office и визуальная проверка; штатный UI обоих клиентов |
| Аккаунт и история | loopback auth/storage/restart/isolation; C# и физический Android protocol | свежая проверка штатного UI обоих клиентов |
| Stop и повтор | HTTP cancellation, блокировка оставшегося worker, новый scope | физическое прерывание голоса и подтверждение отсутствия фонового возобновления |
| Голос | существующий код сохранён | десять физических STT/LLM/TTS прогонов Android, микрофон/динамик/Stop; Windows отдельно |

Локальный SearXNG не обнаружен: нет настройки endpoint, подходящего listener,
Docker binary/service или подтверждённого WSL runtime. Исходный production
compose не является запущенным локальным сервисом. SearXNG возвращает search
snippets и не реализует extract; metered runtime не допускает непроверенную
цену другого reader. Новый reader и обход pricing не добавлены. Для 0.1
достаточен честный поиск со snippets и ссылками; полное чтение не обещается.

## Android на физическом телефоне

Отдельная debug APK собрана из task-owned копии исходников с applicationId
`com.troika.hermes_assistant.diagnostics`, отдельным названием, UID и локальным
состоянием. Endpoint — `http://127.0.0.1:18765` через временный USB reverse.
Namespace Kotlin сохранён; основной пакет `com.troika.hermes_assistant`
не заменён, его version/install/update metadata до и после совпали.

Подготовка изоляции выявила неполный Gradle cache и плавающие зависимости
Flutter integration_test. Только в копии SDK закреплены runner 1.3.0,
rules 1.2.0 и espresso-core 3.3.0. Кэш содержит и метаданные, и бинарные файлы;
копирования одних AAR/JAR оказалось недостаточно. Финальная сборка прошла
offline с отдельным снимком исходного cache, подключённым как
[read-only dependency cache Gradle](https://docs.gradle.org/current/userguide/dependency_caching.html).
Lock files и gc.properties в снимок не копировались. Исходные SDK/cache и
продуктовые исходники Android не изменены. Промежуточные ошибки сборки сохранены
в частных диагностических логах. Публичные библиотечные файлы проверялись по
checksum cache slot, включая допустимый ведущий ноль SHA-1.

На физическом Samsung SM-A225F выполнен Flutter integration test настоящих
`AccountService`, `TroikaApiService` и `FilesService`: **1 test passed, exit 0**.
Подтверждены регистрация и вход, восстановление локальной сессии, получение
потокового ответа, чтение истории, Stop и следующий запрос. Настоящий DOCX
36 643 байта сохранён в app-owned папке телефона, проверен SHA-256, повторно
прочитан и разобран как OpenXML ZIP; затем подтверждена пустая очередь доставки.
Сервер ACK получает штатным `/received` после локальной записи.

Результат runner относится к одному зарегистрированному тесту. Весь интервал
работы отдельного phone server содержит 47 HTTP-запросов, 8 scripted workers,
2 Stop, 2 DOCX и 2 ACK; это наблюдаемые серверные счётчики, а не обещание
единственного запуска или серия измерений производительности. Provider/search
requests — 0; pending RAM после завершения — 0.

После проверки остановлен только diagnostic package, временный reverse удалён,
прежняя настройка удержания экрана возвращена, локальный тестовый сервер закрыт.
Diagnostic APK и синтетическая локальная копия документа оставлены для проверки;
пользовательские данные основного клиента не очищались. Финальный APK после
Flutter test — 166 235 477 байт, SHA-256
`3f4d1e884e4c949fe82e44efb447a3077349ecc32898c41456f98197580e7fab`.

Scripted local server проверяет клиентский протокол; он не заменяет живые
STT/LLM/TTS и не доказывает задержку OpenRouter. Документ повторно прочитан
клиентом, но в отдельном Office-приложении и визуально не проверен. Штатный
пользовательский UI основного установленного приложения не принимался.
Troika 0.1 не считается принятой закрытой альфой до закрытия указанных критериев.
