## Задачи

1. Проверь web_search/extract/research от provider до sources UI. Подключи реальное чтение страниц в согласованных границах; snippets не называй прочитанной страницей. Источники, даты, ошибки, pagination и недоверенное содержимое должны сохраняться.
2. Раздели ответ/исследование/структурированные данные/файл: не создавай DOCX/PPTX по умолчанию. Не добавляй ещё генератор вместо исправления общего пути результата. Внешние действия/публикация имеют отдельный результат.
3. Проверь генерацию DOCX/PDF/PPTX: содержание, таблицы/изображения/формулы по необходимости, нейтральный профессиональный стиль, реальный render всех страниц/слайдов, открытие и версия. Нет заглушек вместо результата.
4. Реализуй поддерживаемый импорт и правки существующих Office-файлов, затем XLSX по согласованному плану. Новый файл вместо перезаписи оригинала; повреждённый input, unsupported features, размер и встроенные опасные элементы дают понятный отказ.
5. Доведи RAM-only handoff, TTL, hash, save-before-ACK, retry/idempotency, локальный индекс и открытие offline. Потеря ACK не должна пересоздавать результат; истёкший handoff не называется сохранённым файлом.
6. Уточни старые cloud artifacts и новые local files без автоматического удаления/миграции. Между устройствами передаётся явная версия, а не выдуманный общий серверный источник.
7. Проверь claims/receipts: успешный tool, source review, тесты, сохранение и фактическая внешняя отправка различаются. Ошибка/частичный результат не получают окончательное «сделано».
8. Согласуй troika_create_project с 01: в твоём patch сохраняются документовые права и корректная доставка; изменения shared routes оформить отдельным контрактом, не конкурирующим движком.
