# Telegram-магазин и поддержка Тройки

Магазин: [@troika03_shop_bot](https://t.me/troika03_shop_bot).
Поддержка: [@troika03_support_bot](https://t.me/troika03_support_bot).

Отдельный бот для оператора не нужен: владелец использует кнопку
«Входящие оператора» или `/admin` в боте поддержки. При переключении кнопок
предыдущее меню удаляется, остаётся новый экран. Сообщения клиента, уведомления
об обращении и ответы оператора сохраняются.

## Меню магазина

| Кнопка / команда | Что показывает |
| --- | --- |
| `/start`, «🏠 Главное меню» | Баннер, коротко о Тройке, главное меню |
| «💎 Тарифы», `/tariffs` | Сводка тарифов и карточка каждого тарифа |
| «📲 Скачать», `/download` | Ссылки `/download/#android` и `/download/#windows` |
| «🔗 Подключить устройство», `/device` | Три шага: скачать, войти в тот же аккаунт, разрешить микрофон |
| «💳 Оплата», `/pay` | Честный статус оплаты, условия, уведомление о старте продаж |
| «✨ О Тройке» | Что умеет Тройка и ограничения beta |
| «🛟 Помощь», `/support` | Переход в бот поддержки, справка и кабинет на сайте |
| `/paysupport` | Поддержка с заранее выбранной темой «Тариф и оплата» |

## Источник тарифов

Названия, цены, объём AI-токенов, лимиты функций, число активных задач и
докупка берутся только из `troika_product/subscription_policy.py` (`PLANS`,
`TOP_UP_*`). В `content.py` хранятся лишь иконки и короткие подписи тарифов.
Новая цена в политике сразу меняет текст бота; дублировать её в копирайте нельзя.
В production каталог ботов монтируется поверх образа, а `subscription_policy.py`
берётся из `TROIKA_TELEGRAM_IMAGE`; после изменения тарифов нужен новый образ.

## Оформление

Кнопки используют поле `style` у `InlineKeyboardButton` (Bot API 9.4,
февраль 2026): `primary` — синяя главная кнопка, `success` — зелёная
(скачать, вопрос решён, закрыть обращение), `danger` — красная (удаление данных).
Старые клиенты Telegram поле игнорируют и рисуют обычную кнопку. Иконки — обычные
эмодзи в тексте; `icon_custom_emoji_id` не используется, потому что требует
Telegram Premium у владельца бота. Тексты — HTML (`<b>`, `<i>`, `<code>`),
пользовательский текст экранируется. Тесты проверяют лимиты Telegram: подпись
фото до 1024 символов, текст до 4096, `callback_data` до 64 байт.

## Поддержка

Главное меню: «✍️ Написать оператору», «💡 Частые вопросы», «📋 Мои обращения»,
статус сервиса и переход в магазин. Темы: установка и вход, голос, тариф и
оплата, ошибка приложения, другой вопрос. Deep links
`t.me/<support>?start=payment|install|voice|bug` сразу открывают тему; другие
значения ведут в главное меню.

Статусы обращения: 🟡 ждёт оператора (последним писал клиент), 🔵 есть ответ,
✅ закрыто. Карточка обращения показывает последние четыре сообщения и кнопки
«✍️ Дописать» и «✅ Вопрос решён». Клиент закрывает только своё обращение;
оператор получает уведомление. Входящие оператора показывают число открытых и
ожидающих обращений, кнопки «✍️ №N», «✅ Закрыть» и «🔄 Обновить».

## Состояние оплаты

По решению владельца от 16 октября приём оплаты выключен. Рублёвые цены
тарифов из политики подписок — ориентиры сервиса, а не цены покупки в Telegram.
Вместо списания магазин предлагает отдельное согласие на уведомление о старте.
`/stop` отзывает согласие. Автоматическая рассылка не запускается.

Счета, рекуррентные списания и выдача подписки отсутствуют в этом релизе.
Любой `pre_checkout_query` получает отказ. `payments_enabled: true` блокирует
запуск, поэтому изменение одного флага не открывает незавершённую продажу.

До включения продаж нужно утвердить цены в Stars, реализовать привязку
проверенного аккаунта, оплату XTR, идемпотентную выдачу периода в общем ledger,
возвраты и сверку. Рублёвые тарифы и ЮKassa не подменяют Stars внутри Telegram.
Правила: [цифровые товары Telegram](https://core.telegram.org/bots/payments-stars).

## Запуск

Сервис использует существующие `aiohttp`, `cryptography`, `PyYAML` и
`python-dotenv`. AI-модели, gateway tools и пользовательские сессии ему не нужны.

1. Скопируйте `deploy/production/telegram.example.yaml` вне checkout. Укажите
   `operator_ids` и `operator_chat_id`. Права оператора проверяются по числовому
   Telegram ID и назначенному чату, а не по username.
2. Сохраните два BotFather token и отдельный Fernet key в приватном `.env`.
   Пример имён переменных: `deploy/production/telegram.env.example`.
   Секреты не должны попадать в Git или логи. Каталог — 0700, файлы — 0600.
3. По умолчанию конфигурация и секреты читаются из
   `get_hermes_home()/troika-telegram/`. Аргументы `--config` и `--secrets`
   позволяют явно выбрать другие приватные файлы.
4. Запустите `python -m troika_product.telegram_commerce check` для проверки
   токенов и username. `profile` устанавливает имена, описания, команды и аватары.
   `run` запускает оба бота. Существующий webhook не удаляется автоматически.

В production используется профиль `telegram` в основном
`deploy/production/compose.yaml`, без второго production manifest.
Сервис принимает только исходящие соединения с Telegram и не публикует порт.
Он использует отдельный каталог `/srv/troika/telegram`, без доступа к данным API.
В `TROIKA_TELEGRAM_IMAGE` задайте проверенный runtime image; в
`TROIKA_TELEGRAM_SOURCE` — абсолютный каталог опубликованного пакета ботов.
Эти две несекретные переменные можно сохранить в действующем
`deploy/production/resource-images.env`, сохранив остальные image tags.
В `/srv/troika/telegram/config.yaml` размещается приватная конфигурация,
в `.env` — секреты. Запускайте только сервис `telegram` с `--no-deps`.

## Работа оператора

Владелец сначала нажимает «Начать» в поддержке: Telegram разрешает ботам
писать только после первого обращения пользователя. Входящие доступны через
`/admin`. Откройте обращение кнопкой «Ответить» и ответьте на сообщение бота.
Связь ответа и обращения определяется сохранённым сервером message ID.
Кнопка «Закрыть» завершает обращение и сообщает клиенту.

При необходимости можно назначить закрытую группу операторов. Недостаточно
добавить бота в группу: отправитель ответа должен быть в `operator_ids`,
а группа должна совпасть с `operator_chat_id`. Privacy mode можно сохранить:
ответы на сообщения бота доставляются без чтения всех сообщений группы.

Пользователь может иметь до трёх открытых обращений. Доступны `/tickets`,
`/paysupport`, `/privacy`, `/delete_me` и `/cancel`. Текст до 2 500 символов;
вложения в этом релизе не принимаются. Чужие обращения недоступны даже при
ручной подмене номера в callback.

## Хранение и доставка

Отдельная SQLite-база хранит обращения, согласие на уведомление, offsets и
очередь отправки. Текст сообщений и payload очереди зашифрованы Fernet;
Telegram ID и технические поля доступны только в приватном каталоге.
Токены в БД не записываются. Логи не содержат тексты, ключи и HTTP URL ботов.

Обработка update и постановка ответа в очередь проходят одной транзакцией.
Повтор update не создаёт повторное обращение. Временный сбой сети приводит к
повтору отправки; блокировка бота одним пользователем не останавливает остальных.
Telegram `sendMessage` не имеет idempotency key: при аварии после принятия
сообщения Telegram и до записи подтверждения возможен повтор одного сообщения.
Неизвестная доставка не объявляется подтверждённой.

`/delete_me` требует нажатия кнопки удаления, удаляет данные только этого
пользователя и его ожидающие отправки. Копии сообщений в Telegram и на устройстве
оператора не удаляются этой командой; бот прямо сообщает об этом.

Автоматического обещания срока ответа, круглосуточной работы оператора,
полноценного billing и готовности всего Troika 1.0 нет.

## Оформление

Два баннера созданы встроенным imagegen; исходные prompts сохранены в
`troika_product/telegram_commerce/assets/prompts.json`. Аватары получены из
векторных оригиналов `brand/troika/app`. Бот использует готовые JPEG из своего
пакета; независимость от локальной папки генератора проверяется при публикации.
Скрипт `scripts/build_telegram_assets.cjs` готовит размеры и сжатие из двух
одобренных изображений. Тарифы остаются текстом Telegram, поэтому их можно
обновить без изменения изображения.

## Проверки

Целевые проверки: `scripts/run_tests.sh -j 2
tests/troika_product/test_telegram_commerce.py -- -q`. Они проверяют ownership,
право оператора, экранирование HTML, повторы, перезапуск, отключённую оплату,
очередь отправки, удаление, связь цен с политикой подписок, лимиты экранов,
статусы обращений и закрытие обращения клиентом. Живая проверка зарегистрированных ботов и Docker
фиксируется отдельно в аудите; unit-тесты её не заменяют.
