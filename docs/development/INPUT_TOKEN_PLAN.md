# Сокращение входного контекста Тройки

Обновлено 15 октября 2026 года.

## Что создаёт расход

Модель получает не только реплику пользователя, но и личность, инструкции,
текущий личный контекст, историю и схемы инструментов. Каждый шаг работы с
инструментом требует нового обращения с накопленным контекстом. Поэтому три
вызова с входом по 10 тысяч токенов дают около 30 тысяч входных токенов за задачу.
Это не означает, что последнее сообщение пользователя содержало столько текста.

В обычном запросе product runtime уже не загружает операторские AGENTS.md,
общую память профиля или полный список навыков. Две постоянные схемы каталога
заменили полный allowlist. История и account memory остаются пользовательскими.
На действующем сервере проверены именно `troika_tool_search` и
`troika_tool_call`: других схем в начальном наборе нет. Автоматический список
навыков не включён; зарегистрированных `pre_llm_call` обработчиков, способных
подмешать контекст, нет. Каталог для интерфейса содержит больше подробностей,
но его HTTP-ответ не добавляется к модельному запросу сам по себе.

## Проверенное сокращение

Локальный замер использует `cl100k_base`, режим доставки на устройство и исходники
продукта. Он не является точным счётчиком провайдера и не включает личную память,
историю, clock context, служебное обрамление сообщений или дополнительные вызовы.

До изменения личность вместе с инструкциями занимала 3 303 токена. Из них 2 079
приходилось на исходную личность, 669 — на полный раздел разработки. Отдельная
сериализация двух схем каталога без пробелов занимает 234 токена; прежний замер
299 использовал другое обрамление. Приветствие «Привет» занимает 3 токена.

Полные инструкции разработки перенесены из постоянной личности в результат
`troika_tool_search` для capability `development`. Этот результат уже содержал
тот же раздел, поэтому его прежняя постоянная копия была избыточной. Короткая
ссылка на загрузку capability сохраняется. После изменения блок занимает 2 674 токена;
экономия 629 токенов на каждом обычном обращении без разработки. Личность, память, история, правила
подтверждения и проверки выполнения не сокращаются. Версия личности меняется,
чтобы следующий запрос обновил старый кешированный system prompt.
Изменение включено на production 14 октября. Начальный набор по-прежнему
содержит две схемы; исходная история и данные аккаунтов не изменялись.

## Компактный рабочий контекст

Владелец одобрил реализацию 14 октября. Полная личность остаётся в
`docker/SOUL.md` и package fallback; сохранённые сообщения, проекты и память
не переписываются. Общий блок теперь занимает 1 046 `cl100k_base` токенов
в режиме доставки на устройство вместо 2 674: сокращение примерно 61%.
Это размер личности с общими инструкциями, не всего запроса провайдеру.

Компактное ядро сохраняет имя, характер, русский язык по умолчанию, тон,
честность, приватность, подтверждения и маршрутизацию. Рецепты напоминаний,
файлов, документов, разработки и поиска приходят с нужной capability.
Начальный набор модели по-прежнему содержит две схемы каталога. Контроль
владельца, согласий, параметров, Stop и расходов остаётся в программе.

Память выбирается по текущему вопросу, вместе с основными предпочтениями и
именем. Для приветствия не отправляются все несвязанные записи и проекты.
Полный список и исходные записи доступны через инструменты помощника;
`troika_context` добавляет поиск и постраничное чтение исходной истории и
полной личности. Доступ проверяет активный account/device token. После Stop,
revoke или смены владельца чтение закрывается.

При входе больше 10 000 оценочных токенов runtime пробует заменить старую
часть истории коротким индексом точных выдержек. Индекс содержит ссылки на
номера сообщений, признаки неполной выдержки и число пропущенных записей.
Обычно последние четыре пользовательских хода со связанными ответами и
инструментами сохраняются целиком. Большие завершённые ходы могут сократить
этот хвост до двух или одного; текущий ход всегда остаётся целиком. Индекс
дополнительно содержит точные короткие выдержки последних четырёх завершённых
ответов, чтобы не скрывать уже полученный вывод. Изменение применяется только при экономии не менее 15%.
Индекс прямо предупреждает: это неполное представление; перед действием по
старым требованиям нужно прочитать оригинал. Все исходные реплики остаются
в account-scoped базе и доступны текущей задаче. Прежний лимит 20 сообщений
и автоматическая перезапись истории compressor отключены для этого режима.

Индекс собирается обычным кодом: дополнительных модельных вызовов для его
создания нет. Ограниченный RAM-кеш принадлежит владельцу, живёт до 15 минут
и переиспользуется только при совпадении полного исходного префикса. Исправление
старой реплики исключает reuse; удаление аккаунта очищает его записи кеша.
Кеш не является долговременной заменой истории.

SDK получает производную копию; сохранение продолжает использовать оригиналы.
Учёт резервирует именно отправляемый запрос. В аудит попадают только числа:
оценочные токены сообщений до/после, построение индекса и попадания в кеш. Текст сообщений,
память, файлы и ключи в эти диагностические записи не попадают.

## Активация и ограничения

Операторский флаг — `platforms.api_server.extra.product_compact_context_enabled`.
Default false сохраняет прежнее поведение. Изменение версии личности обновляет
старый system prompt один раз; обычные повторы сохраняют стабильный префикс.
Серверную активацию и реальные проверки фиксирует
[аудит компактного контекста](../audit/COMPACT_CONTEXT_2026_10_14.md).

Сокращение контекста не гарантирует тождественное качество каждого ответа:
модель должна загрузить отсутствующую старую деталь. Для задачи, требующей
весь материал, его чтение и расход необходимы. Дополнительное чтение источника
добавляет шаги модели; поэтому сравнивается полный расход задачи, а не только
один prompt. Multimodal history и async SDK payload пока передаются без
исторического индекса. При отключённом помощнике история также передаётся
целиком: недоступный инструмент чтения не должен скрывать оригиналы. Длинный
текущий ход сам по себе не обрезается.

Хранение текста в файле, базе или preset не делает его известным внешней
модели бесплатно. Провайдерский prompt cache также не отменяет логические
входные токены. Корпоративный Free по согласованному правилу списывает полный
prompt + completion, включая cache; личный API не списывает ресурс подписки
за модель. Для платных моделей сохраняются операторские коэффициенты.
Оплата и почта остаются отложенными отдельными задачами.
