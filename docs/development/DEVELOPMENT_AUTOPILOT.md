# Автопилот во вкладке «Разработка»

Реализованный объём от 14 октября 2026 года по запросу владельца.
Разработка доступна только в Pro. Общий предел Pro — пять активных Run;
до четырёх из них могут быть проектами разработки. Пятый слот остаётся для
разговора. Free/Plus сохраняют обычные документы по своей тарифной политике.

## Работа пользователя

Пользователь описывает сайт, приложение, презентацию или документ обычными
словами. Образец дизайна необязателен. Тройка сама составляет план, выбирает
визуальное направление, создаёт результат, проводит независимое ревью
исходников или содержания и выполняет до трёх циклов исправления.

Проект выполняется на сервере через существующий `/v1/runs`, с собственными
session_id, run_id и Stop. Android и WPF наблюдают за ним из контроллера уровня
приложения. Уход со вкладки и остановка разговора не отменяют проект.
Остановить проект можно в его карточке. Завершённый результат скачивается на
устройство: ZIP с исходниками либо настоящий PPTX/DOCX.

## Команда и ограничения

Один проект — один родительский Run. Coordinator создаёт роли Planner,
Designer, Developer/Author и Verifier. Работают максимум три specialist workers;
workers не создают вложенные команды. Planner задаёт граф зависимостей и
контракты. Общие модули завершаются раньше зависимых экранов и тестов.
Независимые файлы создаются параллельно; один writer владеет одним файлом.

Designer получает задачу и план, выбирает аудиторию, типографику, палитру,
композицию, поведение и критерии ревью. Спецификация передаётся каждому writer
и verifier и входит в ZIP как DESIGN.md. При ревью существующего проекта
спецификация обновляется даже без недостающих файлов. Planner помечает
существующие файлы write_required, если задача требует их изменения.

Verifier получает всю текущую версию, без скрытых рассуждений автора.
Блокирующее замечание требует конкретного сценария и доказательства из
исходников. Неполный ответ, неверный JSON, циклический граф, отсутствие README
или настоящих тестов не объявляются успехом. До 40 файлов, 160 KB контекста,
64 API-вызовов и 15 минут на проект; бюджет общий и проверяется атомарно.
Verifier выбирает номер существующей строки, а runtime подставляет точное
доказательство из текущего файла. Синтаксическая диагностика и обнаруженное
копирование JavaScript-функций в тест без импорта исходников не могут быть
отменены положительным ревью модели. Этот узкий detector не доказывает
полноту тестов и не заменяет реальный запуск.

Презентации и документы проходят отдельный авторский этап и ревью содержания.
Фиксированные доверенные renderer собирают типизированные данные. Параграфы
и списки сохраняются. Документы имеют сдержанный профессиональный стиль:
белый фон, тёмный текст, обычная иерархия. Модель не выполняет скрипт генератора
и не получает shell облачного сервера.

## API и изоляция

`POST /v1/runs` с workflow=development, input, idempotency_key, free_only=true
и необязательным files запускает фон. `GET /v1/development/projects` возвращает
доступ и snapshot проектов только текущего владельца и устройства.
Существующие GET Run, SSE и Stop используют тот же Run transport.
Старый сервер без snapshot endpoint блокируется клиентским handshake;
запрос не переключается незаметно в обычный чат.

Pro проверяется на сервере перед квотой, созданием Run и вызовом модели.
Legacy project tool тоже требует серверный Pro; скрытие кнопки недостаточно.
Admission учитывает все Run аккаунта и общий предел сервера. При занятых
слотах API возвращает понятный отказ 429; постоянной очереди задач пока нет.
Завершённая передача файла не занимает активный слот разговора.

Одинаковый idempotency key и содержимое возвращают прежний Run; изменённое
содержимое с тем же ключом отклоняется. Клиенты сохраняют ключ неизвестного
запуска в памяти для повтора после обрыва сети. При смене аккаунта старые
snapshots, результаты и голосовая очередь очищаются. Revoke/downgrade/Stop
проверяются между вызовами и перед передачей результата. Уже отправленный
API-вызов может завершиться; отмена не выдаёт его результат пользователю.

## Бесплатный API

Новый автопилот требует настроенный бесплатный маршрут OpenRouter и
проверяет актуальный официальный каталог через доверенный endpoint. Для
выбранных моделей цены prompt/completion и все опубликованные дополнительные
цены должны быть нулевыми. Требуются строгий JSON, текстовый ответ и контекст
от 128 000 токенов. Модели с описанной поддержкой кода получают приоритет.
Список из максимум трёх проверенных free ID кэшируется на пять минут.
Неверный resolver, недоступный каталог или отсутствие подходящей модели
останавливают запуск. SDK retries отключены; запрос явно выбирает первую подходящую модель.
Скрытого provider routing и автоматического fallback нет. Общая auxiliary
fallback цепочка не вызывается.
Скрытое рассуждение отключено, чтобы сохранить лимит для полного результата.
Источник: [официальный каталог OpenRouter](https://openrouter.ai/api/v1/models).
Доступность и качество бесплатных моделей различаются.

Корпоративные вызовы проходят SDK guard и месячный ledger. Только после
проверки нулевых цен task-local catalogue получает выбранные free ID с
действующей политикой prompt + completion. Поэтому неизвестный платный маршрут
не становится бесплатным по суффиксу. Личный API используется явно; provider
должен быть OpenRouter, а конкретная модель должна входить в проверенный список.
openrouter/free как личный router и платные модели блокируются, чтобы личная
настройка не переопределяла проверенный выбор. Автоматического возврата к
корпоративному ключу нет.

Одновременно отправляются максимум два free API-запроса на серверный процесс.
При 429 допускаются два повтора с ожиданием 15/30 секунд в общем бюджете,
с видимым статусом. После исчерпания повторов проект сообщает отказ;
платный вызов не выполняется. Все specialists наследуют ContextVars одного
родительского ресурса; новый worker не получает отдельный ledger.
Существующие development/development_review настройки старого API-tool
сохраняются отдельно и не используются новым автопилотом.

## Голосовые отчёты

Тройка называет проект и сообщает важные этапы, результат и ошибку; каждый записанный файл
не озвучивается. Во время записи, ответа или approval отчёт ждёт.
При готовности старые этапы уступают место итоговому сообщению.
Озвученный отчёт не повторяется; прочитанные идентификаторы и переключатель
сохраняются отдельно для аккаунта. Отключение голосовых отчётов прекращает
текущее объявление. Пользовательский разговор имеет приоритет.
Текст остаётся в карточке при отказе озвучивания.

Android использует действующий TTS, WPF — действующий speech endpoint и player.
Наблюдение продолжается вне вкладки «Разработка», пока приложение открыто.
Голос и push при полностью закрытом приложении в этот объём не входят.

## Честные границы проверки и восстановления

Ревью модели не доказывает исполнение тестов или качество настоящего рендера.
Отчёт содержит execution=not_run и visual_review=not_checked. Локальные тесты
остаются отдельным действием с прежними разрешениями. Generated HTML/JS не
запускается автоматически на облачном host. Изолированный preview и отдельный
Visual verifier пока не подключены; качество дизайна требует проверки результата.

Исходники и server Run state находятся в RAM. Готовый файл передаётся с TTL
600 секунд; клиент проверяет SHA-256, сохраняет файл и подтверждает получение.
Постоянной облачной копии новых файлов нет. Если приложение закрыто дольше TTL,
временная передача может истечь. Если сервер перезапущен, автоматическое
продолжение исходников не гарантируется. Нужно повторно передать локальную
версию. Сохранённые checkpoints, пауза/продолжение и уточнение действующего
Run остаются следующим этапом; согласование постоянного хранения отсутствует.
Исчерпание месячного ресурса или подтверждённого бюджета завершает задачу
понятным отказом. Продолжение через согласование бюджета в карточке проекта
пока не реализовано.

Сборка, unit-тесты, живой free API-пример и установленный E2E фиксируются
отдельно. Исходный код и собранный клиент не означают production deployment.
