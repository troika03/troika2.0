# Политика хранения, экспорта и удаления данных Тройки

**Версия:** 2026-09-14
**Статус:** обязательная политика продукта; автоматическое применение сроков и
production backup/object-storage lifecycle ещё не реализованы.

## 1. Область действия

Политика относится к данным подписочного продукта Тройка: аккаунтам,
устройствам, диалогам, проектам, задачам, заметкам, inbox, документам,
местоположению, vision metadata, журналу безопасности и usage ledger.

Пользователь может удалить отдельные доступные сущности раньше срока. Удаление
аккаунта отзывает все device tokens сразу и удаляет данные из текущих основных
хранилищ. Срок хранения задаёт верхнюю границу, а не минимальное время хранения.

## 2. Утверждённые сроки

| Категория | Верхняя граница хранения в основном хранилище | Начало отсчёта |
|---|---:|---|
| Профиль активного аккаунта и действующие устройства | Пока существует аккаунт | Создание аккаунта |
| Отозванные device/token metadata без token value и digest | 90 дней | Отзыв |
| Диалоги и сообщения | 365 дней | Последняя активность диалога |
| Документы и другие artifacts | 365 дней | Создание файла; будущая версия сможет продлевать срок при явном действии пользователя |
| Проекты, задачи и заметки | 730 дней | Последнее изменение проекта или задачи; для заметки — создание |
| Прочитанные и доставленные inbox-сообщения | 90 дней | Доставка |
| Недоставленные напоминания и follow-up | Не позднее 365 дней после создания | Создание |
| Точный transient device context | 24 часа | Последнее получение от устройства |
| Сохранённые location fingerprints | 365 дней | Последнее обновление места |
| Raw screen/camera media | 0 дней | Не сохраняется |
| Vision session metadata без кадра и OCR | 30 дней | Завершение или истечение сессии |
| Vision summaries | Отдельного хранилища нет; если summary попал в диалог, действует срок диалога 365 дней | Последняя активность диалога |
| Privacy-safe audit events | 400 дней | Событие |
| Daily usage ledger | 400 дней | День учёта |
| Текущее entitlement | Пока существует аккаунт | Создание или изменение entitlement |
| Сформированный ZIP-экспорт | 0 дней на сервере | Архив создаётся в памяти ответа и серверную копию не образует |
| Tombstone незавершённого удаления аккаунта | До успешного завершения очистки | Запрос удаления |

Автоматический retention worker пока отсутствует. Поэтому сроки в таблице уже
определяют требуемое поведение, но ещё не подтверждают фактическую фоновую
очистку. До запуска нужно добавить owner-scoped cleanup job, метрики, dry-run и
тест времени для каждой категории.

## 3. Экспорт данных

`GET /v1/account/export` принимает только действующий product bearer token.
В запросе нет `user_id`: сервер получает владельца из токена и повторно
проверяет активность token, device и account внутри транзакции.

Ответ — ZIP с `troika-data.json` и исходными bytes всех artifacts владельца.
JSON включает профиль, устройства, безопасные token metadata, сессии, видимые
сообщения, проекты, задачи, заметки, inbox, настройки, usage, audit metadata,
location context/fingerprints, vision metadata и artifact metadata.

Экспорт не содержит bearer token values/digests, vision nonce digests,
физические пути и имена object storage, server system prompts и приватные
reasoning-поля модели. Эти поля не нужны для переносимости и могут раскрыть
учётные данные или внутренние механизмы сервера.

## 4. Удаление из основного и object storage

Текущее beta-хранилище artifacts использует отдельный opaque-каталог на
пользователя. Подтверждённое удаление аккаунта удаляет этот каталог до удаления
metadata из product SQLite. Эта локальная очистка реализована и покрыта тестом.

Production object storage ещё не подключён. Для него обязательна следующая
политика:

1. Каждый объект и каждая версия объекта принадлежат одному `user_id`; общий
   префикс без owner metadata запрещён.
2. Удаление пользователя ставит durable deletion request вне удаляемого
   пользовательского набора, блокирует чтение и удаляет текущие объекты,
   прошлые версии, multipart uploads и реплики.
3. Delete marker без lifecycle purge не считается удалением. Проверка должна
   подтвердить отсутствие bytes во всех регионах и версиях.
4. Неудача оставляет запрос в retryable состоянии и не возвращает аккаунту
   доступ.
5. Метрика и audit фиксируют только owner ID/digest, количество объектов,
   время и результат. Имена и содержимое файлов в операторский журнал не
   попадают.

Эта object-storage очистка не реализована и не проверена. До интеграционного
теста с реальным выбранным storage запускать production с artifacts нельзя.

## 5. Резервные копии

Production backup pipeline пока отсутствует. Избирательное удаление одного
пользователя из резервной копии не реализовано и не проверено.

Целевая политика:

- ежедневные зашифрованные backup с ротацией не более 35 дней;
- backup доступны только отдельной recovery-роли и не используются как
  обычное хранилище;
- durable deletion ledger хранится отдельно от восстанавливаемого набора и
  живёт не меньше максимального срока backup;
- после восстановления и до открытия трафика restore scrubber повторно
  применяет все deletion requests и проверяет object storage;
- disaster-recovery rehearsal доказывает, что удалённый аккаунт не становится
  доступным после восстановления;
- по истечении 35 дней должна существовать проверяемая инвентаризация,
  подтверждающая удаление всех backup, которые могли содержать данные.

Пока pipeline, deletion ledger, restore scrubber и rehearsal не готовы,
нельзя утверждать, что удаление данных из резервных копий работает. Это
отдельный launch gate.

## 6. Проверки перед запуском

- Тест экспорта создаёт данные двух пользователей во всех основных типах
  хранилищ и доказывает отсутствие ID, текста, location и artifact bytes
  второго пользователя в архиве первого.
- Retention worker проверяется с управляемым временем и не удаляет свежие или
  чужие данные.
- Object storage проверяется с versioning, незавершённым multipart upload и
  отказом одной реплики.
- Disaster recovery восстанавливает backup, повторно применяет deletion ledger
  и доказывает недоступность удалённого аккаунта до открытия трафика.
