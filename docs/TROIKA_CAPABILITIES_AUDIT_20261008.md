# Каталог возможностей и загрузка инструментов по необходимости

Решение владельца от 8 октября 2026: добавить страницу плагинов, навыков и
инструментов и уменьшить входной контекст без обрезания истории, памяти и
личности Тройки.

В Android: «Профиль» — «Возможности». В новом ПК-клиенте: «Возможности» —
«Плагины, навыки и инструменты». Каталог показывает встроенные возможности,
инструкции для их применения и доступность инструментов. Это управление
проверенными возможностями продукта; установка произвольного стороннего
кода через страницу не реализована.

## Изменение runtime

Hosted agent получает две постоянные схемы: `troika_tool_search` и
`troika_tool_call`. Поиск возвращает исходные подробные схемы выбранной
возможности как новое сообщение инструмента. Вызов проверяет исходную JSON
схему, доступность, активную сессию и настройку аккаунта, затем использует
существующий dispatcher. Он сохраняет проверки владельца, согласия
устройства и подтверждения действий. Обычный разговор не требует discovery.

Переключатели по умолчанию включены. `GET/PATCH /v1/account/capabilities`
определяет владельца по серверному token; клиент не передаёт owner ID.
Изменения объединяются атомарно в SQLite и относятся к аккаунту на всех
устройствах. Отключение действует для следующих вызовов, включая схемы,
оставшиеся в истории. Настройки входят в export и account deletion.
Ошибка сохранения оставляет последнее подтверждённое состояние в обоих UI.

Маршрутизация сохраняет названия выполняемых действий, ссылки источников,
обёртку недоверенных веб-данных, completion receipts и передачу готовых
файлов на устройство. Поиск схемы и ошибочный вызов не доказывают выполнение.
Screen snapshot по-прежнему требует обоих серверных beta flags.

Проверка полного разрешённого набора обнаружила расширение старого `safe`
через registry: `phone_create_image`, `image_hf_flux`, `phone_create_video`
используют общий legacy phone bridge и не являются owner-scoped product
интеграциями. Они остаются в upstream коде, но закрыты в ordinary product.
Обычные изображения и безопасное создание ссылки сохранены. Product
toolset перечисляет проверенные media tools явно; новые registry plugins
не получают доступ автоматически. Gateway toolset отключён по умолчанию
в операторских CLI/platform settings и выбирается явно product API.

## Замер и пределы

Локальный подсчёт сериализованных схем через `cl100k_base`: полный
проверенный набор без opt-in screen — 4 377 токенов; две схемы gateway —
299. Снижение около 93%. Системная личность, история, память, результаты
инструментов и provider-specific framing в этот замер не входят.

Подробные схемы добавляются при реальной задаче и остаются в её истории.
Discovery добавляет вызов модели. Для сложной задачи суммарные входные
токены и задержка могут увеличиться; результат замера не обещает снижение
общей стоимости каждого запроса на 93%. Prompt caching может уменьшить
оплачиваемую часть повторного контекста, но не сам счётчик input tokens.

## Проверки

Новые Python tests проверяют разделение аккаунтов, объединение изменений,
отзыв token, запрет отключённого/произвольного инструмента, валидацию
аргументов, стабильность начальных схем, сохранение sources/receipts,
export/delete и HTTP contract. Flutter tests проверяют server snapshot,
ошибки refresh/save/load, переключение вкладок и узкий экран с текстом 150%.
Светлая и тёмная темы Flutter и WPF просмотрены на синтетическом каталоге.
Чистый набор изменений экспортирован отдельно, без WIP других задач.

Результаты:

- Python для чистого набора: 232 passed в 17 файлах. Первые два resource
  timeout при импорте/дисковой нагрузке закрыты последовательным повтором:
  26 passed; остальные 206 passed уже в первом запуске.
- Flutter для чистого набора: 81 passed, 2 skips; analyze — 0 errors,
  0 warnings, 38 info. В общем рабочем checkout с WIP: 98 passed, 2 skips;
  analyze — 0 errors/warnings, 31 info. Новая страница прошла 7 tests.
- WPF чистого набора: успешная сборка и 25 существующих tests. Дополнительно
  3 проверки каталога: auth/snapshot/PATCH, ошибка сохранения, malformed
  response. Эти проверки подключены к `troika-desktop/build.ps1 -Test`.
- Android release APK и исторический Flutter Windows release собраны в
  общем рабочем checkout; это не отдельные release artifacts только данного
  commit. APK имеет размер 109,2 MB. Новый WPF UI отдельно собран из чистого
  набора. Ни один из этих клиентов в рамках задачи не установлен.
- Общий default Python набор охвачен в 1 240 файлах за основной и
  восстановленные прогоны. Сохранённые счётчики: 24 026 passed, 398 failed;
  81 файл завершился без распознанного счётчика tests при ошибке импорта или
  timeout. Общий baseline не зелёный. Новая функция и связанные product
  regressions проверены отдельным успешным набором. Ошибка implicit gateway
  toolset в старом API исправлена; соответствующие 12 tests passed.

При проверках на C: не оставалось свободного места. Временные файлы и копия
кеша Gradle использовали D:. Release повтор завершился успешно. Изменения
разработки, напоминаний, сайта и native Kotlin из других сессий не входят
в данный commit. В диагностике сохранялись только синтетические данные,
счётчики и служебные логи; prompts и пользовательские данные не добавлены в Git.
Автоматическая проверка заблокировала удаление временных папок. Копия кеша
`_logs/capabilities-gradle-home` остаётся локально; `_logs/` исключён также из
Docker build context. Оригинальный кеш и пользовательские файлы не удалены.

Проверки установленного клиента с обновлённым production API и фактический
provider usage ещё не выполнены. Production deployment, APK установка и
замена установленного ПК-клиента не входят в этот commit. Для включения
функции сначала требуется обновить API, затем клиент.
