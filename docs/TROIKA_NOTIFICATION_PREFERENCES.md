# Личные настройки уведомлений

Актуализировано 2026-10-05. Настройки, quiet hours, owner-scoped event engine,
in-app inbox и Android UI реализованы. Android получает reminder snapshot
и ставит локальные AlarmManager notifications при необходимых permissions.
Этот API только управляет настройками; доставку выполняют отдельные компоненты.
FCM/push и доставка на несинхронизированный телефон пока не реализованы.
Текущие проверки: [аудит функций](TROIKA_FUNCTIONAL_AUDIT.md).

## API

В product mode доступны два маршрута с индивидуальным device bearer token:

- `GET /v1/notification-preferences` возвращает текущие настройки аккаунта.
- `PUT /v1/notification-preferences` целиком заменяет настройки аккаунта.

Владельца сервер определяет из действующего токена. Поля `user_id`, `device_id`
и любые другие неизвестные поля отклоняются. Настройки общие для устройств
одного аккаунта и недоступны другому аккаунту. Legacy shared key не даёт доступ
к этому API. Успешные ответы имеют `Cache-Control: no-store`.

Начальное состояние, которое также является полным телом PUT:

```json
{
  "reminders_enabled": false,
  "proactive_enabled": false,
  "quiet_hours_enabled": false,
  "timezone": "UTC",
  "quiet_start": "22:00",
  "quiet_end": "08:00"
}
```

Все шесть полей обязательны при PUT. Строки `"true"`/`"false"`, числа вместо
boolean, неизвестные IANA time zones и неверное время отклоняются с `400`.
Равные начало и конец также отклоняются: они неоднозначны между отсутствием
тихих часов и запретом на весь день. Для полного отключения пользователь
выключает соответствующие категории уведомлений.

UTC — нейтральное исходное значение. Будущий интерфейс должен дать пользователю
выбрать часовой пояс, а не использовать часовой пояс сервера. Настройки
напоминаний и инициативных сообщений независимы и изначально выключены.

## Хранение и аудит

Таблица `troika_notification_preferences` находится в той же profile-aware
SQLite-базе, что users/devices/tokens. При открытии существующего реестра она
создаётся автоматически, не изменяя действующие токены и сессии.

Замена настроек и событие `notifications.preferences_updated` фиксируются в
одной транзакции. Если аудит недоступен, изменение откатывается. Аудит содержит
user/device ID и три boolean-переключателя; часовой пояс, расписание, текст
сообщений и токен в него не записываются. Перед сохранением внутри транзакции
повторно проверяются принадлежность токена, отзыв, срок действия и активность
устройства/аккаунта.

## Проверка перед будущей доставкой

`NotificationPreferences.allows_delivery(kind, now=aware_datetime)` принимает
`reminder` или `proactive`. Метод учитывает opt-in категории и текущее локальное
время пользователя. Начало тихого интервала включительно, конец исключительно.
Поддерживаются дневные интервалы, переход через полночь и смена UTC offset.
Оба повторения часа при осеннем переходе времени проверяются одинаково по
локальным часам. Неопределённый часовой пояс и naive datetime не допускаются.

Будущий worker должен читать актуальные настройки перед каждой попыткой
доставки. Нельзя кешировать согласие на момент создания напоминания или
использовать персональный device token как долгоживущую учётную запись worker.
При отсутствии opt-in или ошибке загрузки настроек доставка запрещена.

Следующий этап: личная очередь/in-app inbox с владельцем для каждой записи,
состоянием доставки и защитой от повторов, затем Android UI для настроек и
просмотра уведомлений. Перенос просроченных напоминаний после тихих часов,
политика хранения и push при закрытом приложении требуют отдельной реализации.
