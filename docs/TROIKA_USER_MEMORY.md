# Личная память Тройки

**Статус:** реализовано для закрытой beta, 2026-09-14.

Свежая проверка 2026-10-05 подтвердила create/list/update на временном аккаунте.
Общие ограничения и результаты находятся в [аудите функций](TROIKA_FUNCTIONAL_AUDIT.md).

## Назначение

Личная память хранит только явно добавленные или подтверждённые пользователем
долговременные сведения. Поддерживаются три типа записей:

- `fact` — устойчивый факт о пользователе;
- `preference` — предпочтение;
- `instruction` — правило общения с Тройкой.

Пароли, access/refresh tokens, платёжные реквизиты и другие authentication
secrets сохранять не следует. Android и tool-инструкция сообщают это до записи.
API не применяет ненадёжный классификатор свободного текста и поэтому не может
гарантировать, что пользователь сам не ввёл secret.

## API и изоляция

Все endpoint требуют действующий product bearer token:

- `GET /v1/memories` — список памяти текущего владельца;
- `POST /v1/memories` — создание записи;
- `PATCH /v1/memories/{memory_id}` — изменение типа, заголовка или текста;
- `DELETE /v1/memories/{memory_id}` — удаление записи.

Запросы не принимают `user_id`. Владелец выводится только из проверенного
токена. Каждая SQL-операция повторно фильтрует `user_id`; ID записи другого
пользователя возвращает `404`, не раскрывая факт её существования. Создание
поддерживает `Idempotency-Key` в пределах одного владельца.

Заголовок содержит 1–80 символов, текст — 1–1200. Один пользователь может
хранить до 200 записей, и экран получает их одним owner-scoped запросом.
Успешные ответы имеют `Cache-Control: no-store`. Privacy-safe audit фиксирует
создание, изменение и удаление без заголовка и содержимого записи.

## Использование ассистентом

В product mode profile-global `MEMORY.md` и `USER.md` остаются выключенными.
Перед каждым ответом сервер загружает не более 12 последних обновлённых записей
только аутентифицированного владельца. Текст каждой записи ограничивается 600
символами в prompt.

Блок помечается как недоверенные пользовательские данные. Модель может
использовать его для персонализации, но не должна трактовать содержимое как
system/tool instructions или обход правил. Инструмент `troika_assistant`
создаёт память только по явной просьбе или подтверждению пользователя; правка и
удаление также требуют явного запроса.

## Управление и жизненный цикл

Android-экран «Помощник → Память» показывает все записи и позволяет создать,
исправить или удалить каждую из них. Удаление из интерфейса требует отдельного
подтверждения.

Память входит в owner-scoped ZIP из `GET /v1/account/export` и удаляется из
текущего product SQLite при подтверждённом удалении аккаунта. Верхний retention
срок — 730 дней после последнего изменения; автоматический retention worker
ещё не реализован. Удаление из production object storage и резервных копий
также не реализовано и не проверено.

## Проверки

Автоматические тесты используют двух владельцев и доказывают:

- чужая память не видна через список, ID, prompt или `troika_assistant`;
- чужую запись нельзя исправить или удалить;
- экспорт первого пользователя не содержит заголовок и текст памяти второго;
- удаление аккаунта очищает его память и сохраняет память второго владельца;
- отозванный token больше не читает память.
