# Изолированные проверки разработки

Владелец разрешил этот режим 16 октября 2026 года. Обычный API не получает
Docker socket, shell или произвольные команды. Отдельный операторский supervisor
доступен только через частную Docker-сеть и внутренний bearer-файл. Production
включает его через `product_development_checks_*`; по умолчанию режим выключен.

Supervisor принимает только фиксированные сценарии: pytest, Node `node:test`,
React/Vitest, HTML/React preview и рендер DOCX/PPTX. Проект не управляет флагами
Docker, командой запуска, установкой зависимостей или конфигурацией сборки.
Зависимости предустановлены и закреплены lock-файлом; npm scripts не выполняются.
CSS перед Node/React-тестами разбирается доверенным esbuild без project config;
незакрытая строка не может пройти вслед за успешным тестом функций.
Неподдерживаемый стек получает честный статус или ошибку сборки.

Каждая проверка создаёт одноразовый контейнер: без сети, с read-only корнем,
непривилегированным пользователем, без capabilities, без ключей и mounts данных
Тройки. Рабочие файлы находятся в ограниченных tmpfs. На один сервер допускается
одна проверка: 0,75 CPU, 512 MiB RAM, 128 процессов, до 100 секунд. Вывод и вход
ограничены. Контейнер удаляется после завершения или остановки. Docker logging
для него выключен; supervisor не пишет тело задания и изображения в журнал.
Основной API получает рендер только в RAM и передаёт его бесплатной vision-модели.
В отчёте остаются выводы и хеш изображения, без самого изображения.

Chromium запускается с включённой sandbox. Основа seccomp-профиля взята из
[Playwright](https://github.com/microsoft/playwright/blob/1b025d7e20a026371cd5f98ba0cdce48892737c8/utils/docker/seccomp_profile.json),
исходный SHA256 `cc3e61cabda6bbc1e53e54d27ba4d55a9d3be829b6dd1a596f4a7b31b1cc7849`.
К разрешённым syscall добавлен `chroot`: он нужен вложенной user namespace
Chromium при `cap-drop ALL`. Host capability `SYS_CHROOT` не выдаётся.
См. [официальное руководство](https://playwright.dev/python/docs/docker).

Перед установкой operator заменяет `PREVIEW_IMAGE_DIGEST` в unit-файле на
проверенный immutable digest, создаёт 64-символьный секретный файл и проверяет
привязку `172.18.0.1` к частной сети. В API config задаётся путь к bearer-файлу
внутри продуктового профиля, а не само значение секрета. Изменение образа,
профиля и параметров требует нового smoke-прогона. При недоступности среды
автопилот сохраняет контрольную копию и не объявляет проект проверенным.

Если host firewall блокирует INPUT из Docker, разрешение ограничивается
интерфейсом частного bridge, его подсетью, адресом `172.18.0.1` и TCP-портом
проверяющего сервиса (17 октября — 18770). На текущем сервере включён только
`troika-preview-v2`; старый `troika-preview` на 18768 отключён и его правило
удалено. Публичный интерфейс и общий входящий доступ не открываются. После
изменения нужен HTTP smoke именно из API-контейнера, а не только локальный
вызов supervisor с host. На текущем сервере bridge — `br-390c4e9216a1`,
подсеть — `172.18.0.0/16`; при смене сети эти значения проверяются заново.
