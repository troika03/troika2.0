# Измерение маркетинга без скрытого трекинга

## 0. Статус
**Спецификация, не установленная аналитика.** В сайте сейчас заявлено «Рекламных трекеров и сторонней аналитики нет». До изменения политики конфиденциальности, проверки законности и согласия владельца **не добавлять** рекламные пиксели, GA4, Метрику, cross-device IDs, fingerprinting, cookies трекинга. Не передавать в события текст разговоров, пароль, почту, токены, ID документов или их содержимое.

## 1. Воронка (задать события после разрешённой реализации)
| Событие | Когда возникает | Что можно хранить в агрегате |
|---|---|---|
| `landing_view` | открытие публичной страницы | дата (день), slug, UTM-площадка/кампания |
| `primary_cta_click` | нажатие CTA «Начать»/«Скачать» | день, slug, CTA |
| `registration_success` | сервер подтвердил создание аккаунта | счётчик по дню, без email |
| `download_success` | сервер подтвердил выдачу полного файла | счётчик по дню, платформа |
| `first_task_success` | установленный клиент подтвердил понятный результат | счётчик/тип сценария, без текста задачи |
| `result_saved` | устройство подтвердило локальное сохранение | только счётчик, без имени файла |
| `week1_return` | активность участника на 7–13 день | агрегат по когорте, без постоянного стороннего ID |
| `beta_feedback` | добровольно отправлен отзыв | количественная оценка/категория, текст отдельно как поддержка |

Нельзя считать `CTA clicked` успешной установкой, а загрузку ZIP — активацией.

## 2. Формулы
- CTR CTA = клики по CTA / уникальные визиты страницы (если есть легальное обезличенное измерение).
- Регистрация / визит = успешные регистрации / посетители посадочной страницы.
- Активация / регистрация = участники с первым подтверждённым полезным результатом / успешно зарегистрированные.
- 7-day retention = участники когорты, вернувшиеся в дни 7–13 / участники этой когорты; правило активности фиксировать до измерения.
- CAC = затраты канала / новых платящих клиентов. Пока оплат нет, CAC не считать.
- LTV и payback рассчитывать только на фактической выручке с учётом комиссии, налогов и затрат AI/STT/поддержки.

Не хранить IP в отчёте маркетинга и не пытаться восстановить человека по комбинациям малых сегментов. При маленьких выборках объединять сегменты, а не публиковать персональные графики.

## 3. UTM без cookies
Разрешённые поля в ссылке: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`. Пример:
`https://cm444726.tw1.ru/features/?utm_source=telegram&utm_medium=organic_social&utm_campaign=beta_oct2026&utm_content=demo_doc1`
Это **пометка ссылки**, а не доказательство работающей атрибуции. Пока сбор не внедрён законным способом, данные о переходах по UTM не сохраняются автоматически. Не включать email/номер/имя в UTM. При смене домена заменить base URL и проверить 301, canonical, OG, robots/sitemap.

## 4. Минимальный weekly dashboard
Неделя, опубликовано материалов, просмотры/переходы из собственной статистики площадок, новые регистрации (агрегат), подтверждённые активированные бета-участники, наиболее частые блокеры, доля полезных сценариев, аварии/жалобы, стоимость инфраструктуры, решения на следующую неделю.

Канал может сообщать «1000 просмотров», но это не «1000 потенциальных клиентов» — метрики разных площадок не суммировать как идентичных людей.

## 5. Решение о подключении аналитики
1. Утвердить оператора данных, цели, сроки хранения, региональные требования, тексты privacy/cookies и способ отзыва согласия, если нужно.
2. Выбрать first-party агрегаты на стороне сервера, не включать third-party tracking по умолчанию.
3. Обновить сайт/документацию/тесты и пройти security review.
4. Проверить отсутствие PII в событиях, возможность отключения и минимальные права доступа.
5. Отдельно согласовать публикацию dashboard и любые рекламные интеграции.
