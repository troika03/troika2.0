# Сайт Тройки

Исходники находятся в `src/` и `worker/`. Каталог `dist/` содержит прежний
статический вариант и существующие незавершённые правки; текущая версия
собирается отдельно и не перезаписывает его.

`npm run build` создаёт `build/server/index.js`; `npm test` проверяет
поведение сайта. `npm run preview` открывает локальный просмотр на порту 4178.
Для Sites используется `npm run build:hosting`, создающий `dist/server/index.js`
в отдельном checkout источников сайта. Старый `dist/` в продуктовой копии
не следует использовать как актуальный релиз.

Сайт сохраняет проверенный `project_id` и существующий доступ владельца.
Хостинг использует Worker, D1 для обращений и R2 для установочных файлов.
Публичный доступ не включён автоматически.

## Связь с продуктом

Вход и регистрация обращаются к существующему Troika API. Токены продукта
хранятся только в зашифрованной HttpOnly-cookie. Произвольные адреса и API-пути
не проксируются. Обновление сессии сериализуется между вкладками браузера.
Выход отзывает текущее веб-устройство; завершение всех сеансов, экспорт и
удаление аккаунта выполняются настоящими серверными операциями.

Кабинет показывает фактический ресурс сервера: дневные запросы либо месячные
расчётные токены, если новый учёт включён. Отображаемые согласованные тарифы
не включают оплату автоматически. `PAYMENTS_ENABLED` остаётся `false`.
Не включать оплату до проверки продавца, провайдера и серверного billing.

## Конфигурация

Значения задаются инструментами среды Sites; секреты не входят в исходники.

- `API_ORIGIN`: HTTPS origin действующего сервера Troika.
- `SESSION_SECRET`: криптографический ключ защиты cookie, минимум 40 символов.
- `RELEASE_UPLOAD_KEY`: отдельный секрет только для загрузки сборок.
- `SUPPORT_ADMIN_EMAIL`: почта оператора, проверенная серверной идентичностью Sites.
- `PAYMENTS_ENABLED`: включение пользовательского checkout после готовности billing.

Административные ответы поддержки требуют проверенной идентичности Sites,
а обычные обращения — действующего аккаунта Troika. Содержимое обращений не
пишется в Git и логи. Удаление аккаунта через сайт удаляет и обращения сайта.
Экспорт обращений выполняется отдельно от продуктового ZIP.

## Установочные файлы

`scripts/upload-release.mjs` получает параметры и секреты через скрытый stdin.
Он передаёт файл частями, затем скачивает опубликованный файл потоком и
проверяет SHA-256 и размер. В исходники и архив сайта APK/ZIP не включаются.
На странице загрузки указаны фактические ограничения подписи текущих сборок.

## Незавершённые внешние подключения

Оплата, автоматическое восстановление пароля, почтовая верификация и реквизиты
оператора требуют серверной готовности и данных владельца. Публикация этой
версии не означает принятие общего релиза Troika 1.0.
