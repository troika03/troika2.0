# Сайт Тройки

Исходники находятся в `src/` и `worker/`. Каталог `dist/` содержит прежний
статический вариант и существующие незавершённые правки; текущая версия
собирается отдельно и не перезаписывает его.

`npm run build` создаёт `build/server/index.js`; `npm test` проверяет
поведение сайта. `npm run preview` открывает локальный просмотр на порту 4178.
Для Sites используется `npm run build:hosting`, создающий `dist/server/index.js`
в отдельном checkout источников сайта. Старый `dist/` в продуктовой копии
не следует использовать как актуальный релиз.

Исходная публикация Sites сохраняет проверенный `project_id` и доступ владельца.
Она использует Worker, D1 для обращений и R2 для установочных файлов.
Её публичная аудитория не расширялась при переносе в Timeweb.

## Публикация в Timeweb

С 16 октября сайт опубликован на https://cm444726.tw1.ru/. Домен связан
с каталогом `troika/public_html`; HTTPS действует, HTTP перенаправляется.
`npm run build:timeweb` создаёт публичные страницы и PHP 8.2 адаптер, а также
`setup.php`, схему SQLite и консоль оператора вне `public_html`.

Адаптер напрямую обращается к фиксированному HTTPS API Тройки. Существующие
аккаунты сохраняются. Cookie защищена AES-256-GCM, Secure, HttpOnly и SameSite;
изменения требуют Origin сайта. Тексты обращений и ответы зашифрованы в SQLite.
Приватная папка имеет права 0700, конфигурация и база — 0600.
Оператор работает только через авторизованную консоль Timeweb:
`php support-operator.php list`, `show UUID`, `reply UUID` с JSON на stdin
(`message`, `status`: `open` или `closed`). Непроверенная почта не даёт роль
оператора; публичных административных маршрутов нет.

Для повторного развёртывания загрузить содержимое `build-timeweb` в `troika`,
установщики — в `private/releases`, затем выполнить `php setup.php` из корня
сайта. Setup сохраняет существующие ключи и обращения, сверяет размер и SHA-256
обоих установщиков и публикует манифест только после успешной проверки.
`private/application.json` создаётся на сервере без вывода ключей. Не включать
runtime-конфигурацию, базу или установщики в архив исходников. Публичные папки
требуют 0755, статические файлы — 0644; приватные права не расширять.

Прежний мост к Sites заменён: исходный хостинг блокировал обращения с Timeweb
через Cloudflare. Служебный `private/backend.json` больше не используется.
Исходный Sites, его закрытая аудитория, D1 и R2 сохранены. До переноса в D1
проверены нулевые таблицы обращений и ответов. Оплата выключена.
Проверки и ограничения: [аудит переноса](../docs/audit/WEBSITE_TIMEWEB_2026_10_16.md).
Технический домен бесплатный, хостинг работает в тестовом периоде Timeweb.

## Связь с продуктом

Вход и регистрация обращаются к существующему Troika API. Токены продукта
хранятся только в зашифрованной HttpOnly-cookie. Произвольные адреса и API-пути
не проксируются. Обновление сессии сериализуется между вкладками браузера.
Выход отзывает текущее веб-устройство; завершение всех сеансов, экспорт и
удаление аккаунта выполняются настоящими серверными операциями.

Кабинет показывает фактический ресурс сервера: дневные запросы либо месячные
расчётные токены, если новый учёт включён. Отображаемые согласованные тарифы
не включают оплату автоматически. `PAYMENTS_ENABLED` остаётся `false`.
Не включать оплату до проверки продавца, провайдера и серверного billing.

## Конфигурация

Следующие значения относятся к исходному Sites. В Timeweb собственные ключи
создаёт `setup.php` вне публичной папки; секреты не входят в исходники.

- `API_ORIGIN`: HTTPS origin действующего сервера Troika.
- `SESSION_SECRET`: криптографический ключ защиты cookie, минимум 40 символов.
- `RELEASE_UPLOAD_KEY`: отдельный секрет только для загрузки сборок.
- `SUPPORT_ADMIN_EMAIL`: почта оператора, проверенная серверной идентичностью Sites.
- `PAYMENTS_ENABLED`: включение пользовательского checkout после готовности billing.

В исходном Sites административные ответы требуют проверенной идентичности Sites,
а обычные обращения — действующего аккаунта Troika. Содержимое обращений не
пишется в Git и логи. Удаление аккаунта через сайт удаляет и обращения сайта.
Экспорт обращений выполняется отдельно от продуктового ZIP.

## Установочные файлы

`scripts/upload-release.mjs` получает параметры и секреты через скрытый stdin.
Он передаёт файл частями, затем скачивает опубликованный файл потоком и
проверяет SHA-256 и размер. В исходники и архив сайта APK/ZIP не включаются.
На странице загрузки указаны фактические ограничения подписи текущих сборок.
Timeweb раздаёт проверенные файлы из закрытой папки через `transfer.php`.
`node scripts/verify-timeweb-downloads.mjs` проверяет полное скачивание,
SHA-256, HEAD, частичную загрузку и защиту от обхода пути.

## Незавершённые внешние подключения

Оплата, автоматическое восстановление пароля, почтовая верификация и реквизиты
оператора требуют серверной готовности и данных владельца. Публикация этой
версии не означает принятие общего релиза Troika 1.0.
