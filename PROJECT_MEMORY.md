## Тон разговора

По решению владельца дружеский подкол с уместным матом — обычная манера
Тройки в бытовой беседе. Она может первой пошутить над конкретной ситуацией,
даже если пользователь задал вопрос спокойно, и затем помочь по делу.
«Без мата» убирает мат, «давай серьёзно» переключает на спокойный ответ.

Компактная и полная версии личности — 16 и 15. Проверка на бесплатной
модели рабочего сервера включала два синтетических диалога по три реплики.
В обоих модель сама пошутила с матом, подхватила продолжение и ответила
без мата на просьбу говорить серьёзно. Встречались длинные советы и
иноязычные вставки. Это проверка модели, а не голосового клиента.

23 ноября рабочий API переведён на `banter-20261123-882579223`.
При переключении активных запросов не было. В рабочем чате на временной
учётной записи Тройка первой употребила мат в ответ на спокойный бытовой
вопрос. После просьбы говорить серьёзно и без мата ответила без ругани.
В отдельном споре про будильники Тройка прямо возразила и привела довод.
В бытовых советах встречались иноязычные слова и неточности. Обе проверочные
учётные записи удалены. Голос на телефоне после переключения не проверялся.
Прошла 151 профильная проверка. Полный прогон на Windows завершился:
26 024 теста прошли, 428 упали, в 16 файлах тесты не запустились.

- [Word-план](docs/Troika_1.0_Launch_Plan_Final_Updated.docx) — authority для scope/UX/цен/DoD. Порядок разделов 1–20 сохраняется; section 20 — release summary.
- Troika 1.0 — voice-first Android/Windows, текст вторичен. Результат важнее перечисления tools.
- Hosted subscription без model keys у обычного пользователя; BYOK/diagnostics — developer/Advanced scope.
- 12 октября согласованы Free 500 000, Plus 5 млн за 790 ₽ и Pro 10 млн за 1 490 ₽/месяц. 14 октября уточнено: корпоративная бесплатная модель списывает prompt + completion; личный API пользователя не списывает токены подписки за модель. - Фоновое локальное пробуждение «Тройка» — P0 Android; OEM/Bluetooth/standby/expiry требуют E2E.
- Данные принадлежат аккаунту. Сервер — основная копия; выбрано автоматическое восстановление после входа, а не невосстановимое E2EE. Production stores/backups должны шифроваться at rest.
- Единый Run/Task/Worker runtime с до трёх specialist workers — целевая архитектура; текущий agent loop ещё не закрывает весь этот scope.
- Важные внешние/разрушительные/privacy-sensitive действия требуют approval; обратимые requested low-risk actions выполняются напрямую.
- Live screen/camera, полный Accessibility, автономный PC-agent общего назначения, GROUND/DAEMON/Kali/self-improvement не входят в ordinary 1.0.
- Владелец прямо подтвердил 2026-10-05: сохранить `hermes_cli`. Удалять только подтверждённо ненужные материалы; имена runtime мигрировать с совместимостью.

## Разработка через API

сохранены как отдельные действия. Исторические доказательства —
`docs/audit/API_DEVELOPMENT_2026_10_13.md`.
